Live API reference¶

Preview

This feature is subject to the "Pre-GA Offerings Terms" in the General Service Terms section of the Service Specific Terms. Pre-GA features are available "as is" and might have limited support. For more information, see the launch stage descriptions.

The Live API enables low-latency, bidirectional voice and video interactions with Gemini. Using the Live API, you can provide end users with natural, human-like voice conversations and the ability to interrupt the model's responses using voice commands. The Live API can process text, audio, and video input, and it can provide text and audio output.

The Live API is designed for server-to-server communication. For web and mobile apps, we recommend using the integration from our partners at Daily.

To try a tutorial that lets you use your voice and camera to talk to Gemini through the Live API, see the websocket-demo-app tutorial.

For more information about the Live API, see Live API.

Capabilities¶

The Live API includes the following key capabilities:

  • Multimodality: The model can see, hear, and speak.
  • Low-latency realtime interaction: The model can provide fast responses.
  • Session memory: The model retains memory of all interactions within a single session, recalling previously heard or seen information.
  • Support for function calling, code execution, and Search as a Tool: You can integrate the model with external services and data sources.

Supported models¶

  • Gemini 2.5 Flash with Live API native audio (Preview)
  • Gemini 2.0 Flash with Live API (Preview)
  • Gemini 2.5 Flash

How the Live API works¶

The Live API is a stateful API that uses WebSockets to establish a persistent session between your application and the Gemini server. The following diagram shows the typical workflow of a Live API session.

flowchart LR
    A[Start: Client initiates WebSocket connection] --> B[Configure session];
    B -- BidiGenerateContentSetup --> C[Server confirms setup];
    C -- BidiGenerateContentSetupComplete --> D{Exchange messages};
    D -- Send: ClientContent/RealtimeInput --> D;
    D -- Receive: ServerContent/ToolCall --> D;
    D -- End session --> E[Close connection];

click A "#"
click B "#configure-a-session"
click C "#configure-a-session"
click D "#send-and-receive-messages"
click E "#"
  1. Initiate Connection: The client establishes a WebSocket connection with the Gemini server.
  2. Configure Session: In the first message, the client sends a BidiGenerateContentSetup message to configure the session, specifying the model, generation parameters, system instructions, and tools.
  3. Exchange Messages: Once the server confirms the setup, the client and server can exchange messages to send text, audio, or video, and receive text, audio, or function call requests.
  4. Close Connection: The session ends when the connection is closed.

Get started with the Live API¶

To try the Live API, go to the Vertex AI Studio, and then click Start Session.

The following tutorial shows how to use the Live API for a text-to-text conversation using the Gen AI SDK for Python (version 3.9+).

Steps to connect and interact with the Live API

1. Install the SDK and configure your client

First, install the necessary library and configure the client with your project and location details.

# Replace the `GOOGLE_CLOUD_PROJECT` and `GOOGLE_CLOUD_LOCATION` values
# with appropriate values for your project.

from google import genai
from google.genai.types import (
    Content,
    LiveConnectConfig,
    Modality,
    Part,
)

client = genai.Client(
    vertexai=True,
    project=GOOGLE_CLOUD_PROJECT,
    location=GOOGLE_CLOUD_LOCATION
)
MODEL_ID = "gemini-live-2.5-flash"

Troubleshooting

If you encounter issues with code snippets or setup, refer to the Troubleshooting Guide.

2. Connect to the service and exchange messages

Use an async context to connect to the service. After connecting, you can send user content and asynchronously listen for the model's response.

async with client.aio.live.connect(
    model=MODEL_ID,
    config=LiveConnectConfig(response_modalities=[Modality.TEXT]),
) as session:
    text_input = "Hello? Gemini, are you there?"
    print("> ", text_input, "\n")
    await session.send_client_content(
        turns=Content(role="user", parts=[Part(text=text_input)])
    )

    response = []

    async for message in session.receive():
        if message.text:
            response.append(message.text)

    print("".join(response))
# Example output:
# >  Hello? Gemini, are you there?
# Yes, I'm here. What would you like to talk about?

API Integration Guide¶

This section describes the core components of the Live API integration.

Sessions¶

A WebSocket connection establishes a session between the client and the Gemini server. After a client initiates a connection, the session can exchange messages to send text, audio, or video to the server and receive audio, text, or function call requests from the server.

The session configuration is sent in the first message after connection. A session configuration includes the model, generation parameters, system instructions, and tools.

View an example session configuration 

{
  "model": string,
  "generationConfig": {
    "candidateCount": integer,
    "maxOutputTokens": integer,
    "temperature": number,
    "topP": number,
    "topK": integer,
    "presencePenalty": number,
    "frequencyPenalty": number,
    "responseModalities": [string],
    "speechConfig": object
  },

  "systemInstruction": string,
  "tools": [object]
}
For more information, see BidiGenerateContentSetup.

Send messages (Client-to-Server)¶

Messages are JSON-formatted objects exchanged over the WebSocket connection. To send a message, the client must send a JSON object with exactly one of the supported fields.

Supported client messages

Message Description
BidiGenerateContentSetup Session configuration to be sent in the first message.
BidiGenerateContentClientContent Incremental content update of the current conversation.
BidiGenerateContentRealtimeInput Real-time audio or video input.
BidiGenerateContentToolResponse Response to a ToolCallMessage received from the server.

Receive messages (Server-to-Client)¶

To receive messages from Gemini, listen for the WebSocket message event and parse the result.

View an example event listener 
ws.addEventListener("message", async (evt) => {
  if (evt.data instanceof Blob) {
    // Process the received data (audio, video, etc.)
  } else {
    // Process JSON response
  }
});

Server messages will have exactly one of the supported fields.

Supported server messages

Message Description
BidiGenerateContentSetupComplete Confirms that the session setup is complete.
BidiGenerateContentServerContent Content generated by the model in response to a client message.
BidiGenerateContentToolCall Request for the client to run function calls.
BidiGenerateContentToolCallCancellation Sent when a function call is canceled due to user interruption.
UsageMetadata A report of the number of tokens used by the session so far.
GoAway A signal that the current connection will soon be terminated.
SessionResumptionUpdate A session checkpoint, which can be resumed.
BidiGenerateContentTranscription A transcription of either the user's or model's speech.

Incremental content updates¶

Use incremental updates (BidiGenerateContentClientContent) to send text input, establish session context, or restore session context. For short contexts, you can send turn-by-turn interactions. For longer contexts, it is recommended to provide a single summary message to free up the context window for follow-up interactions.

View an example context message 

{
  "clientContent": {
    "turns": [
      {
          "parts":[
          {
            "text": ""
          }
        ],
        "role":"user"
      },
      {
          "parts":[
          {
            "text": ""
          }
        ],
        "role":"model"
      }
    ],
    "turnComplete": true
  }
}
Note that BidiGenerateContentClientContent should only be used to establish previous context or provide text input. To respond to function calls, use BidiGenerateContentToolResponse.

System instructions¶

You can provide system instructions at the beginning of a session to control the model's output and specify the tone and sentiment of audio responses. System instructions remain in effect for the entire session and cannot be changed after the session starts.

Interruptions¶

Users can interrupt the model's output at any time. When Voice Activity Detection (VAD) detects an interruption, the ongoing generation is canceled. The server sends a BidiGenerateContentServerContent message to report the interruption and a BidiGenerateContentToolCallCancellation message if any pending function calls were discarded.

Voices and audio¶

To specify a voice, set the voiceName within the speechConfig object as part of your session configuration. For a list of supported voices, see Change voice and language settings. For a list of supported audio formats, see Supported audio formats.

View an example speechConfig object 
{
  "voiceConfig": {
    "prebuiltVoiceConfig": {
      "voiceName": "VOICE_NAME"
    }
  }
}

Limitations¶

Consider the following limitations when planning your project:

  • Client authentication: The Live API only provides server-to-server authentication. Client input should be routed through an intermediate application server for secure authentication.
  • Maximum session duration: The default maximum length of a session is 10 minutes. For more information, see Session length.
  • Voice activity detection (VAD): VAD is enabled by default but can be configured or disabled. If disabled, the client is responsible for sending ActivityStart and ActivityEnd messages.
  • Additional limitations: Manual endpointing is not supported. Audio inputs and outputs can negatively impact the model's ability to use function calling.
  • Token count: Token count is not supported.
  • Rate limits:
    • 5,000 concurrent sessions per API key
    • 4M tokens per minute

Messages and events reference¶

This section provides detailed descriptions of the messages and events used in the Live API.

Client messages¶

BidiGenerateContentClientContent

Incremental update of the current conversation delivered from the client. This content is appended to the conversation history and used as part of the prompt for the model. Sending this message will interrupt any current model generation.

Field Description
turns[] [Content](/vertex-ai/generative-ai/docs/reference/rpc/google.cloud.aiplatform.v1beta1#google.cloud.aiplatform.v1beta1.Content) Optional. The content appended to the current conversation. For single-turn queries, this is a single instance. For multi-turn queries, this is a repeated field containing conversation history and the latest request.
turn_complete bool Optional. If true, indicates that the server should start content generation with the currently accumulated prompt. Otherwise, the server will await additional messages.
BidiGenerateContentRealtimeInput

User input that is sent in real time, such as streaming audio or video. This can be sent continuously without interrupting model generation.

Field Description
media_chunks[] [Blob](/vertex-ai/generative-ai/docs/reference/rpc/google.cloud.aiplatform.v1beta1#google.cloud.aiplatform.v1beta1.Blob) Optional. Inlined bytes data for media input.
activity_start [ActivityStart](#activitystart) Optional. Marks the start of user activity. Can only be sent if server-side activity detection is disabled.
activity_end [ActivityEnd](#activityend) Optional. Marks the end of user activity. Can only be sent if server-side activity detection is disabled.
BidiGenerateContentSetup

Configuration message sent only once at the beginning of a session. Clients must wait for a BidiGenerateContentSetupComplete response before sending other messages.

Field Description
model string Required. The fully qualified name of the publisher model (e.g., projects/{project}/locations/{location}/publishers/*/models/*).
generation_config [GenerationConfig](/vertex-ai/generative-ai/docs/reference/rpc/google.cloud.aiplatform.v1beta1#google.cloud.aiplatform.v1beta1.GenerationConfig) Optional. Generation config. Several fields are not supported.
system_instruction [Content](/vertex-ai/generative-ai/docs/reference/rpc/google.cloud.aiplatform.v1beta1#google.cloud.aiplatform.v1beta1.Content) Optional. System instructions for the model. Only text should be used.
tools[] [Tool](/vertex-ai/generative-ai/docs/reference/rpc/google.cloud.aiplatform.v1beta1#google.cloud.aiplatform.v1beta1.Tool) Optional. A list of Tools the model may use.
session_resumption [SessionResumptionConfig](/vertex-ai/generative-ai/docs/reference/rpc/google.cloud.aiplatform.v1beta1#google.cloud.aiplatform.v1beta1.SessionResumptionConfig) Optional. Configures session resumption.
context_window_compression [ContextWindowCompressionConfig](/vertex-ai/generative-ai/docs/reference/rpc/google.cloud.aiplatform.v1beta1#google.cloud.aiplatform.v1beta1.ContextWindowCompressionConfig) Optional. Configures context window compression.
realtime_input_config [RealtimeInputConfig](#realtimeinputconfig) Optional. Configures the handling of real-time input.
input_audio_transcription [AudioTranscriptionConfig](#audiotranscriptionconfig) Optional. Configures transcription for input audio.
output_audio_transcription [AudioTranscriptionConfig](#audiotranscriptionconfig) Optional. Configures transcription for output audio.
BidiGenerateContentToolResponse

Client-generated response to a ToolCall received from the server.

Field Description
function_responses[] [FunctionResponse](/vertex-ai/generative-ai/docs/reference/rpc/google.cloud.aiplatform.v1beta1#google.cloud.aiplatform.v1beta1.FunctionResponse) Optional. The response to the function calls, matched by ID.

Server messages¶

BidiGenerateContentServerContent

Incremental server update generated by the model in response to client messages.

Field Description
turn_complete bool Output only. If true, the model is done generating for the current turn.
interrupted bool Output only. If true, a client message has interrupted the current model generation.
generation_complete bool Output only. If true, the model has finished generating its entire response.
grounding_metadata [GroundingMetadata](/vertex-ai/generative-ai/docs/reference/rpc/google.cloud.aiplatform.v1beta1#google.cloud.aiplatform.v1beta1.GroundingMetadata) Output only. Metadata specifying sources used to ground generated content.
input_transcription [Transcription](#transcription) Optional. Transcription of the user's speech.
output_transcription [Transcription](#transcription) Optional. Transcription of the model's speech.
model_turn [Content](/vertex-ai/generative-ai/docs/reference/rpc/google.cloud.aiplatform.v1beta1#google.cloud.aiplatform.v1beta1.Content) Output only. The content generated by the model.
BidiGenerateContentSetupComplete

Sent in response to a BidiGenerateContentSetup message from the client, confirming the session is ready. This type has no fields.

BidiGenerateContentToolCall

Request for the client to execute function calls.

Field Description
function_calls[] [FunctionCall](/vertex-ai/generative-ai/docs/reference/rpc/google.cloud.aiplatform.v1beta1#google.cloud.aiplatform.v1beta1.FunctionCall) Output only. The function call to be executed.
BidiGenerateContentToolCallCancellation

Notification that a previously issued ToolCallMessage should be canceled.

Field Description
ids[] string Output only. The IDs of the tool calls to be canceled.
GoAway

A signal that the server will terminate the connection soon.

Field Description
time_left [Duration](https://protobuf.dev/reference/protobuf/google.protobuf/#duration) The remaining time before the connection is terminated.
SessionResumptionUpdate

An update on the session resumption state, sent only if session resumption is configured.

Field Description
new_handle string A new handle that represents a resumable state.
resumable bool True if the session can be resumed at this point.
last_consumed_client_message_index int64 The index of the last client message included in this state.
UsageMetadata

Metadata on the token usage of the cached content.

Field Description
total_token_count int32 Total number of tokens consumed.
text_count int32 Number of text characters.
image_count int32 Number of images.
video_duration_seconds int32 Duration of video in seconds.
audio_duration_seconds int32 Duration of audio in seconds.

Other types and enums¶

ActivityEnd

Marks the end of user activity. This type has no fields.

ActivityStart

Marks the start of user activity. This type has no fields.

AudioTranscriptionConfig

Configuration for audio transcription. This type has no fields.

RealtimeInputConfig

Configures the real-time input behavior.

Field Description
automatic_activity_detection [AutomaticActivityDetection](#automaticactivitydetection) Optional. Configures automatic activity detection. Enabled by default.
activity_handling [ActivityHandling](#activityhandling) Optional. Defines what effect user activity has (e.g., interrupting the model).
turn_coverage [TurnCoverage](#turncoverage) Optional. Defines which input is included in the user's turn.
AutomaticActivityDetection

Configures automatic detection of activity.

Field Description
start_of_speech_sensitivity [StartSensitivity](#startsensitivity) Optional. Determines how likely speech is to be detected.
end_of_speech_sensitivity [EndSensitivity](#endsensitivity) Optional. Determines how likely detected speech is to be considered ended.
prefix_padding_ms int32 Optional. Required duration of detected speech before start-of-speech is committed.
silence_duration_ms int32 Optional. Required duration of silence before end-of-speech is committed.
disabled bool Optional. If true, disables automatic activity detection.
Transcription

An audio transcription message.

Field Description
text string Optional. The transcription text.
finished bool Optional. Indicates the end of the transcription.
ActivityHandling
Enum Description
ACTIVITY_HANDLING_UNSPECIFIED Default behavior is START_OF_ACTIVITY_INTERRUPTS.
START_OF_ACTIVITY_INTERRUPTS Start of user activity will interrupt the model's response ("barge-in").
NO_INTERRUPTION The model's response will not be interrupted by user activity.
EndSensitivity
Enum Description
END_SENSITIVITY_UNSPECIFIED Default is END_SENSITIVITY_LOW.
END_SENSITIVITY_HIGH Automatic detection ends speech more often.
END_SENSITIVITY_LOW Automatic detection ends speech less often.
StartSensitivity
Enum Description
START_SENSITIVITY_UNSPECIFIED Default is START_SENSITIVITY_LOW.
START_SENSITIVITY_HIGH Automatic detection detects the start of speech more often.
START_SENSITIVITY_LOW Automatic detection detects the start of speech less often.
TurnCoverage
Enum Description
TURN_COVERAGE_UNSPECIFIED Default behavior is TURN_INCLUDES_ALL_INPUT.
TURN_INCLUDES_ONLY_ACTIVITY The user's turn only includes activity since the last turn (e.g., speech).
TURN_INCLUDES_ALL_INPUT The user's turn includes all real-time input since the last turn, including inactivity (e.g., silence).
