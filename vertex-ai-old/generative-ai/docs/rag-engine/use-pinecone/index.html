Use Pinecone with Vertex AI RAG Engine¶

Preview

The VPC-SC security control is supported by RAG Engine. Data residency, CMEK, and AXT security controls aren't supported.

To see an example of using RAG Engine with Pinecone, run the "RAG Engine with Pinecone" Jupyter notebook in one of the following environments:

Open in Colab Open in Colab Enterprise Open in Vertex AI Workbench View on GitHub

This page shows you how to connect your RAG corpus to your Pinecone database.

You can use your Pinecone database instance with Vertex AI RAG Engine to index and conduct a vector-based similarity search. A similarity search finds pieces of text that are similar to your query by using an embedding model. The embedding model produces vector data for each piece of text, which is then used to retrieve semantic contexts for grounding and returning the most relevant content from your LLM.

With Vertex AI RAG Engine, you can continue to use your fully-managed Pinecone vector database, which you are responsible for provisioning and managing. Vertex AI RAG Engine uses your vector database for storage, index management, and search.

Before you begin¶

Prerequisites and considerations

Considerations for using Pinecone

Before connecting Pinecone to RAG Engine, review the following requirements and responsibilities:

  • You must create, configure, and manage the scaling of your Pinecone database instance.
  • Vertex AI RAG Engine uses the default namespace on your index. Ensure that this namespace isn't modified by other processes.
  • You must provide a Pinecone API key to allow RAG Engine to interact with your Pinecone database. RAG Engine does not store your Pinecone API key. Instead, you must:
    • Store your key in Google Cloud Secret Manager.
    • Grant your project's service account permissions to access the secret.
    • Provide RAG Engine with the secret's resource name.
  • Each RAG corpus has a one-to-one mapping with a Pinecone index. This association is made during the CreateRagCorpus or UpdateRagCorpus API call and is permanent.

Supported configurations

  • Embedding models and dimensions: When creating your Pinecone index, you must specify the embedding dimension that matches the model you intend to use with RAG Engine.
Model Dimension size
First-party Gecko (text-embedding-004 and later) 768
Fine-tuned first-party Gecko 768

How to connect RAG Engine to Pinecone¶

Step-by-step guide to connect Pinecone

Step 1: Create your Pinecone index

Follow the Pinecone quickstart guide to create and configure your index.

  • Location: To reduce latency and meet data residency requirements, create your Pinecone index in a location that is the same as or geographically close to where you use Vertex AI RAG Engine.
  • Metadata indexing: If you create a pod-based index, you must specify file_id on the pod.metadata_config.indexed field. For more information, see Selective metadata indexing.

Step 2: Create your Pinecone API key

RAG Engine requires an API key to authenticate to your Pinecone index. Follow the Pinecone authentication guide to create an API key in your Pinecone project.

Step 3: Provision your Vertex AI RAG Engine service account

When you create the first RAG corpus in your project, RAG Engine provisions a dedicated service account. You can find this service account on your project's Identity and Access Management (IAM) page.

The service account follows this format: service-{project-number}@gcp-sa-vertex-rag.iam.gserviceaccount.com

For example: service-123456789@gcp-sa-vertex-rag.iam.gserviceaccount.com

Step 4: Store your API key in Secret Manager

An API key is sensitive information. To protect it, you must store it in Secret Manager and grant the RAG Engine service account access to it.

  1. Store your API key in Secret Manager.
  2. Grant the RAG Engine service account permissions to access the secret:
    1. Navigate to your project's IAM page.
    2. Enable the option Include Google-provided role grants.
    3. Find the service account: service-{project-number}@gcp-sa-vertex-rag.iam.gserviceaccount.com.
    4. Edit the service account's principals.
    5. Add the Secret Manager Secret Accessor role to the service account.

Step 5: Create your RAG corpus

To use your Pinecone index, you must associate it with a RAG corpus. This binding is permanent. You can create the corpus with all the Pinecone details upfront or create it first and add the details later.

Troubleshooting

If you encounter issues with code snippets or setup, refer to the Troubleshooting Guide.

Use this method if you have already provisioned your Pinecone index and stored your API key in Secret Manager.

To associate the corpus, set the following fields in your CreateRagCorpus request: * rag_vector_db_config.pinecone: Sets Pinecone as the vector database. * rag_vector_db_config.pinecone.index_name: The name of your Pinecone index. * rag_vector_db_config.api_auth.api_key_config.api_key_secret_version: The full resource name of the secret version containing your Pinecone API key, in the format projects/{PROJECT_NUMBER}/secrets/{SECRET_ID}/versions/{VERSION_ID}.

Before trying this sample, follow the Python setup instructions in the Vertex AI quickstart using client libraries. For more information, see the Vertex AI Python API reference documentation.

To authenticate to Vertex AI, set up Application Default Credentials. For more information, see Set up authentication for a local development environment.

import vertexai

        publisher_model="publishers/google/models/text-embedding-004"

    index_name=pinecone_index_name,
    api_key=pinecone_api_key_secret_manager_version,
)

corpus = rag.create_corpus(
    display_name=display_name,
    description=description,
    backend_config=rag.RagVectorDbConfig(
        rag_embedding_model_config=embedding_model_config,
        vector_db=vector_db,
    ),
)
print(corpus)

# ...

# Choose a display name for your corpus
CORPUS_DISPLAY_NAME="YOUR_CORPUS_DISPLAY_NAME"

# Set your Pinecone index name

curl -X POST \

# The response to this call will contain the ID for your created RAG corpus

-H "Authorization: Bearer $(gcloud auth print-access-token)" \
-H "Content-Type: application/json" \
https://us-central1-aiplatform.googleapis.com/v1beta1/projects/${PROJECT_ID}/locations/us-central1/operations/${OPERATION_ID}

Update your RAG corpus¶

You can use the UpdateRagCorpus API to add or change the vector database configuration. This is necessary if you created a corpus without providing the Pinecone index name and API key secret version.

Field Mutability Required or Optional
rag_vector_db_config.vector_db Immutable after you make a choice. Required
rag_vector_db_config.pinecone.index_name Immutable after you set the field on the RAG corpus. Required
rag_vector_db_config.api_auth.api_key_config.api_key_secret_version Mutable. After you set the API key, you can't remove it. Optional 
import vertexai
from vertexai.preview import rag

# TODO(developer): Update and un-comment below lines
# PROJECT_ID = "your-project-id"
# RAG_CORPUS_ID = "your-rag-corpus-id" # e.g., "1234567890"
# pinecone_index_name = "pinecone-index-name"
# pinecone_api_key_secret_manager_version = "projects/{PROJECT_ID}/secrets/{SECRET_NAME}/versions/latest"

vertexai.init(project=PROJECT_ID, location="us-central1")

# Get the existing corpus
corpus = rag.get_corpus(RAG_CORPUS_ID)

# Configure the Pinecone vector DB information to update
vector_db = rag.Pinecone(
    index_name=pinecone_index_name,
    api_key=pinecone_api_key_secret_manager_version,
)

# Update the corpus
updated_corpus = corpus.update(
    backend_config=rag.RagVectorDbConfig(vector_db=vector_db)
)
print(updated_corpus)

# Set your project ID for the corpus that you want to update.
PROJECT_ID="YOUR_PROJECT_ID"

# Set the ID of the corpus to update
CORPUS_ID="YOUR_CORPUS_ID"

# Set your Pinecone index name
PINECONE_INDEX_NAME="YOUR_INDEX_NAME"

# Set the full resource name of your secret. Follows the format
# projects/{PROJECT_NUMBER}/secrets/{SECRET_ID}/versions/{VERSION_ID}
SECRET_RESOURCE_NAME="YOUR_SECRET_RESOURCE_NAME"

# Call UpdateRagCorpus API with the Vector DB information.
# The updateMask specifies which fields to update.
curl -X PATCH \
-H "Authorization: Bearer $(gcloud auth print-access-token)" \
-H "Content-Type: application/json" \
"https://us-central1-aiplatform.googleapis.com/v1beta1/projects/${PROJECT_ID}/locations/us-central1/ragCorpora/${CORPUS_ID}?updateMask=ragVectorDbConfig" -d '{
      "rag_vector_db_config" : {
         "pinecone": {"index_name": "'\""${PINECONE_INDEX_NAME}"\"'"},
         "api_auth": {"api_key_config":
               {"api_key_secret_version": "'\""${SECRET_RESOURCE_NAME}"\"'"}
         }
      }
   }'

# To poll the status of your RAG corpus update, get the operation_id returned in
# the response of your UpdateRagCorpus call.
OPERATION_ID="YOUR_OPERATION_ID"

# Poll Operation status until done = true in the response.
curl -X GET \
-H "Authorization: Bearer $(gcloud auth print-access-token)" \
-H "Content-Type: application/json" \
https://us-central1-aiplatform.googleapis.com/v1beta1/projects/${PROJECT_ID}/locations/us-central1/operations/${OPERATION_ID}
