Prepare your evaluation dataset¶

For the Generative AI evaluation service, the evaluation dataset contains the data required to assess your model's performance. This typically includes the model response you want to evaluate, the input prompt used to generate that response, and optionally, a ground truth response for comparison.

This document outlines the required schema for your dataset, the supported import formats, and provides examples for various evaluation scenarios.

Before you begin¶

Concepts
  • Evaluation dataset: A collection of examples used to measure a model's performance, typically containing prompts, model responses, and sometimes ground truth references.
  • Ground truth: The ideal or correct response (often human-verified) against which the model's response is compared for accuracy. It is also referred to as reference.
  • Model-based metrics: Metrics that use another large language model (LLM) as a judge to score a model's response based on criteria like fluency, safety, or summarization quality.
  • Computation-based metrics: Metrics that evaluate a model's response by computing scores based on predefined rules or algorithms, such as BLEU for translation or exact match for question answering.
  • Prompt: The input text or instruction provided to a model to elicit a response.

Evaluation dataset schema¶

The structure of your evaluation dataset depends on the metrics you plan to use. The following sections describe the required input fields for different evaluation use cases.

General use cases¶

For most model-based metrics, your dataset needs to provide the following fields:

Input field Contents
prompt The user input for the generative AI model or application. This is optional in some cases.
response The model's inference response that you want to evaluate.
baseline_model_response (Required for pairwise metrics) The baseline model's response used for a side-by-side comparison with your model's response.

If you use the Generative AI Evaluation module of the Vertex AI SDK for Python, the service can automatically generate the response and baseline_model_response fields using the models you specify.

Multi-turn or chat¶

For evaluating conversational models, you need to include the conversation history.

Input field Contents
history The history of the conversation between the user and the model before the current turn.
prompt The user input for the model in the current turn.
response The model's response to be evaluated, based on the history and current prompt.
baseline_model_response (Required for pairwise metrics) The baseline model's response, based on the history and current prompt.

Computation-based metrics¶

For computation-based metrics, your dataset must include a ground truth reference to compare against the model's response.

Input field Contents
response The model's inference response to be evaluated.
reference The ground truth to compare your model's response to.

For translation tasks, the dataset requires the source text, the translated response, and a ground truth reference translation.

Input field Contents
source The source text in the original language that the model translated from.
response The model's translated response to be evaluated.
reference The ground truth translation to compare your model's response to. This is in the same language as the response.

Depending on your use cases, you can also break down the input user prompt into more granular fields, such as instruction and context, and assemble them for inference by providing a prompt template.

Input field Contents
instruction The part of the prompt that contains the instruction for the model (e.g., "Please summarize the following text").
context The part of the prompt that contains the content for the model to process (e.g., the article to be summarized).
reference The ground truth to compare your model's response to.

The required inputs for the evaluation dataset must be consistent with your metrics. For more details, see Define your evaluation metrics and Run evaluation and Adapt a metric prompt template to your input data.

Supported dataset formats¶

You can provide your evaluation dataset in one of the following formats. Choose the format that best suits your workflow and data source.

Format Best for
JSONL or CSV in Cloud Storage Large, static datasets that are already stored or can be easily uploaded to Cloud Storage. This is a scalable and cost-effective option for production workflows.
BigQuery table Very large datasets (terabytes or more) that are already part of your data warehouse in BigQuery. This format is ideal for leveraging existing data infrastructure and complex queries.
Pandas DataFrame In-memory datasets used in interactive environments like Jupyter notebooks. This is convenient for experimentation, rapid prototyping, and smaller datasets that fit in memory.

Evaluation dataset examples¶

This section provides dataset examples using the Pandas DataFrame format. While only a few records are shown for illustration, a typical evaluation dataset should contain at least 100 examples for statistically meaningful results.

Troubleshooting

If you encounter issues with code snippets or setup, refer to the Troubleshooting Guide.

The following summarization example demonstrates a sample dataset for pointwise model-based metrics.

import pandas as pd

prompts = [
    # Example 1
    (
        "Summarize the text in one sentence: As part of a comprehensive"
        " initiative to tackle urban congestion and foster sustainable urban"
        " living, a major city has revealed ambitious plans for an extensive"
        " overhaul of its public transportation system. The project aims not"
        " only to improve the efficiency and reliability of public transit but"
        " also to reduce the city's carbon footprint and promote eco-friendly"
        " commuting options. City officials anticipate that this strategic"
        " investment will enhance accessibility for residents and visitors"
        " alike, ushering in a new era of efficient, environmentally conscious"
        " urban transportation."
    ),
    # Example 2
    (
        "Summarize the text such that a five-year-old can understand: A team of"
        " archaeologists has unearthed ancient artifacts shedding light on a"
        " previously unknown civilization. The findings challenge existing"
        " historical narratives and provide valuable insights into human"
        " history."
    ),
]

responses = [
    # Example 1
    (
        "A major city is revamping its public transportation system to fight"
        " congestion, reduce emissions, and make getting around greener and"
        " easier."
    ),
    # Example 2
    (
        "Some people who dig for old things found some very special tools and"
        " objects that tell us about people who lived a long, long time ago!"
        " What they found is like a new puzzle piece that helps us understand"
        " how people used to live."
    ),
]

eval_dataset = pd.DataFrame({
    "prompt": prompts,
    "response": responses,
})

The following open-book question-answering example demonstrates a sample dataset for pairwise model-based metrics, which requires a baseline_model_response for comparison.

import pandas as pd

prompts = [
    # Example 1
    (
        "Based on the context provided, what is the hardest material? Context:"
        " Some might think that steel is the hardest material, or even"
        " titanium. However, diamond is actually the hardest material."
    ),
    # Example 2
    (
        "Based on the context provided, who directed The Godfather? Context:"
        " Mario Puzo and Francis Ford Coppola co-wrote the screenplay for The"
        " Godfather, and the latter directed it as well."
    ),
]

responses = [
    # Example 1
    "Diamond is the hardest material. It is harder than steel or titanium.",
    # Example 2
    "Francis Ford Coppola directed The Godfather.",
]

baseline_model_responses = [
    # Example 1
    "Steel is the hardest material.",
    # Example 2
    "John Smith.",
]

eval_dataset = pd.DataFrame(
  {
    "prompt":  prompts,
    "response":  responses,
    "baseline_model_response": baseline_model_responses,
  }
)

For computation-based metrics, a reference (ground truth) field is required.

import pandas as pd

eval_dataset = pd.DataFrame({
  "response": ["The Roman Senate was filled with exuberance due to Pompey's defeat in Asia."],
  "reference": ["The Roman Senate was filled with exuberance due to successes against Catiline."],
})

Tool-use (function calling) metrics

The following example shows input data for computation-based tool-use metrics.

import pandas as pd

json_responses = ["""{
    "content": "",
    "tool_calls":[{
      "name":"get_movie_info",
      "arguments": {"movie":"Mission Impossible", "time": "today 7:30PM"}
    }]
  }"""]

json_references = ["""{
    "content": "",
    "tool_calls":[{
      "name":"book_tickets",
      "arguments":{"movie":"Mission Impossible", "time": "today 7:30PM"}
      }]
  }"""]

eval_dataset = pd.DataFrame({
    "response": json_responses,
    "reference": json_references,
})

    "Schulen und Kindergärten wurden eröffnet.",

    "They were able to control the fire.",
    "Schools and kindergartens opened",
]

    "source": source,
    "response": response,
    "reference": reference,
})

Best practices¶

Follow these best practices when creating your evaluation dataset:

  • Provide representative examples: Your dataset should include examples that reflect the types of inputs your model will process in a production environment.
  • Ensure sufficient size: Your dataset must include at least one evaluation example. We recommend around 100 examples to ensure high-quality aggregated metrics and statistically significant results. A larger dataset helps establish higher confidence in the evaluation results, minimizes the influence of outliers, and ensures that the performance metrics reflect the model's true capabilities. The quality of aggregated metrics tends to plateau when more than 400 examples are provided.
