Evaluate Gen AI agents¶

Preview

This feature is subject to the "Pre-GA Offerings Terms" in the General Service Terms section of the Service Specific Terms. Pre-GA features are available "as is" and might have limited support. For more information, see the launch stage descriptions.

After you build and test your generative AI model, you can use it to create an agent, such as a chatbot, that performs tasks. The generative AI evaluation service helps you measure how well your agent completes these tasks and achieves its goals for your specific use case.

This document guides you through the process of evaluating your agent's performance using the Vertex AI SDK.

Concepts
  • Agent: An autonomous system that uses a large language model (LLM) to understand user requests and perform tasks by calling appropriate tools.
  • Trajectory: The sequence of tool calls an agent makes to process a request and arrive at a final response.
  • Tool Call: A specific action or function that an agent invokes, such as calling an API or querying a database.
  • LangChain: An open-source framework for developing applications powered by language models, including agents.
  • Agent Engine: A Google Cloud platform based on LangChain on Vertex AI that lets you deploy and manage agents.

Before you begin¶

Before you can evaluate your agent, you need to choose a supported agent type and prepare your evaluation dataset.

Supported agents¶

The generative AI evaluation service supports the following types of agents. Choose the one that best fits your development environment and customization needs.

Supported Agent Description Best for...
Agent built with Agent Engine's template An agent deployed and managed on Agent Engine (LangChain on Vertex AI), a fully managed Google Cloud platform. Users who want a managed, low-code environment for deploying and managing agents.
LangChain agents built using Agent Engine's customizable template An agent built with the open-source LangChain framework and deployed on Agent Engine. Developers who need the flexibility of LangChain combined with the managed services of Agent Engine.
Custom agent function A flexible Python function that takes a prompt and returns a response and trajectory in a dictionary format. Users who have a custom-built agent and need maximum flexibility for integration.

Prepare your evaluation dataset¶

Your evaluation dataset provides the ground truth for measuring your agent's performance. The schema for your dataset depends on the evaluation method you choose.

  • Final response evaluation: The data schema is similar to that of model response evaluation.
  • Trajectory evaluation: Your dataset must include the predicted_trajectory and reference_trajectory for each example.
Input Field Description
predicted_trajectory The list of tool calls the agent actually used to generate the final response.
reference_trajectory The expected or ideal sequence of tool calls the agent should have used to satisfy the query. This is not required for the trajectory_single_tool_use metric.

The following is an example of a Pandas DataFrame for trajectory evaluation.

How to evaluate an agent¶

Follow these steps to configure and run an agent evaluation job.

Step 1: Define evaluation metrics¶

You can evaluate an agent based on its final output or the path it took to get there.

Evaluation Method Description
Final response evaluation Evaluates the quality of the agent's final output, regardless of the steps taken. This determines if the agent achieved its goal.
Trajectory evaluation Evaluates the sequence of tool calls (the path) the agent took to reach the final response. This determines if the agent followed the correct process.

With the generative AI evaluation service, you can trigger an agent execution and get metrics for both evaluation methods in a single Vertex AI SDK query.

Final response evaluation¶

Final response evaluation follows the same process as model response evaluation. For more information, see Define your evaluation metrics.

Trajectory evaluation¶

The following metrics help you evaluate the model's ability to follow the expected trajectory.

Metric Description
trajectory_exact_match Checks if the predicted trajectory is identical to the reference trajectory.
trajectory_in_order_match Checks if the predicted trajectory contains all reference tool calls in the same order, allowing for extra calls.
trajectory_any_order_match Checks if the predicted trajectory contains all reference tool calls, regardless of order and allowing for extra calls.
trajectory_precision Measures the proportion of predicted tool calls that are relevant (i.e., also in the reference trajectory).
trajectory_recall Measures the proportion of reference tool calls that were captured in the predicted trajectory.
trajectory_single_tool_use Checks if a specific tool was used in the predicted trajectory.
View details for trajectory evaluation metrics

trajectory_exact_match

If the predicted trajectory is identical to the reference trajectory, with the exact same tool calls in the exact same order, this metric returns a score of 1; otherwise, it returns 0.

  • Input parameters: predicted_trajectory, reference_trajectory
  • Output scores: 0 (no match), 1 (exact match)

trajectory_in_order_match

If the predicted trajectory contains all the tool calls from the reference trajectory in the same order (and may also have extra tool calls), this metric returns a score of 1; otherwise, it returns 0.

  • Input parameters: predicted_trajectory, reference_trajectory
  • Output scores: 0 (order does not match), 1 (in-order match)

trajectory_any_order_match

If the predicted trajectory contains all the tool calls from the reference trajectory, regardless of order (and may contain extra tool calls), this metric returns a score of 1; otherwise, it returns 0.

  • Input parameters: predicted_trajectory, reference_trajectory
  • Output scores: 0 (does not contain all reference tool calls), 1 (match)

trajectory_precision

This metric measures how many of the tool calls in the predicted trajectory are relevant according to the reference trajectory. It is calculated by dividing the number of matching tool calls by the total number of calls in the predicted trajectory.

  • Input parameters: predicted_trajectory, reference_trajectory
  • Output scores: A float in the range of [0, 1]. A higher score indicates higher precision.

trajectory_recall

This metric measures how many of the essential tool calls from the reference trajectory are captured in the predicted trajectory. It is calculated by dividing the number of matching tool calls by the total number of calls in the reference trajectory.

  • Input parameters: predicted_trajectory, reference_trajectory
  • Output scores: A float in the range of [0, 1]. A higher score indicates better recall.

trajectory_single_tool_use

This metric checks if a specific tool is present in the predicted trajectory. It does not check the order or frequency of tool calls.

  • Input parameters: predicted_trajectory
  • Output scores: 0 (tool is absent), 1 (tool is present)

In addition, the following two agent performance metrics are added to the evaluation results by default. You don't need to specify them in EvalTask.

  • latency: Time taken by the agent to return a response, measured in seconds.
  • failure: Indicates if the agent invocation resulted in an error (1) or succeeded (0).

Step 2: Import your evaluation dataset¶

You can import your dataset from a JSONL or CSV file in Cloud Storage, a BigQuery table, or a Pandas DataFrame.

The generative AI evaluation service provides public datasets to demonstrate agent evaluation. The following code shows how to import an example dataset from a Cloud Storage bucket:

# dataset name to be imported
dataset = "on-device" # Alternatives: "customer-support", "content-creation"

# copy the tools and dataset file
!gcloud storage cp gs://cloud-ai-demo-datasets/agent-eval-datasets/{dataset}/tools.py .
!gcloud storage cp gs://cloud-ai-demo-datasets/agent-eval-datasets/{dataset}/eval_dataset.json .

# load the dataset examples
import json

eval_dataset = json.loads(open('eval_dataset.json').read())

# run the tools file
%run -i tools.py

The dataset variable can be one of the following:

  • "on-device": An On-Device Home Assistant that controls home devices.
  • "customer-support": A Customer Support Agent that handles orders and support tickets.
  • "content-creation": A Marketing Content Creation Agent that manages campaigns.

Step 3: Run the evaluation¶

Run an evaluation job by defining an EvalTask. You can mix final response metrics and trajectory metrics in the same task.

Troubleshooting

If you encounter issues with code snippets or setup, refer to the Troubleshooting Guide.

single_tool_use_metric = TrajectorySingleToolUse(tool_name='tool_name')

eval_task = EvalTask(
    dataset=EVAL_DATASET,
    metrics=[
        "rouge_l_sum",
        "bleu",
        custom_trajectory_eval_metric, # custom computation-based metric
        "trajectory_exact_match",
        "trajectory_precision",
        single_tool_use_metric,
        response_follows_trajectory_metric # llm-based metric
    ],
)
eval_result = eval_task.evaluate(
    runnable=RUNNABLE,
)

Metric customization¶

You can customize evaluation metrics to fit your specific needs.

View an example of a custom model-based metric

You can customize a large language model-based metric for trajectory evaluation using a templated interface or from scratch. For more details, see Model-based metrics.

from vertexai.preview.evaluation import PointwiseMetric, PointwiseMetricPromptTemplate

response_follows_trajectory_prompt_template = PointwiseMetricPromptTemplate(
    criteria={
        "Follows trajectory": (
            "Evaluate whether the agent's response logically follows from the "
            "sequence of actions it took. Consider these sub-points:\n"
            "  - Does the response reflect the information gathered during the trajectory?\n"
            "  - Is the response consistent with the goals and constraints of the task?\n"
            "  - Are there any unexpected or illogical jumps in reasoning?\n"
            "Provide specific examples from the trajectory and response to support your evaluation."
        )
    },
    rating_rubric={
        "1": "Follows trajectory",
        "0": "Does not follow trajectory",
    },
    input_variables=["prompt", "predicted_trajectory"],
)

response_follows_trajectory_metric = PointwiseMetric(
    metric="response_follows_trajectory",
    metric_prompt_template=response_follows_trajectory_prompt_template,
)
View an example of a custom computation-based metric

You can also define a custom computation-based metric for trajectory or response evaluation.

from vertexai.preview.evaluation import CustomMetric

def essential_tools_present(instance, required_tools = ["tool1", "tool2"]):
    trajectory = instance["predicted_trajectory"]
    tools_present = [tool_used['tool_name'] for tool_used in trajectory]
    if len(required_tools) == 0:
      return {"essential_tools_present": 1}
    score = 0
    for tool in required_tools:
      if tool in tools_present:
        score += 1
    return {
        "essential_tools_present": score/len(required_tools),
    }

custom_trajectory_eval_metric = CustomMetric(name="essential_tools_present", metric_function=essential_tools_present)

Step 4: View and interpret results¶

The evaluation results are displayed in tables, separating final response metrics from trajectory metrics.

Final response metrics

Instance-level results

Column Description
response The final response generated by the agent.
latency_in_seconds Time taken to generate the response.
failure Indicates if a valid response was generated.
score The score calculated for the response based on the specified metric.
explanation The explanation for the score based on the specified metric.

Aggregate results

Column Description
mean The average score across all instances.
standard deviation The standard deviation of all scores.
Trajectory metrics

Instance-level results

Column Description
predicted_trajectory The sequence of tool calls the agent followed.
reference_trajectory The expected sequence of tool calls.
score The score calculated for the trajectory based on the specified metric.
latency_in_seconds Time taken to generate the response.
failure Indicates if a valid response was generated.

Aggregate results

Column Description
mean The average score across all instances.
standard deviation The standard deviation of all scores.
