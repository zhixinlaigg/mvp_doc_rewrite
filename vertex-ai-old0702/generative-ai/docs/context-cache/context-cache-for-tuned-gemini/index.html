Context Caching for Fine-tuned Gemini Models¶

You can use context caching for your fine-tuned Gemini models to improve performance and reduce costs for prompts that include large amounts of context. By caching frequently used context, you avoid re-sending large amounts of data with each request to your fine-tuned model.

The management operations (Read, Update, Delete) of a context cache for a tuned Gemini model are the same as for a base model. Only cached content creation and inference require specific adjustments, which are detailed in this document.

Supported models¶

Context caching is supported for models fine-tuned from the following base model:

  • gemini-1.0-pro-002

Before you begin¶

Before you begin
Concepts
  • Context Caching: A feature that stores parts of a prompt (the context) so they don't need to be resent with every API call, which saves costs and can improve latency.
  • Fine-tuning: The process of further training a pre-trained model on a specific dataset to adapt it for a particular task or improve its performance on a narrow domain.
  • Endpoint: A network-addressable interface for a deployed model that serves prediction requests.

Prerequisites

You need a deployed fine-tuned Gemini model based on a supported base model. For details on how to fine-tune a Gemini model, see Fine-tune a Gemini model. To get the endpoint for your deployed tuned model, see Deploy a tuned model.

Make sure that you have the following information:

  • The ID and the version of the tuned Gemini model.
  • The endpoint resource name for the deployed fine-tuned model.

How to use context caching with a fine-tuned model¶

Step 1: Create a context cache for a fine-tuned model

The procedure for creating a context cache for a fine-tuned model largely follows the steps outlined in Create a context cache. The main difference is that instead of using a base model in the format projects/{PROJECT}/locations/{LOCATION}/publishers/google/models/{MODEL}, you must use your fine-tuned model in the format projects/{PROJECT}/locations/{LOCATION}/models/{MODEL}@{VERSION}.

The following examples show how to create a context cache with a tuned Gemini model using the Vertex AI API.

Troubleshooting

If you encounter issues with code snippets or setup, refer to the Troubleshooting Guide.

REST API Request

To create a context cache, send a POST request to the Vertex AI API endpoint.

Before using any of the request data, make the following replacements:

  • PROJECT_ID: Your project ID.
  • LOCATION: The region to process the request. For a list of supported regions, see Available regions.
  • MODEL_ID: The ID of your fine-tuned Gemini model.
  • MODEL_VERSION: The version number of your fine-tuned Gemini model.
  • CACHE_DISPLAY_NAME: A meaningful display name to help you identify the context cache.
  • MIME_TYPE: The MIME type of the content to cache (e.g., application/pdf, video/mp4).
  • CONTENT_TO_CACHE_URI: The Cloud Storage URI of the content to cache (e.g., gs://your-bucket/document.pdf).

HTTP method and URL:

POST https://LOCATION-aiplatform.googleapis.com/v1/projects/PROJECT_ID/locations/LOCATION/cachedContents

Request JSON body:

{
  "model": "projects/PROJECT_ID/locations/LOCATION/models/MODEL_ID@MODEL_VERSION",
  "displayName": "CACHE_DISPLAY_NAME",
  "contents": [{
    "role": "user",
      "parts": [{
        "fileData": {
          "mimeType": "MIME_TYPE",
          "fileUri": "CONTENT_TO_CACHE_URI"
        }
      }]
  },
  {
    "role": "model",
      "parts": [{
        "text": "This is sample text to demonstrate explicit caching."
      }]
  }]
}

To send your request, choose one of the following options:

Note: The following command assumes that you have logged in to the gcloud CLI by running gcloud init or gcloud auth login.

  1. Save the request body in a file named request.json.

  2. Execute the following command in your terminal:

curl -X POST \  
     -H "Authorization: Bearer $(gcloud auth print-access-token)" \  
     -H "Content-Type: application/json; charset=utf-8" \  
     -d @request.json \  
     "https://LOCATION-aiplatform.googleapis.com/v1/projects/PROJECT_ID/locations/LOCATION/cachedContents"

Complete Example

This example shows a complete curl command with placeholder variables.

LOCATION="us-central1"
MODEL_ID="your-tuned-model-id"
PROJECT_ID="your-project-id"
MODEL_VERSION=1
MIME_TYPE="video/mp4"
CACHED_CONTENT_URI="gs://path-to-bucket/video-file-name.mp4"
CACHE_DISPLAY_NAME="my-tuned-model-video-cache"

curl -X POST \
-H "Authorization: Bearer $(gcloud auth print-access-token)" \
-H "Content-Type: application/json" \
https://${LOCATION}-aiplatform.googleapis.com/v1/projects/${PROJECT_ID}/locations/${LOCATION}/cachedContents -d \
'{
  "model":"projects/${PROJECT_ID}/locations/${LOCATION}/models/${MODEL_ID}@${MODEL_VERSION}",
  "displayName": "${CACHE_DISPLAY_NAME}",
  "contents": [
    {
      "role": "user",
      "parts": [
        {
          "fileData": {
            "mimeType": "${MIME_TYPE}",
            "fileUri": "${CACHED_CONTENT_URI}"
          }
        }
      ]
    }
  ]
}'

Note: The following command assumes that you have logged in to the gcloud CLI by running gcloud init or gcloud auth login.

  1. Save the request body in a file named request.json.

  2. Execute the following command in PowerShell:

$cred = gcloud auth print-access-token  
$headers = @{ "Authorization" = "Bearer $cred" }  

Invoke-WebRequest `  
    -Method POST `  
    -Headers $headers `  
    -ContentType: "application/json; charset=utf-8" `  
    -InFile request.json `  
    -Uri "https://LOCATION-aiplatform.googleapis.com/v1/projects/PROJECT_ID/locations/LOCATION/cachedContents" | Select-Object -Expand Content

Response

You should receive a JSON response similar to the following, which includes the name and metadata of the newly created cache.

{
  "name": "projects/PROJECT_NUMBER/locations/us-central1/cachedContents/CACHE_ID",
  "model": "projects/PROJECT_ID/locations/LOCATION/models/MODEL_ID@MODEL_VERSION",
  "createTime": "2024-06-04T01:11:50.808236Z",
  "updateTime": "2024-06-04T01:11:50.808236Z",
  "expireTime": "2024-06-04T02:11:50.794542Z"
}
Step 2: Use a context cache with a fine-tuned model

The procedure for using a context cache with a fine-tuned model largely follows the steps outlined in Use a context cache. The main difference is that instead of sending the request to a base model endpoint, you must send it to the endpoint of your deployed fine-tuned model in the format projects/{PROJECT}/locations/{LOCATION}/endpoints/{ENDPOINT_ID}.

When you use a context cache, you can't specify the following properties:

  • GenerativeModel.system_instructions
  • GenerativeModel.tool_config
  • GenerativeModel.tools

Troubleshooting

If you encounter issues with code snippets or setup, refer to the Troubleshooting Guide.

REST API Request

To use a context cache in a prompt, send a POST request to your deployed model's endpoint.

Before using any of the request data, make the following replacements:

  • PROJECT_ID: Your project ID.
  • LOCATION: The region where the request to create the context cache was processed.
  • ENDPOINT_ID: The endpoint where the fine-tuned model is deployed.
  • CACHE_ID: The ID of the context cache you created in the previous step.
  • PROMPT_TEXT: The text prompt to submit to the model.

HTTP method and URL:

POST https://LOCATION-aiplatform.googleapis.com/v1/projects/PROJECT_ID/locations/LOCATION/endpoints/ENDPOINT_ID:generateContent

Request JSON body:

{
  "cachedContent": "projects/PROJECT_NUMBER/locations/LOCATION/cachedContents/CACHE_ID",
  "contents": [
      {"role":"user","parts":[{"text":"PROMPT_TEXT"}]}
  ],
  "generationConfig": {
      "maxOutputTokens": 8192,
      "temperature": 1,
      "topP": 0.95
  },
  "safetySettings": [
      {
          "category": "HARM_CATEGORY_HATE_SPEECH",
          "threshold": "BLOCK_MEDIUM_AND_ABOVE"
      },
      {
          "category": "HARM_CATEGORY_DANGEROUS_CONTENT",
          "threshold": "BLOCK_MEDIUM_AND_ABOVE"
      },
      {
          "category": "HARM_CATEGORY_SEXUALLY_EXPLICIT",
          "threshold": "BLOCK_MEDIUM_AND_ABOVE"
      },
      {
          "category": "HARM_CATEGORY_HARASSMENT",
          "threshold": "BLOCK_MEDIUM_AND_ABOVE"
      }
  ]
}

To send your request, choose one of the following options:

Note: The following command assumes that you have logged in to the gcloud CLI by running gcloud init or gcloud auth login.

  1. Save the request body in a file named request.json.

  2. Execute the following command in your terminal:

curl -X POST \
