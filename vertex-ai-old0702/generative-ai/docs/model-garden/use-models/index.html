Use models in Model Garden¶

Discover, test, tune, and deploy generative AI models by using Model Garden in the Google Cloud console. You can also interact with Model Garden models programmatically by using the Vertex AI SDK for Python, the Google Cloud CLI, or the REST API.

This document guides you through the common lifecycle of using a model from Model Garden, from initial discovery to final cleanup.

The following workflow shows the general steps for using a model from Model Garden.

flowchart TD
    A[Discover and test a model] --> B{Need to customize?};
    B -- Yes --> C[Tune a model];
    B -- No --> D[Deploy a model];
    C --> D;
    D --> E[Manage and clean up resources];

    click A "#discover-and-test-a-model"
    click C "#tune-a-model"
    click D "#deploy-a-model"
    click E "#manage-and-clean-up-resources"

Before you begin¶

Concepts
  • Model Garden: A central place in Vertex AI to discover, test, tune, and deploy Google-proprietary and select open source models.
  • Model Registry: A central repository for managing the lifecycle of your ML models after they are trained or imported.
  • Endpoint: A service you deploy your model to, which serves online predictions. An endpoint has a unique URI that you send prediction requests to.
  • Tuning: The process of adjusting a pre-trained model's parameters on a specific dataset to improve its performance on a particular task.
Set up your project and environment
  1. In the Google Cloud console, on the project selector page, select or create a Google Cloud project.
  2. Make sure that billing is enabled for your Google Cloud project.
  3. Enable the Vertex AI API.
  4. If you are using the gcloud CLI or the SDK, install and initialize the Google Cloud CLI.

Discover and test a model¶

The first step is to explore Model Garden to find a model suitable for your use case. You can then test it directly in the console using the prompt design interface or review its documentation for code samples.

Steps to discover and test a model

Send test prompts

  1. In the Google Cloud console, go to the Model Garden page.

    Go to Model Garden

  2. Find a supported model that you want to test and click View details.

  3. Click Open prompt design. You're taken to the Prompt design page.
  4. In the Prompt field, enter the prompt that you want to test.
  5. Optional: Configure the model parameters.
  6. Click Submit.

View code samples

Most model cards for task-specific models contain code samples that you can copy and test.

  1. In the Google Cloud console, go to the Model Garden page.
  2. Find a supported model and click its model card to view details.
  3. Click the Documentation tab to find embedded code samples.

Tune a model¶

For some models, you can fine-tune them with your own data to improve their performance on a specific task. Model Garden supports tuning through a guided pipeline or by using a Jupyter notebook for more control.

Method Best For Description
Fine-tuning pipeline Users who prefer a guided, UI-based experience for tuning standard models like T5-FLAN or BERT. A structured pipeline in the Google Cloud console that walks you through the tuning process.
Notebook Developers who need more flexibility and control over the tuning process and environment. Most open source and fine-tunable models provide a notebook that can be opened in Vertex AI Workbench or Colab.

  1. In the Google Cloud console, go to the Model Garden page.

    Go to Model Garden

  2. In Search models, enter BERT or T5-FLAN, then click the magnifying glass to search.

  3. Click View details on the T5-FLAN or the BERT model card.
  4. Click Open fine-tuning pipeline. You're taken to the Vertex AI pipelines page.
  5. To start tuning, click Create run.

  1. In the Google Cloud console, go to the Model Garden page.

    Go to Model Garden

  2. Find a supported model that you want to tune and go to its model card.

  3. Click Open notebook.

Deploy a model¶

After you have selected a model, deploy it to a Vertex AI endpoint to serve online predictions. You can deploy models using the Google Cloud console for a guided experience, or programmatically using the Vertex AI SDK, gcloud CLI, or REST API for automation and integration.

Method Best For Key Features
Console Quick deployments and users who prefer a graphical interface. Guided, step-by-step UI for configuration and deployment.
Vertex AI SDK for Python Integrating model deployment into Python applications and MLOps workflows. High-level, intuitive Python library for managing AI resources.
gcloud CLI Scripting, automation, and terminal-based management. Command-line interface for managing Google Cloud resources.
REST API Integrating with custom applications or services in any language. Language-agnostic interface for programmatic control over resources.

Troubleshooting

If you encounter issues with code snippets or setup, refer to the Troubleshooting Guide.

You can deploy both open models and partner models through the Google Cloud console.

Deploy an open model

  1. In the Google Cloud console, go to the Model Garden page.

    Go to Model Garden

  2. Find a supported model that you want to deploy, and click its model card.

  3. Click Deploy to open the Deploy model pane.
  4. In the Deploy model pane, specify details for your deployment.
    1. Use or modify the generated model and endpoint names.
    2. Select a location to create your model endpoint in.
    3. Select a machine type to use for each node of your deployment.
    4. To use a Compute Engine reservation, under the Deployment settings section, select Advanced. For the Reservation type field, select a reservation type. The reservation must match your specified machine specs.
      • Automatically use created reservation: Vertex AI automatically selects an allowed reservation with matching properties.
      • Select specific reservations: Vertex AI uses a specific reservation. If there's no capacity, an error is thrown.
      • Don't use (default): Vertex AI uses the general Google Cloud resource pool.
  5. Click Deploy.
Deploy a partner model

Preview

Before you begin

You must have an agreement with the partner, including terms, licensing, and pricing. To initiate contact, see the partner documentation on their Model Garden model card and click Contact sales. You must deploy on the partner's required machine types.

Note: For self-deploy partner models, if you have sufficient quotas but encounter serving quota issues during deployment, contact your Google Cloud account team for assistance.

Steps

  1. In the Google Cloud console, go to the Model Garden page.

    Go to Model Garden

  2. To find a specific model, enter its name in the Model Garden search box.

  3. To view all models that you can self-deploy, in the Model collections section of the filter pane, select Self-deploy partner models.
  4. Click the name of the model to deploy, which opens its model card.
  5. Click Deploy options.
  6. In the Deploy on Vertex AI pane, configure your deployment such as the location and machine type.
  7. Click Deploy.

After the deployment is complete, you can request predictions by using the SDK or API. Additional instructions are available in the "Documentation" section on the model card.

For more information about setting up the SDK, see the Google Gen AI SDK overview or Install the Vertex AI SDK for Python.

Deploy an open model

1. List deployable models

Run the gcloud ai model-garden models list command to find the model ID to deploy.

gcloud ai model-garden models list

The output shows model IDs and whether they support deployment. To view supported Hugging Face models, add the --can-deploy-hugging-face-models flag.

MODEL_ID                                                                SUPPORTS_DEPLOYMENT
google/gemma2@gemma-2-27b                                               Yes
google/gemma2@gemma-2-27b-it                                            Yes
...

2. View deployment specifications

Run the gcloud ai model-garden models list-deployment-config command to view supported machine types, accelerators, and container URIs.

gcloud ai model-garden models list-deployment-config \
    --model=MODEL_ID

Replace MODEL_ID with the ID from the previous step (e.g., google/gemma@gemma-2b).

3. Deploy a model to an endpoint

Run the gcloud ai model-garden models deploy command. Model Garden uses default settings unless you specify them.

gcloud ai model-garden models deploy \
    --model=MODEL_ID \
    [--machine-type=MACHINE_TYPE] \
    [--accelerator-type=ACCELERATOR_TYPE] \
    [--endpoint-display-name=ENDPOINT_NAME] \
    [--hugging-face-access-token=HF_ACCESS_TOKEN] \
    [--reservation-affinity reservation-affinity-type=any-reservation] \
    [--reservation-affinity reservation-affinity-type=specific-reservation,key="compute.googleapis.com/reservation-name",values=RESERVATION_RESOURCE_NAME] \
    [--asynchronous]

Replace the placeholders: * MODEL_ID: The model ID to deploy. For Hugging Face models, use the URL format (e.g., stabilityai/stable-diffusion-xl-base-1.0). * MACHINE_TYPE: The machine type for deployment (e.g., g2-standard-4). * ACCELERATOR_TYPE: The accelerator type (e.g., NVIDIA_L4). * ENDPOINT_NAME: A name for the Vertex AI endpoint. * HF_ACCESS_TOKEN: An access token for gated Hugging Face models. * RESERVATION_RESOURCE_NAME: The name of a specific Compute Engine reservation.

4. View deployment details

Run the gcloud ai endpoints list --list-model-garden-endpoints-only command to see details about your deployment.

gcloud ai endpoints list --list-model-garden-endpoints-only \
    --region=LOCATION_ID

Replace LOCATION_ID with the region where you deployed the model.

Manage and clean up resources¶

To avoid incurring unnecessary charges to your Google Cloud account, it's important to clean up the resources you created. This involves undeploying the model from its endpoint, then deleting the endpoint and the model from the Model Registry.

View or manage an endpoint¶

To view and manage your endpoint, go to the Vertex AI Online prediction page.

Go to Online prediction

Clean up resources¶

To stop a deployed model from using resources, you must perform the following steps in order: 1. Undeploy the model from its endpoint. 2. Delete the endpoint. 3. Delete the model from the Model Registry.

Undeploy a model

  1. In the Google Cloud console, go to the Endpoints tab on the Online prediction page.

    Go to Endpoints

  2. In the Region drop-down list, choose the region where your endpoint is located.

  3. Click the endpoint name to open the details page.
  4. On the row for the model, click more_vert Actions, and then select Undeploy model from endpoint.
  5. In the Undeploy model from endpoint dialog, click Undeploy.
Delete an endpoint

  1. In the Google Cloud console, go to the Endpoints tab on the Online prediction page.

    Go to Endpoints

  2. In the Region drop-down list, choose the region your endpoint is located.

  3. At the end of the endpoint's row, click more_vert Actions, and then select Delete endpoint.
  4. In the confirmation prompt, click Confirm.
Delete a model

  1. Go to the Model Registry page from the Vertex AI section in the Google Cloud console.

    Go to the Model Registry page

  2. In the Region drop-down list, choose the region where you deployed your model.

  3. On the row for your model, click more_vert Actions and then select Delete model.
  4. In the confirmation prompt, click Delete.

Replace the placeholders in the commands with your PROJECT_ID, LOCATION_ID, ENDPOINT_ID, MODEL_ID, and DEPLOYED_MODEL_ID.

Undeploy a model

  1. Find the endpoint ID associated with your deployment.

    gcloud ai endpoints list \
    --project=PROJECT_ID \
    --region=LOCATION_ID

  2. Find the model ID.

    gcloud ai models list \
    --project=PROJECT_ID \
    --region=LOCATION_ID

  3. Get the deployed model ID using the model ID from the previous step.

    gcloud ai models describe MODEL_ID \
    --project=PROJECT_ID \
    --region=LOCATION_ID

    In the output, find the deployedModelId.

  4. Undeploy the model from the endpoint.

    gcloud ai endpoints undeploy-model ENDPOINT_ID \
    --project=PROJECT_ID \
    --region=LOCATION_ID \
    --deployed-model-id=DEPLOYED_MODEL_ID
Delete an endpoint

  1. Get the endpoint ID to delete.

    gcloud ai endpoints list \
    --project=PROJECT_ID \
    --region=LOCATION_ID

  2. Delete the endpoint.

    gcloud ai endpoints delete ENDPOINT_ID \
    --project=PROJECT_ID \
    --region=LOCATION_ID

    When prompted, type y to confirm.

Delete a model

  1. Find the model ID to delete.

    gcloud ai models list \
    --project=PROJECT_ID \
    --region=LOCATION_ID

  2. Delete the model.

    gcloud ai models delete MODEL_ID \
    --project=PROJECT_ID \
    --region=LOCATION_ID
