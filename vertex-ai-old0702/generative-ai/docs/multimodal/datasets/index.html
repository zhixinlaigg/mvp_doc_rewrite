Multimodal datasets¶

Preview

This feature is subject to the "Pre-GA Offerings Terms" in the General Service Terms section of the Service Specific Terms. Pre-GA features are available "as is" and might have limited support. For more information, see the launch stage descriptions.

To see an example of Multimodal datasets, run the "Vertex AI Multimodal Dataset Preview" Jupyter notebook in one of the following environments:

Open in Colab Open in Colab Enterprise Open in Vertex AI Workbench View on GitHub

Multimodal datasets on Vertex AI let you create, manage, share, and use multimodal datasets for Generative AI. You can use multimodal datasets through the Vertex AI SDK for Python or the REST API.

Key features include:

  • Flexible Data Loading: Load datasets from BigQuery, DataFrames, or JSONL files in Cloud Storage.
  • Unified Data Source: Create your dataset once and use it across different jobs, such as supervised fine-tuning and batch prediction, which prevents data duplication and formatting issues.
  • Centralized Management: Keep all your generative AI datasets in a single, managed location.
  • Pre-run Validation: Validate your schema and structure and quantify the resources needed for downstream tasks, helping you catch errors and estimate costs before you start a task.

Overview of Multimodal Datasets¶

Multimodal datasets are a type of managed dataset on Vertex AI, specifically designed for generative AI workflows. They differ from other managed datasets in the following ways:

Feature Multimodal Datasets Other Managed Datasets
Supported Modality Any modality (text, image, audio, video). Single modality only.
Use Case Generative AI services on Vertex AI (e.g., tuning, batch prediction). Vertex AI predictive models (e.g., AutoML, custom training).
Supported Methods Includes generative-specific methods like assemble and assess. Standard dataset management methods.
Underlying Storage Stored in BigQuery, optimized for large-scale data. Varies based on dataset type.

Before you begin¶

Prerequisites
Concepts
  • Multimodal Dataset: A managed dataset in Vertex AI that can contain data of various types (text, image, video, audio) and is used for generative AI tasks.
  • Template: A configuration that defines how to transform the raw data in your dataset into a format that a generative model can understand, typically a prompt-response structure.
  • Assemble: An optional process that applies a template to your dataset and saves the formatted output to a new BigQuery table, allowing you to preview the data before using it.
  • Assess: A method to validate your dataset for errors or estimate the resource usage (e.g., token count) for a downstream task like tuning or batch prediction.
  • BigQuery: A serverless, highly scalable data warehouse that is used as the underlying storage for multimodal datasets.

  1. Sign in to your Google Cloud account. If you're new to Google Cloud, create an account to evaluate how our products perform in real-world scenarios. New customers also get $300 in free credits to run, test, and deploy workloads.

  2. In the Google Cloud console, on the project selector page, select or create a Google Cloud project.

    Note: If you don't plan to keep the resources that you create in this procedure, create a project instead of selecting an existing project. After you finish these steps, you can delete the project, removing all resources associated with the project.

    Go to project selector

  4. Enable the Vertex AI, BigQuery, and Cloud Storage APIs.

Create a dataset¶

You can create a multimodal dataset from several sources. Choose the source that best fits your data's current location and format.

Source Description Use Case
Pandas DataFrame In-memory data structure. Best for smaller datasets that fit in memory, ideal for quick prototyping and experimentation in notebooks.
BigQuery DataFrame A lazy-loaded DataFrame backed by a BigQuery table. Suitable for large datasets stored in BigQuery, allowing for pandas-like operations without loading all data into memory.
BigQuery Table A direct reference to a table in BigQuery. The most efficient method for very large datasets already stored in BigQuery, avoiding data movement.
JSONL in Cloud Storage A file where each line is a JSON object. Useful when your data is already formatted as Gemini requests and stored in Cloud Storage.
Existing Dataset Reference an existing MultimodalDataset on Vertex AI. Use when you need to load or reuse a dataset that has already been created. 
my_dataset = datasets.MultimodalDataset.from_pandas(
    dataframe=my_dataframe,
    target_table_id=table_id    # optional
)

For more information, see Introduction to BigQuery DataFrames.

my_dataset = datasets.MultimodalDataset.from_bigframes(
    dataframe=my_dataframe,
    target_table_id=table_id    # optional
)

my_dataset_from_bigquery = datasets.MultimodalDataset.from_bigquery(
    bigquery_uri=f"bq://projectId.datasetId.tableId"
)

This example assumes the JSONL file in Cloud Storage contains requests that are already formatted for Gemini, so no assembly is required.

my_dataset = datasets.MultimodalDataset.from_gemini_request_jsonl(
  gcs_uri = gcs_uri_of_jsonl_file,
)

# Get the most recently created dataset
first_dataset = datasets.MultimodalDataset.list()[0]

# Load dataset based on its name
same_dataset = datasets.MultimodalDataset(first_dataset.name)

Construct and attach a template¶

A template defines how to transform the multimodal dataset into a format that can be passed to the model. This is required for running a tuning or batch prediction job.

You can construct a template in two ways. Choose the method that best suits the complexity of your data format.

Template Method Description Use Case
construct_single_turn_template A helper method for creating a simple, single-turn conversation template. Ideal for straightforward prompt-response pairs where you have one user input and one model output.
GeminiExample A more flexible method that allows for constructing complex, multi-turn conversation templates. Necessary for multi-turn dialogues or when you need fine-grained control over the conversation structure.

Method 1: Use the construct_single_turn_template helper

This is the simplest way to create a template for single-turn conversations.

# 1. Construct the template
template_config = datasets.construct_single_turn_template(
        prompt="This is the image: {image_uris}",
        response="{labels}",
        system_instruction='You are a botanical image classifier. Analyze the provided image '
                'and determine the most accurate classification of the flower.'
                'These are the only flower categories: [\'daisy\', \'dandelion\', \'roses\', \'sunflowers\', \'tulips\'].'
                'Return only one category per image.'
)

# 2. Attach it to the dataset
my_dataset.attach_template_config(template_config=template_config)

Method 2: Manually construct a template from a GeminiExample

This method allows for finer granularity, such as multi-turn conversations. The following code sample also includes optional commented code for specifying a field_mapping, which lets you use a placeholder name that is different from the column name of the dataset.

# 1. Define a GeminiExample
gemini_example = datasets.GeminiExample(
    contents=[
        Content(role="user", parts=[Part.from_text("This is the image: {image_uris}")]),
        Content(role="model", parts=[Part.from_text("This is the flower class: {label}.")]),
        Content(role="user", parts=[Part.from_text("Your response should only contain the class label.")]),
        Content(role="model", parts=[Part.from_text("{label}")]),

        # Optional: If you specify a field_mapping, you can use different placeholder values. For example:
        # Content(role="user", parts=[Part.from_text("This is the image: {uri_placeholder}")]),
        # Content(role="model", parts=[Part.from_text("This is the flower class: {flower_placeholder}.")]),
        # Content(role="user", parts=[Part.from_text("Your response should only contain the class label.")]),
        # Content(role="model", parts=[Part.from_text("{flower_placeholder}")]),
    ],
    system_instruction=Content(
        parts=[
            Part.from_text(
                'You are a botanical image classifier. Analyze the provided image '
                'and determine the most accurate classification of the flower.'
                'These are the only flower categories: [\'daisy\', \'dandelion\', \'roses\', \'sunflowers\', \'tulips\'].'
                'Return only one category per image.'
            )
        ]
    ),
)

# 2. Construct the template, specifying a map for the placeholder
template_config = datasets.GeminiTemplateConfig(
    gemini_example=gemini_example,

    # Optional: Map the template placeholders to the column names of your dataset.
    # Not required if the template placeholders are column names of the dataset.
    # field_mapping={"uri_placeholder": "image_uris", "flower_placeholder": "labels"},
)

# 3. Attach it to the dataset
my_dataset.attach_template_config(template_config=template_config)

(Optional) Assemble the dataset¶

The assemble method applies the template to transform your dataset and stores the output in a new BigQuery table. This lets you preview the data before it is passed to the model. By default, the dataset's attached template_config is used, but you can specify a template to override this behavior.

For example, assume your multimodal dataset contains the following data:

Row image_uris labels
1 gs://cloud-samples-data/ai-platform/flowers/daisy/1396526833_fb867165be_n.jpg daisy

The assemble method creates a new BigQuery table where each row contains the formatted request body, as shown in the example below.

Use the dataset¶

After creating and templating your dataset, you can use it to tune Gemini models or run a batch prediction job.

Tune your model¶

You can use a multimodal dataset for supervised fine-tuning of a Gemini model.

Optional: Validate the dataset for tuning

Assess the dataset to check for formatting errors or other issues before starting a tuning job.

Call assess_tuning_validity(). By default, the dataset's attached template_config is used.

# Attach template
my_dataset.attach_template_config(template_config=template_config)

# Validation for tuning
validation = my_dataset.assess_tuning_validity(
    model_name="gemini-1.0-pro-002",
    dataset_usage="SFT_TRAINING"
)

# Inspect validation result
validation.errors

Call the assess method and provide a TuningValidationAssessmentConfig.

curl -X POST \
-H "Authorization: Bearer $(gcloud auth print-access-token)" \
-H "Content-Type: application/json" \
"https://LOCATION-aiplatform.googleapis.com/v1beta1/projects/PROJECT_ID/locations/LOCATION/datasets/DATASET_ID:assess" \
-d '{
  "tuningValidationAssessmentConfig": {
    "modelName": "projects/PROJECT_ID/locations/LOCATION/publishers/google/models/gemini-1.0-pro-002",
    "datasetUsage": "SFT_TRAINING"
  }
}'
Optional: Estimate resource usage for tuning

Assess the dataset to get the token and billable character count for your tuning job.

Call assess_tuning_resources().

# Resource estimation for tuning.
tuning_resources = my_dataset.assess_tuning_resources(
    model_name="gemini-1.0-pro-002"
)

print(tuning_resources)
# For example, TuningResourceUsageAssessmentResult(token_count=362688, billable_character_count=122000)

Run the batch prediction job

You can use your multimodal dataset to do batch prediction by passing the BigQuery table_id of the assembled output. For more information, see Request a batch prediction job.

from vertexai.batch_prediction import BatchPredictionJob

# Dataset needs to have an attached template_config to batch prediction
my_dataset.attach_template_config(template_config=template_config)

# assemble dataset to get assembly table id
assembly_table_id, _ = my_dataset.assemble()

batch_prediction_job = BatchPredictionJob.submit(
    source_model="gemini-1.0-pro-002",
    input_dataset=assembly_table_id,
)

from google import genai

client = genai.Client(http_options=HttpOptions(api_version="v1"))

# Attach template_config and assemble dataset
my_dataset.attach_template_config(template_config=template_config)
assembly_table_id, _ = my_dataset.assemble()

job = client.create_batch_prediction_job(
    model="gemini-1.0-pro-002",
    input_dataset=assembly_table_id,
)

Limitations¶

  • Multimodal datasets can be used with only generative AI features. They cannot be used with non-generative AI features such as AutoML training and custom training.
  • Multimodal datasets can be used with only Google models such as Gemini. They cannot be used with third-party models.

Pricing¶

When you tune a model or run a batch prediction job, you are billed for Generative AI usage and querying the dataset in BigQuery.

When you create, assemble, or assess your multimodal dataset, you are billed for storing and querying multimodal datasets in BigQuery. Specifically, the following operations use of those underlying services:

  • Create dataset:
    • Datasets created from either an existing BigQuery table or dataframe incur no additional storage costs. This is because we use a logical view instead of storing another copy of the data.
    • Datasets created from other sources copy the data to a new BigQuery table, which incurs storage costs in BigQuery. For example, active logical storage for $0.02 per GiB per month.
  • Assemble dataset:
    • This method creates a new BigQuery table that contains the full dataset in model request format, which incurs storage costs in BigQuery. For example, active logical storage for $0.02 per GiB per month.
    • This method also reads the dataset once, which incurs query costs in BigQuery. For example, on-demand compute pricing, $6.25 per TiB.
  • Assess dataset:
    • This method reads the dataset once, which incurs query costs in BigQuery. For example, on-demand compute pricing, $6.25 per TiB.
