Break down complex tasks into simpler prompts¶

For complex tasks that require multiple instructions or steps, you can improve the model's responses by breaking your prompts into subtasks. Smaller, more focused prompts enhance controllability, simplify debugging, and increase accuracy.

Concepts
  • Prompt: An instruction or question given to a large language model to elicit a specific response.
  • Prompt Chaining: A technique where a complex task is broken into sequential steps, and the output of one prompt serves as the input for the next.
  • Response Aggregation: A technique where a complex task is broken into parallel subtasks, and their individual responses are combined in a final step to produce the result.

Choose a method for breaking down tasks¶

There are two primary methods for breaking down complex prompts: chaining them sequentially or aggregating their responses in parallel. The following table compares these two approaches to help you select the best one for your use case.

Method Description Use Case
Chain prompts Splits a task into sequential subtasks, where the output of one step becomes the input for the next. Best for tasks with inherent dependencies, where each step builds upon the previous one, such as a multi-step data analysis pipeline.
Aggregate responses Splits a task into independent subtasks that can be executed in parallel. The individual results are then combined in a final step. Ideal for tasks where sub-components can be processed independently, such as analyzing multiple data sources before synthesizing a summary.

For complex tasks that involve multiple sequential steps, make each step a prompt and chain the prompts together in a sequence. In this sequential chain of prompts, the output of one prompt in the sequence becomes the input of the next prompt. The output of the last prompt in the sequence is the final output.

The following workflow illustrates how to chain prompts to analyze customer feedback.

flowchart TD
    A[Start with Customer Feedback] --> B[Task 1: Extract Issues and Sentiments]
    B --> C[Task 2: Classify Issues]
    C --> D[Task 3: Generate Solutions]
    D --> E[End with Actionable Recommendations]

click B "#task-1-identify-customer-issues"
click C "#task-2-classify-issues-into-categories"
click D "#task-3-generate-solutions"
Example: Analyze customer feedback

Suppose you run a telecommunications business and want to use a model to help you analyze customer feedback to identify common customer issues, classify issues into categories, and generate solutions for those categories.

Task 1: Identify customer issues

The first task is to extract meaningful data from raw customer feedback. A prompt that achieves this task might be similar to the following, where CUSTOMER_FEEDBACK is a variable containing the customer feedback:

Extract the main issues and sentiments from the customer feedback on our telecom services.
Focus on comments related to service disruptions, billing issues, and customer support interactions.
Please format the output into a list with each issue/sentiment in a sentence, separated by a semicolon.

Input: CUSTOMER_FEEDBACK

The model's response should contain a list of extracted issues and sentiments from the customer feedback.

Task 2: Classify issues into categories

Next, use the response from the previous task to prompt the model to classify the data into categories. A prompt that achieves this task might look similar to the following, where TASK_1_RESPONSE is the response from the previous task:

Classify the extracted issues into categories such as service reliability, pricing concerns, customer support quality, and others.
Please organize the output into JSON format with each issue as the key, and category as the value.

Input: TASK_1_RESPONSE

The model's response should contain the categorized issues.

Task 3: Generate solutions

Finally, prompt the model to generate actionable recommendations based on the categorized issues, using the response from the previous task. A prompt that achieves this might look similar to the following, where TASK_2_RESPONSE is the response from the previous task:

Generate detailed recommendations for each category of issues identified from the feedback.
Suggest specific actions to address service reliability, improving customer support, and adjusting pricing models, if necessary.
Please organize the output into a JSON format with each category as the key, and recommendation as the value.

Input: TASK_2_RESPONSE

The model's response should contain recommendations for each category, aimed at improving customer experience and service quality.

Troubleshooting

If you encounter issues with the prompts, refer to the Troubleshooting Guide.

In cases where you have complex tasks that don't need to be performed in a specific order, you can run parallel prompts and aggregate the model's responses.

The following workflow illustrates how to run parallel prompts and aggregate the responses to create a record store stocklist.

    subgraph "Parallel Analysis"
    A[Task 1a: Analyze Sales Data]
    B[Task 1b: Analyze Streaming Data]
    end
    C[Start with Store and Streaming Data] --> A
    C --> B
    A --> D[Task 2: Aggregate Data and Recommend Stocklist]
    B --> D[Task 2: Aggregate Data and Recommend Stocklist]
    D --> E[End with Recommended Stocklist]

click A "#task-1a-analyze-sales-data"
click B "#task-1b-analyze-streaming-data"
click D "#task-2-aggregate-data"
Example: Create a record store stocklist

Suppose you own a record store and want to use a model to help you decide which records to stock based on music streaming trends and your store's sales data.

Task 1: Analyze data in parallel

First, analyze the two datasets: streaming data and sales data. You can run the prompts to complete these tasks in parallel.

Task 1a: Analyze sales data

A prompt to analyze sales data might be similar to the following, where STORE_SALES_DATA is a variable containing the sales data:

Analyze the sales data to identify the number of sales of each record.
Please organize the output into a JSON format with each record as the key, and sales as the value.

Input: STORE_SALES_DATA

The expected output is a JSON object containing the number of sales for each record.

Task 1b: Analyze streaming data

A prompt to analyze streaming data might be similar to the following, where STREAMING_DATA is a variable containing the streaming data:

Analyze the streaming data to provide the number of streams for each album.
Please organize the output into a JSON format with each album as the key, and streams as the value.

Input: STREAMING_DATA

The expected output is a JSON object containing the number of streams for each album.

Task 2: Aggregate data

Now, you can aggregate the data from both tasks to help plan your purchasing decisions. To do this, include the output from both previous tasks as input. A prompt that achieves this might look similar to the following, where TASK_1A_RESPONSE and TASK_1B_RESPONSE are the responses from the previous tasks:

Recommend a stocklist of about 20 records based on the most sold and most streamed records.
Roughly three quarters of the stock list should be based on record sales, and the rest on streaming.

Input: TASK_1A_RESPONSE and TASK_1B_RESPONSE

The expected output is a suggested stocklist of about 20 records, weighted towards records with a proven sales history.

Troubleshooting

If you encounter issues with the prompts, refer to the Troubleshooting Guide.
