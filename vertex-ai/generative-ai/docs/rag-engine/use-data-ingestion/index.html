Use data ingestion with Vertex AI RAG Engine¶

This page explains how to perform data ingestion for Vertex AI RAG Engine using supported data sources like Cloud Storage, Google Drive, Slack, Jira, or SharePoint. The ImportRagFiles API provides data connectors to these sources.

Vertex AI RAG Engine supports VPC-SC security controls and CMEK. Data residency and AXT security controls are not supported.

Before you begin¶

Concepts
  • RAG Corpus: A collection of documents that you provide to ground a model's responses.
  • Data Ingestion: The process of importing and processing files from a data source into a RAG corpus.
  • Data Connector: A pre-built integration that allows RAG Engine to pull data from a specific source like Slack or Jira.
  • Secret Manager: A Google Cloud service that securely stores and manages API keys, passwords, and other sensitive data.
  • Chunking: The process of breaking down large documents into smaller, more manageable pieces for efficient processing and retrieval.

Key concepts for data ingestion¶

Data deduplication¶

If the same file is imported multiple times with no changes, the file is skipped because it already exists. The response.skipped_rag_files_count in the API response refers to the number of files that were skipped during the import process.

A file is skipped when all of the following conditions are met:

  • The file has been previously imported.
  • The file content has not changed.
  • The chunking configuration for the file has not changed.

Understand import failures¶

To understand import failures, you can inspect the metadata in a response to an import request and configure a data sink to log results.

Response metadata

You can use response.metadata (a response object in the SDK) to view the import results, the request time, and the response time.

Import result sink

In the SDK, import_result_sink is an optional parameter where you can specify a destination for detailed import logs. If provided, the successful and failed file results are written to this sink, making it easier to diagnose failures.

The import_result_sink must be a Cloud Storage path or a BigQuery table.

  • Cloud Storage: The path must be in the format gs://my-bucket/my/object.ndjson, and the object must not already exist. After the import job completes, each line of the object contains a JSON object with details like operation ID, timestamp, filename, status, and file ID.
  • BigQuery: The table path must be in the format bq://my-project.my-dataset.my-table. If the table doesn't exist, it is created. If it exists, its schema is verified.

Ingest data from a supported source¶

Vertex AI RAG Engine supports several data sources. Choose the one that best fits your needs.

Data Source Description Use Case
Local File Upload A synchronous, single-file upload (up to 25 MB) using the upload_file method. Best for quick tests or ingesting individual small documents directly.
Cloud Storage Import one or more files from a Cloud Storage bucket. Ideal for batch processing of large files or integrating with existing cloud data pipelines.
Google Drive Import a directory from Google Drive. Useful for ingesting documents and files stored and managed within Google Workspace.
Slack Import channel messages and files using a data connector. Best for building a knowledge base from team communications and shared resources in Slack.
Jira Import issues and project data using a data connector. Ideal for grounding models with information from project management and issue tracking systems.
SharePoint Import files and folders from a SharePoint site. Useful for leveraging documents and data stored in a corporate SharePoint environment.

For more information on file size limits, see Supported document types.

Troubleshooting

If you encounter issues with code snippets or setup, refer to the Troubleshooting Guide.

You can import files from Cloud Storage or Google Drive into your corpus. The system automatically checks your file's path, filename, and content hash to prevent re-indexing unchanged files. If a file with the same name and path has its content updated, it is re-indexed.

Steps to import files from Cloud Storage or Google Drive

1. Create a RAG corpus

Follow the instructions at Create a RAG corpus.

2. Grant permissions (Google Drive only)

If you are importing from Google Drive, you must grant the Vertex AI RAG Data Service Agent permissions to access your files.

  1. Go to the IAM page of your Google Cloud project.
  2. Select Include Google-provided role grant.
  3. Search for the Vertex AI RAG Data Service Agent service account and copy its email address.
  4. In Google Drive, click Share on the folder or file you want to import.
  5. Share it with the service account email and grant it Viewer permission. The Google Drive resource ID can be found in the web URL.

3. Import your files

Use the code samples at Import RagFiles API to import your files from Cloud Storage or Google Drive.

Import files and messages from a Slack workspace using the Slack data connector.

Steps to import files from Slack

1. Create a RAG corpus

Follow the instructions at Create a RAG corpus.

2. Configure a Slack app

  1. Create a new Slack app in your workspace.
  2. From the Slack UI, navigate to the Permissions page under Add features and functionality.
  3. Add the following OAuth scopes:
    • channels:history
    • groups:history
    • im:history
    • mpim:history
  4. Click Install to Workspace to install the app.
  5. Copy the Bot User OAuth Token, which will serve as your API token.

3. Store the API token in Secret Manager

  1. Add your API token as a new secret in Secret Manager.
  2. Grant the Secret Manager Secret Accessor role to your project's Vertex AI RAG Data Service Agent service account to allow it to access the stored secret.

4. Import files from Slack

Use the following code samples to import files. Get your CHANNEL_ID from the Slack channel you want to import.

curl

If you want to get messages from a specific channel, change the CHANNEL_ID.

API_KEY_SECRET_VERSION=SLACK_API_KEY_SECRET_VERSION
CHANNEL_ID=SLACK_CHANNEL_ID
PROJECT_ID=us-central1

curl -X POST \
-H "Authorization: Bearer $(gcloud auth print-access-token)" \
-H "Content-Type: application/json" \
https://\${ENDPOINT}/v1beta1/projects/\${PROJECT_ID}/locations/\${PROJECT_ID}/ragCorpora/\${RAG_CORPUS_ID}/ragFiles:import \
-d '{
  "import_rag_files_config": {
    "slack_source": {
      "channels": [
        {
          "apiKeyConfig": {
            "apiKeySecretVersion": "'"${API_KEY_SECRET_VERSION}"'"
          },
          "channels": [
            {
              "channel_id": "'"${CHANNEL_ID}"'"
            }
          ]
        }
      ]
    }
  }
}'

Python

If you want to get messages for a given time range or from a specific channel, change the START_TIME, END_TIME, CHANNEL1, or CHANNEL2 fields.

# Slack example
start_time = protobuf.timestamp_pb2.Timestamp()
start_time.GetCurrentTime()
end_time = protobuf.timestamp_pb2.Timestamp()
end_time.GetCurrentTime()
source = rag.SlackChannelsSource(
    channels = [
        SlackChannel("CHANNEL1", "api_key1"),
        SlackChannel("CHANNEL2", "api_key2", START_TIME, END_TIME)
    ],
)

response = rag.import_files(
    corpus_name="projects/my-project/locations/us-central1/ragCorpora/my-corpus-1",
    source=source,
    chunk_size=512,
    chunk_overlap=100,
)

Import issues and project data from Jira using the Jira data connector.

Steps to import files from Jira

1. Create a RAG corpus

Follow the instructions at Create a RAG corpus.

2. Create a Jira API token

  1. Sign in to the Atlassian site and create an API token.
  2. Copy the token for the next step.

3. Store the API token in Secret Manager

  1. Add your API token as a new secret in Secret Manager.
  2. Grant the Secret Manager Secret Accessor role to your project's Vertex AI RAG Data Service Agent service account.

4. Import files from Jira

Provide projects or customQueries with your request. When you import projects, the project name is expanded into a query to retrieve all issues (e.g., MyProject becomes project = MyProject). To learn more about custom queries, see Use advanced search with Jira Query Language (JQL).

curl

EMAIL=JIRA_EMAIL
API_KEY_SECRET_VERSION=JIRA_API_KEY_SECRET_VERSION
SERVER_URI=JIRA_SERVER_URI
CUSTOM_QUERY=JIRA_CUSTOM_QUERY
PROJECT_ID=JIRA_PROJECT
REGION="us-central1"

curl -X POST \
-H "Authorization: Bearer $(gcloud auth print-access-token)" \
-H "Content-Type: application/json" \
https://\${ENDPOINT}/v1beta1/projects/\${PROJECT_ID}/locations/REGION>/ragCorpora/\${RAG_CORPUS_ID}/ragFiles:import \
-d '{
  "import_rag_files_config": {
    "jiraSource": {
      "jiraQueries": [{
        "projects": ["'"${PROJECT_ID}"'"],
        "customQueries": ["'"${CUSTOM_QUERY}"'"],
        "email": "'"${EMAIL}"'",
        "serverUri": "'"${SERVER_URI}"'",
        "apiKeyConfig": {
          "apiKeySecretVersion": "'"${API_KEY_SECRET_VERSION}"'"
        }
      }]
    }
  }
}'

Python

# Jira Example
jira_query = rag.JiraQuery(
    email="xxx@yyy.com",
    jira_projects=["project1", "project2"],
    custom_queries=["query1", "query2"],
    api_key="api_key",
    server_uri="server.atlassian.net"
)
source = rag.JiraSource(
    queries=[jira_query],
)

response = rag.import_files(
    corpus_name="projects/my-project/locations/REGION/ragCorpora/my-corpus-1",
    source=source,
    chunk_size=512,
    chunk_overlap=100,
)

Import files and folders from a SharePoint site using the SharePoint data connector.

Steps to import files from SharePoint

1. Create a RAG corpus

Follow the instructions at Create a RAG corpus.

2. Create and configure an Azure app

  1. Go to App Registrations in the Azure portal to create a new app registration.
    • Provide a name for the application.
    • Choose the option, Accounts in this organizational directory only.
    • Verify that the redirect URIs are empty.
  2. From the app's Overview page, copy the Application (client) ID (your CLIENT_ID) and the Directory (tenant) ID (your TENANT_ID).
  3. On the API permissions page, add the following permissions and grant admin consent for them:
    • SharePoint: Sites.Read.All
    • Microsoft Graph: Files.Read.All and Sites.Read.All (Note: The original doc mentioned Browser SiteLists.Read.All, but Sites.Read.All is the current equivalent).
  4. On the Certificates & secrets page, create a new client secret and copy its value.

3. Store the client secret in Secret Manager

  1. Add the client secret value as a new secret in Secret Manager.
  2. Grant the Secret Manager Secret Accessor role to your project's Vertex AI RAG Data Service Agent service account.

4. Import files from SharePoint

You must specify a drive name or drive ID from your SharePoint site. You can optionally specify a folder path or folder ID; if you don't, all folders and files on the drive are imported. Use _{YOUR_ORG_ID}.sharepoint.com_ as the SHAREPOINT_SITE_NAME.

curl

CLIENT_ID=SHAREPOINT_CLIENT_ID
API_KEY_SECRET_VERSION=SHAREPOINT_API_KEY_SECRET_VERSION
TENANT_ID=SHAREPOINT_TENANT_ID
SITE_NAME=SHAREPOINT_SITE_NAME
FOLDER_PATH=SHAREPOINT_FOLDER_PATH
DRIVE_NAME=SHAREPOINT_DRIVE_NAME

curl -X POST \
-H "Authorization: Bearer $(gcloud auth print-access-token)" \
-H "Content-Type: application/json" \
https://\${ENDPOINT}/v1beta1/projects/\${PROJECT_ID}/locations/REGION>/ragCorpora/\${RAG_CORPUS_ID}/ragFiles:import \
-d '{
  "import_rag_files_config": {
    "sharePointSources": {
      "sharePointSource": [{
        "clientId": "'"${CLIENT_ID}"'",
        "apiKeyConfig": {
          "apiKeySecretVersion": "'"${API_KEY_SECRET_VERSION}"'"
        },
        "tenantId": "'"${TENANT_ID}"'",
        "sharepointSiteName": "'"${SITE_NAME}"'",
        "sharepointFolderPath": "'"${FOLDER_PATH}"'",
        "driveName": "'"${DRIVE_NAME}"'"
      }]
    }
  }
}'

Python

from vertexai.preview import rag
from vertexai.preview.rag.utils import resources

CLIENT_ID="SHAREPOINT_CLIENT_ID"
API_KEY_SECRET_VERSION="SHAREPOINT_API_KEY_SECRET_VERSION"
TENANT_ID="SHAREPOINT_TENANT_ID"
SITE_NAME="SHAREPOINT_SITE_NAME"
FOLDER_PATH="SHAREPOINT_FOLDER_PATH"
DRIVE_NAME="SHAREPOINT_DRIVE_NAME"

# SharePoint Example.
source = resources.SharePointSources(
    share_point_sources=[
        resources.SharePointSource(
            client_id=CLIENT_ID,
            client_secret=API_KEY_SECRET_VERSION,
            tenant_id=TENANT_ID,
            sharepoint_site_name=SITE_NAME,
            folder_path=FOLDER_PATH,
            drive_id=DRIVE_ID,
        )
    ]
)

response = rag.import_files(
    corpus_name="projects/my-project/locations/REGION/ragCorpora/my-corpus-1",
    source=source,
    chunk_size=512,
    chunk_overlap=100,
)
