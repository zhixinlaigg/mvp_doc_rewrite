    Use data ingestion with Vertex AI RAG Engine¶

    This page explains how to perform data ingestion into Vertex AI RAG Engine from supported data sources like Cloud Storage, Google Drive, Slack, Jira, and SharePoint. Data ingestion is handled by the ImportRagFiles API, which provides data connectors to these sources.

    Preview

    The RAG Engine API is in Preview.

    The VPC-SC security control is supported by RAG Engine. Data residency, CMEK, and AXT security controls aren't supported.

    Supported data sources¶

    RAG Engine can ingest unstructured data from several sources. The following table provides a summary of the supported data sources.

    Data Source Description Use Case Key Requirements
    Local file upload A synchronous call to upload a single file up to 25 MB. Quick, one-off file uploads for testing or small-scale use. upload_file API call.
    Cloud Storage Import one or more files from a Cloud Storage bucket. Batch ingestion of files stored in Google Cloud. Service account with Storage Object Viewer role.
    Google Drive Import a directory from Google Drive. Ingesting documents, spreadsheets, and other files from a shared drive. Service account with Viewer permission on the Drive folder.
    Slack Import messages and files from Slack channels using a data connector. Building a knowledge base from team communications. Slack app with correct permissions and an API token.
    Jira Import issues and documents from Jira projects using a data connector. Indexing project documentation, tasks, and discussions. Jira API token and user credentials.
    SharePoint Import files and folders from a SharePoint site using a data connector. Ingesting documents from an enterprise document management system. Azure app registration with SharePoint API permissions.

    For more information on file size limits and supported document types, see Supported document types.

    Before you begin¶

    Expand to see all prerequisites

    Create a RAG corpus

    All data must be imported into a RAG corpus. A corpus is a collection of RagFiles that structures and optimizes your data for retrieval. To create one, see Create a RAG corpus.

    Grant permissions to the service account

    To import files, the Vertex AI RAG Data Service Agent requires permissions to access the data source.

    1. In the Google Cloud console, go to the IAM page.

      Go to IAM

    2. Select the Include Google-provided role grants checkbox.

    3. Search for the Vertex AI RAG Data Service Agent service account. The service account is in the format service-PROJECT_NUMBER@gcp-sa-rag-data-service.iam.gserviceaccount.com.
    4. Grant this service account the necessary permissions for your chosen data source. For example:
      • Cloud Storage: Grant the Storage Object Viewer role on the bucket.
      • Google Drive: Share the Google Drive folder or file with the service account email address and grant it Viewer permission.
      • Secret Manager: If you are using data connectors for Slack, Jira, or SharePoint, grant the Secret Manager Secret Accessor role to the service account so it can access the API tokens stored in Secret Manager.

    Import files from a data source¶

    After you have completed the prerequisites, you can import files from your chosen data source. Select one of the following tabs for detailed instructions.

    To import files from Cloud Storage or Google Drive, use the import_rag_files method and specify the Google Cloud Storage URI or Google Drive path in your request. For a complete code sample, see the ImportRagFiles API template.

    The system automatically checks your file's path, filename, and version_id. The version_id is a hash calculated from the file's content, which prevents the same unchanged file from being re-indexed. If a file with the same name and path is updated, it will be re-indexed.

    Step 1: Get your Slack channel ID and create an app
    1. Get your CHANNEL_ID from the Slack channel you want to import.
    2. Go to the Slack API page and create a new app.
    Step 2: Configure app permissions
    1. From the Slack UI, in the Add features and functionality section, click Permissions.
    2. In the Bot Token Scopes section, add the following permissions:
      • channels:history
      • groups:history
      • im:history
      • mpim:history
    3. Click Install to Workspace to install the app into your Slack workspace.
    Step 3: Get your API token and store it in Secret Manager
    1. After installing the app, copy the Bot User OAuth Token.
    2. Add this token as a new secret in Secret Manager.
    Step 4: Import files from Slack

    Use the following code samples to import files from your Slack channel. Replace the placeholder variables with your project and Slack information.

    curl

    API_KEY_SECRET_VERSION=SLACK_API_KEY_SECRET_VERSION
CHANNEL_ID=SLACK_CHANNEL_ID
PROJECT_ID=us-central1

curl -X POST \
-H "Authorization: Bearer $(gcloud auth print-access-token)" \
-H "Content-Type: application/json" \
https://us-central1-aiplatform.googleapis.com/v1beta1/projects/${ PROJECT_ID }/locations/us-central1/ragCorpora/${ RAG_CORPUS_ID }/ragFiles:import \
-d '{
  "import_rag_files_config": {
    "slack_source": {
      "channels": [
        {
          "apiKeyConfig": {
            "apiKeySecretVersion": "'"${ API_KEY_SECRET_VERSION }"'"
          },
          "channels": [
            {
              "channel_id": "'"${ CHANNEL_ID }"'"
            }
          ]
        }
      ]
    }
  }
}'

    If you encounter issues with code snippets or setup, refer to the Troubleshooting Guide.

    Understand import results¶

    This section explains how to interpret the results of an import job, including how data is deduplicated and how to track failures.

    Data deduplication¶

    If the same file is imported multiple times with no changes, the file is skipped to avoid redundant processing. The response.skipped_rag_files_count in the API response indicates the number of files that were skipped.

    A file is skipped if all of the following conditions are met: * The file has been imported previously. * The file content has not changed. * The chunking configuration for the file has not changed.

    Import failures¶

    To understand why some files might fail to import, you can inspect the API response or configure a data sink to log detailed results.

    • Response metadata: The response.metadata object contains high-level information about the import job, including request and response times.

    • Import result sink: For detailed logging, you can specify an import_result_sink in your import request. This is an optional parameter that designates a destination for detailed logs of both successful and failed file imports. The sink must be a Cloud Storage path or a BigQuery table.

      • Cloud Storage sink: Provide a path in the format gs://my-bucket/my/object.ndjson. The object must not exist before the import. After the job completes, this object will contain one JSON object per line, detailing the operation ID, timestamp, filename, status, and file ID for each file.
      • BigQuery sink: Provide a table reference in the format bq://my-project.my-dataset.my-table. If the table does not exist, it will be created. If it exists, its schema will be verified.
