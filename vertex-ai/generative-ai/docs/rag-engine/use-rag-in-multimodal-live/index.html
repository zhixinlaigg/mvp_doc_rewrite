Use Vertex AI RAG Engine in Gemini Live API¶

Preview

Some of the RAG features are Preview offerings, subject to the "Pre-GA Offerings Terms" of the Google Cloud Service Specific Terms. Pre-GA products and features may have limited support, and changes to Pre-GA products and features may not be compatible with other Pre-GA versions. For more information, see the launch stage descriptions. Further, by using the Gemini API on Vertex AI, you agree to the Generative AI Preview terms and conditions (Preview Terms).

Retrieval-augmented generation (RAG) is a technique that retrieves and provides relevant information to large language models (LLMs) to generate verifiable and grounded responses. You can use the Vertex AI RAG Engine with the Gemini Live API in two primary ways:

  • Information Retrieval: Connect to a standard RAG corpus to ground model responses with your specific data.
  • Context Storage: Use a special MemoryCorpus to store conversation history, enabling the model to recall past interactions within or across sessions.

The VPC-SC security controls and CMEK are supported by Vertex AI RAG Engine. Data residency and AXT security controls aren't supported.

This page shows you how to use Vertex AI RAG Engine with the multimodal Live API for both information retrieval and context storage.

RAG Engine use cases with the Live API¶

The following table compares the two methods for using RAG Engine with the Gemini Live API.

Feature Standard RAG Corpus (Information Retrieval) MemoryCorpus (Context Storage)
Primary Use Case Grounding model responses with factual data from your documents. Storing and retrieving conversation history to maintain context across turns or sessions.
Corpus Type Standard RagCorpus. MemoryCorpus, a specialized type of RagCorpus.
Key Configuration Specify the rag_corpus resource in the retrieval tool. Specify the rag_corpus resource and set store_context=True in the retrieval tool.

Before you begin¶

Before you begin
Concepts
  • Retrieval-Augmented Generation (RAG): A technique that enhances LLM responses by retrieving relevant information from an external knowledge base.
  • RAG Corpus: A collection of documents that you provide to the RAG Engine for indexing and retrieval.
  • Gemini Live API: A streaming API designed for real-time, multimodal conversational AI applications.
  • Websocket: A communication protocol that enables persistent, two-way communication between a client and a server.
  • MemoryCorpus: A specialized RAG corpus designed to store and index conversation history for context recall.

Prerequisites

The following prerequisites must be completed before you can use Vertex AI RAG Engine with the multimodal Live API:

  1. Enable the RAG API in Vertex AI.
  2. Create a RAG Corpus.
  3. Import files to the RAG Corpus.

Retrieve information from a RAG corpus¶

This section shows how to connect to a standard RAG corpus to retrieve information and ground model responses in real-time.

The following diagram shows the workflow for retrieving information from a RAG corpus.

    click A "#step-1-configure-the-rag-tool"
    click B "#step-2-connect-and-stream-responses"
Steps

Step 1: Configure the RAG tool

To use your RAG corpus, specify it as a retrieval tool in your Live API request. This configuration points the Gemini model to your data source for grounding its responses.

Replace the following variables in the code sample: * YOUR_PROJECT_ID: The ID of your Google Cloud project. * YOUR_CORPUS_ID: The ID of your RAG corpus. * YOUR_LOCATION: The region where your resources are located (for example, us-central1).

PROJECT_ID = "YOUR_PROJECT_ID"
RAG_CORPUS_ID = "YOUR_CORPUS_ID"
LOCATION = "YOUR_LOCATION"

TOOLS = {
  "retrieval": {
    "vertex_rag_store": {
    "rag_resources": {
          "rag_corpus": "projects/${PROJECT_ID}/locations/${LOCATION}/ragCorpora/${RAG_CORPUS_ID}"
        }
     }
  }
}

Troubleshooting

If you encounter issues with code snippets or setup, refer to the Troubleshooting Guide.

Step 2: Connect and stream responses

To enable real-time communication, you must use a Websocket. You can connect using the Python API for low-level control or the Python SDK for a more abstracted experience.

This method uses the websockets library to interact directly with the API endpoint.

CONFIG = {"response_modalities": ["TEXT"], "speech_config": { "language_code": "en-US" }}
headers = {
  "Content-Type": "application/json",
  "Authorization": f"Bearer {bearer_token[0]}",
}
HOST= "${LOCATION}-aiplatform.googleapis.com"
SERVICE_URL = f"wss://{HOST}/ws/google.cloud.aiplatform.v1beta1.LlmBidiService/BidiGenerateContent"
MODEL="gemini-2.0-flash-exp"

# Connect to the server
async with connect(SERVICE_URL, additional_headers=headers) as ws:
  # Setup the session
  await ws.send(
json.dumps(
          {
              "setup": {
                  "model": MODEL,
                  "generation_config": CONFIG,
                  # Setup RAG as a retrieval tool
                  "tools": TOOLS,
              }
          }
      )
  )

  # Receive setup response
  raw_response = await ws.recv(decode=False)
  setup_response = json.loads(raw_response.decode("ascii"))

  # Send text message
  text_input = "What are popular LLMs?"
  display(Markdown(f"**Input:** {text_input}"))

  msg = {
      "client_content": {
          "turns": [{"role": "user", "parts": [{"text": text_input}]}],
          "turn_complete": True,
      }
  }

  await ws.send(json.dumps(msg))

  responses = []

  # Receive chunks of server response
  async for raw_response in ws:
      response = json.loads(raw_response.decode())
      server_content = response.pop("serverContent", None)
      if server_content is None:
          break

      model_turn = server_content.pop("modelTurn", None)
      if model_turn is not None:
          parts = model_turn.pop("parts", None)
          if parts is not None:
              display(Markdown(f"**parts >** {parts}"))
              responses.append(parts[0]["text"])

      # End of turn
      turn_complete = server_content.pop("turnComplete", None)
      if turn_complete:
          grounding_metadata = server_content.pop("groundingMetadata", None)
          if grounding_metadata is not None:
            grounding_chunks = grounding_metadata.pop("groundingChunks", None)
            if grounding_chunks is not None:
              for chunk in grounding_chunks:
                display(Markdown(f"**grounding_chunk >** {chunk}"))
          break

  # Print the server response
  display(Markdown(f"**Response >** {''.join(responses)}"))

This method uses the Vertex AI SDK for Python, which provides a higher-level abstraction. To learn how to install the SDK, see Install the Vertex AI SDK for Python.

from google import genai
from google.genai import types
from google.genai.types import (Content, LiveConnectConfig, HttpOptions, Modality, Part,)
from IPython import display

MODEL="gemini-2.0-flash-exp"

client = genai.Client(
  vertexai=True,
  project=PROJECT_ID,
  location=LOCATION
)

async with client.aio.live.connect(
  model=MODEL,
  config=LiveConnectConfig(response_modalities=[Modality.TEXT],
                            tools=TOOLS),
) as session:
  text_input = "\'What are core LLM techniques?\'"
  print("> ", text_input, "\n")
  await session.send_client_content(
      turns=Content(role="user", parts=[Part(text=text_input)])
  )

  async for message in session.receive():
      if message.text:
          display.display(display.Markdown(message.text))
          continue

Use a RAG corpus as a context store¶

You can use a MemoryCorpus to store session context, allowing the Live API to form and retrieve past contexts related to your conversation. This enriches the current context for model generation and lets you share context across different Live API sessions. Vertex AI RAG Engine supports storing and indexing text and audio speech from session contexts.

The following diagram shows the workflow for using a MemoryCorpus as a context store.

flowchart TD
    A["Step 1: Create a MemoryCorpus"] --> B["Step 2: Specify the memory corpus to store context"]

    click A "#step-1-create-a-memorycorpus"

Steps

Step 1: Create a MemoryCorpus

To store and index conversation history, you must create a RAG corpus of the MemoryCorpus type. You must also specify an LLM parser in your configuration, which is used to parse session contexts from the Live API to build memory for indexing.

Replace the following variables in the code sample: * YOUR_EMBEDDING_MODEL: The embedding model to use, such as publishers/google/models/text-embedding-005. * YOUR_MEMORY_CORPUS_DISPLAY_NAME: A display name for your memory corpus. * YOUR_LLM_PARSER_MODEL_NAME: The LLM parser model, such as projects/{project_id}/locations/{location}/publishers/google/models/gemini-1.5-pro-preview-0514.

# Currently supports Google first-party embedding models
EMBEDDING_MODEL = YOUR_EMBEDDING_MODEL
MEMORY_CORPUS_DISPLAY_NAME = YOUR_MEMORY_CORPUS_DISPLAY_NAME
LLM_PARSER_MODEL_NAME = YOUR_LLM_PARSER_MODEL_NAME

memory_corpus = rag.create_corpus(
   display_name=MEMORY_CORPUS_DISPLAY_NAME,
   corpus_type_config=rag.RagCorpusTypeConfig(
       corpus_type_config=rag.MemoryCorpus(
           llm_parser=rag.LlmParserConfig(
               model_name=LLM_PARSER_MODEL_NAME,
           )
       )
   ),
   backend_config=rag.RagVectorDbConfig(
       rag_embedding_model_config=rag.RagEmbeddingModelConfig(
           vertex_prediction_endpoint=rag.VertexPredictionEndpoint(
               publisher_model=EMBEDDING_MODEL
           )
       )
   ),
)

Troubleshooting

If you encounter issues with code snippets or setup, refer to the Troubleshooting Guide.

Step 2: Specify the memory corpus to store context

When using your memory corpus with the Live API, specify it as a retrieval tool and set store_context to true. This setting allows the Live API to automatically store the session contexts in your MemoryCorpus.

Replace the following variables in the code sample: * YOUR_PROJECT_ID: The ID of your Google Cloud project. * YOUR_LOCATION: The region where your resources are located. * YOUR_TEXT_INPUT: The initial text input for the conversation. * YOUR_MODEL_NAME: The model to use, such as gemini-2.0-flash-exp.

from google import genai
from google.genai import types
from google.genai.types import (Content, LiveConnectConfig, HttpOptions, Modality, Part)
from IPython import display

PROJECT_ID=YOUR_PROJECT_ID
LOCATION=YOUR_LOCATION
TEXT_INPUT=YOUR_TEXT_INPUT
MODEL_NAME=YOUR_MODEL_NAME

client = genai.Client(
   vertexai=True,
   project=PROJECT_ID,
   location=LOCATION,
)

memory_store=types.VertexRagStore(
   rag_resources=[
       types.VertexRagStoreRagResource(
           rag_corpus=memory_corpus.name
       )
   ],
   store_context=True
)

async with client.aio.live.connect(
   model=MODEL_NAME,
   config=LiveConnectConfig(response_modalities=[Modality.TEXT],
                            tools=[types.Tool(
                                retrieval=types.Retrieval(
                                    vertex_rag_store=memory_store))]),
) as session:
   text_input=TEXT_INPUT
   await session.send_client_content(
       turns=Content(role="user", parts=[Part(text=text_input)])
   )

   async for message in session.receive():
       if message.text:
           display.display(display.Markdown(message.text))
           continue
