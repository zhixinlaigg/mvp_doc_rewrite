    Use Vertex AI Feature Store in Vertex AI RAG Engine¶

    Preview

    Some of the RAG features are Preview offerings, subject to the "Pre-GA Offerings Terms" of the Google Cloud Service Specific Terms. Pre-GA products and features may have limited support, and changes to Pre-GA products and features may not be compatible with other Pre-GA versions. For more information, see the launch stage descriptions. Further, by using the Gemini API on Vertex AI, you agree to the Generative AI Preview terms and conditions (Preview Terms).

    The VPC-SC security controls and CMEK are supported by Vertex AI RAG Engine. Data residency and AXT security controls aren't supported.

    This page shows you how to set up Vertex AI Feature Store as the vector database to use with RAG Engine. By integrating Vertex AI Feature Store, RAG Engine can handle large data volumes with low latency, which helps to improve the performance and scalability of your RAG applications.

    To see a complete example, you can run the "Vertex AI RAG Engine with Vertex AI Feature Store" Jupyter notebook.

    Open in Colab Open in Colab Enterprise Open in Vertex AI Workbench View on GitHub

    Before you begin¶

    Concepts
    • Vertex AI Feature Store: A managed cloud-native service that simplifies machine learning (ML) feature management and online serving.
    • FeatureOnlineStore: A Feature Store resource that serves feature data with low latency for online applications.
    • FeatureView: A resource that connects a data source, like a BigQuery table, to a FeatureOnlineStore for serving.
    • RAG Corpus: A collection of documents or data that the RAG system uses to find relevant information for answering queries.
    • Embeddings: Numerical vector representations of text or other data, used to measure semantic similarity.

    Set up a Vertex AI Feature Store¶

    Vertex AI Feature Store lets you manage feature data within a BigQuery table or view, enabling low-latency online feature serving. For FeatureOnlineStore instances created with optimized online serving, you can use vector similarity search to retrieve approximate nearest neighbors.

    The following sections show you how to set up a Vertex AI Feature Store instance for your RAG application.

    Step 1: Create a BigQuery table schema

    Use the Google Cloud console or bq command-line tool to create a BigQuery table. It must contain the following fields to serve as the data source.

    Field name Data type Status
    corpus_id String Required
    file_id String Required
    chunk_id String Required
    chunk_data_type String Nullable
    chunk_data String Nullable
    file_original_uri String Nullable
    embeddings Float Repeated

    The following code sample demonstrates how to define your BigQuery table schema using SQL.

    CREATE TABLE `PROJECT_ID.input_us_central1.rag_source_new` (
  `corpus_id` STRING NOT NULL,
  `file_id` STRING NOT NULL,
  `chunk_id` STRING NOT NULL,
  `chunk_data_type` STRING,
  `chunk_data` STRING,
  `embeddings` ARRAY<FLOAT64>,
  `file_original_uri` STRING
);
    Step 2: Provision a FeatureOnlineStore instance

    To enable online serving of features, use the Vertex AI Feature Store CreateFeatureOnlineStore API to set up a FeatureOnlineStore instance. If you are provisioning a FeatureOnlineStore for the first time, the operation might take approximately five minutes to complete.

    Troubleshooting

    If you encounter issues with code snippets or setup, refer to the Troubleshooting Guide.

    To create an online store instance, send a POST request by using the featureOnlineStores.create method.

    Before you begin

    Before using any of the request data, make the following replacements:

    • LOCATION_ID: Region where you want to create the FeatureOnlineStore instance, such as us-central1.
    • PROJECT_ID: Your project ID.
    • FEATUREONLINESTORE_NAME: The name of the new FeatureOnlineStore instance.

    Request

    HTTP method and URL:

    POST https://LOCATION_ID-aiplatform.googleapis.com/v1/projects/PROJECT_ID/locations/LOCATION_ID/featureOnlineStores?feature_online_store_id=FEATUREONLINESTORE_NAME

    Request JSON body:

    {
  "optimized": {}
}

    from google.cloud import aiplatform
from vertexai.resources.preview import feature_store


def create_feature_view_from_rag_source(
    project: str,
    location: str,
    existing_feature_online_store_id: str,
    feature_view_id: str,
    bq_table_uri: str,
):
    aiplatform.init(project=project, location=location)
    fos = feature_store.FeatureOnlineStore(existing_feature_online_store_id)
    fv = fos.create_feature_view(
        name=feature_view_id,
        source=feature_store.utils.FeatureViewVertexRagSource(uri=bq_table_uri),
    )
    return fv

    After the Vertex AI Feature Store instance is set up, the following sections show you how to use it as the vector database for your RAG application.

    Step 4: Create a RAG corpus

    To create the RAG corpus, you must provide the FEATURE_VIEW_RESOURCE_NAME. The RAG corpus is created and automatically associated with the Vertex AI Feature Store instance. RAG APIs use the generated rag_corpus_id to handle data uploads and retrieve relevant contexts.

    • FEATUREVIEW_NAME: The name of the feature view where you want to manually start the data sync.
