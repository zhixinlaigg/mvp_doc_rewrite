Batch prediction¶

To see an example of using batch predictions, run the "Intro to Batch Predictions with the Gemini API" Jupyter notebook in one of the following environments:

Open in Colab Open in Colab Enterprise Open in Vertex AI Workbench View on GitHub

Batch prediction is a valuable technique for applying machine learning models to large datasets efficiently. Instead of processing individual data points, you can submit a batch of data to Gemini for prediction, saving time and computational resources. Unlike online prediction, where you are limited to one input prompt at a time, you can send a large number of multimodal prompts in a single batch request. Your responses then asynchronously populate in your specified BigQuery or Cloud Storage output location.

Batch requests for Gemini models are discounted 50% from standard requests. To learn more, see the Pricing page.

Important: Batch predictions prioritize off-peak capacity and might take longer to process during busy periods. Turnaround time is not guaranteed.

Batch prediction use case¶

Consider an online bookstore with thousands of books in its database. Instead of generating descriptions individually for each book, which would be time-consuming, this store can use Gemini batch prediction to process all book information at once. This approach dramatically improves efficiency by reducing the overall processing time and minimizing the computational resources required.

Batch prediction can also improve consistency with automation. By processing all descriptions simultaneously, the model maintains a uniform tone and style across book descriptions, reinforcing brand identity. This bookstore can also integrate batch prediction into their workflow to automatically generate descriptions for new book entries, eliminating manual effort and ensuring their website remains up-to-date with minimal human intervention.

Gemini models that support batch predictions¶

The following base and tuned Gemini models support batch predictions:

  • Gemini 2.5 Pro
  • Gemini 2.5 Flash
  • Gemini 2.0 Flash
  • Gemini 2.0 Flash-Lite

Limitations¶

After submission, batch jobs are validated and queued for available capacity. Once a job starts running, it has a 24-hour execution limit. If it doesn't complete within that time, all completed requests will be exported, and you are only charged for requests that are completed. The maximum time that a batch job can spend in queue and running is 72 hours.

For quotas and limits on batch prediction jobs, see Generative AI on Vertex AI quotas and system limits.

Before you begin¶

Concepts
  • Batch prediction: A method for processing a large volume of prompts in a single request and receiving outputs asynchronously.
  • Online prediction: A method for processing a single prompt request and receiving a response in real-time (synchronously).
  • JSONL (JSON Lines): A text format where each line is a separate, valid JSON object, commonly used for streaming data or large datasets.
  • Cloud Storage: A scalable and durable object storage service for unstructured data like files, images, and videos.
  • BigQuery: A serverless, highly scalable data warehouse that allows for super-fast SQL queries using the processing power of Google's infrastructure.

Compare input and output sources¶

Batch requests for Gemini models accept input from either Cloud Storage or BigQuery. You can independently choose to output predictions to either a BigQuery table or a JSONL file in a Cloud Storage bucket. Use the following table to help decide which source is right for your use case.

Feature Cloud Storage BigQuery
Input Format JSON Lines (JSONL) file. A BigQuery table with a request column containing JSON data.
Best For Unstructured or file-based data, such as a collection of multimodal prompts with URIs pointing to images or videos. Structured data already residing in BigQuery, where prompts can be generated from existing table columns.
Data Location Input files must be located in the us-central1 region. The input BigQuery dataset must be in the same region as the Vertex AI batch prediction job.
Output Format JSON Lines (JSONL) file. A new BigQuery table.
Recommendation Recommended for jobs with a minimum of 25,000 requests to leverage parallel processing efficiently. Recommended for jobs with a minimum of 25,000 requests. Other columns in the source table are carried over to the output table.

Perform a batch prediction job¶

This section walks you through the process of creating and managing a batch prediction job. The overall workflow consists of three main steps: preparing your input data, submitting the batch prediction request, and retrieving the results once the job is complete.

Step 1: Prepare your inputs¶

Choose whether your input data is in Cloud Storage or BigQuery and prepare it according to the specified format.

Caution: Soft delete is enabled on Cloud Storage buckets by default, which retains content in a deleted state and can result in significant storage costs. We highly recommend you Disable soft delete to prevent unexpected charges.

  • File format: JSON Lines (JSONL).
  • Location: The input file must be in a Cloud Storage bucket located in us-central1.

  • Permissions: The service account running the job must have roles/storage.objectUser permissions on the bucket. To grant this role, use the following command:

    gcloud projects add-iam-policy-binding PROJECT_ID \
    --member="serviceAccount:SERVICE_ACCOUNT_ID@PROJECT_ID.iam.gserviceaccount.com" \
    --role="roles/storage.objectUser"
    Replace PROJECT_ID and SERVICE_ACCOUNT_ID with your project and service account details.

Example input (JSONL)

Each line in the file must be a valid JSON object representing a single request.

{"request":{"contents": [{"role": "user", "parts": [{"text": "What is the relation between the following video and image samples?"}, {"fileData": {"fileUri": "gs://cloud-samples-data/generative-ai/video/animals.mp4", "mimeType": "video/mp4"}}, {"fileData": {"fileUri": "gs://cloud-samples-data/generative-ai/image/cricket.jpeg", "mimeType": "image/jpeg"}}]}], "generationConfig": {"temperature": 0.9, "topP": 1, "maxOutputTokens": 256}}}
{"request":{"contents": [{"role": "user", "parts": [{"text": "Describe what is happening in this video."}, {"fileData": {"fileUri": "gs://cloud-samples-data/generative-ai/video/another_video.mov", "mimeType": "video/mov"}}]}]}}
  • Table schema: Your input table must contain a request column of type JSON or STRING. This column holds the GenerateContentRequest for the model.
  • Permissions: The service account must have the roles/bigquery.user role. To grant this role, use the following command: 
    gcloud projects add-iam-policy-binding PROJECT_ID \
    --member="serviceAccount:SERVICE_ACCOUNT_ID@PROJECT_ID.iam.gserviceaccount.com" \
    --role="roles/bigquery.user"
    Replace PROJECT_ID and SERVICE_ACCOUNT_ID with your project and service account details.
  • Additional columns: Your input table can have other columns, which will be ignored during prediction but included in the output table. The following data types are not supported for these additional columns: ARRAY, STRUCT, RANGE, DATETIME, and GEOGRAPHY.
  • Reserved column names: Do not use response or status as column names in your input table, as these are reserved for the output.

Example input (JSON in request column)

{
  "contents": [
    {
      "role": "user",
      "parts": [
        {
          "text": "Give me a recipe for banana bread."
        }
      ]
    }
  ],
  "system_instruction": {
    "parts": [
      {
        "text": "You are a chef."
      }
    ]
  }
}

Step 2: Request a batch prediction job¶

After preparing your inputs, submit a request to create a batch prediction job using either the REST API or the Python SDK.

Troubleshooting

If you encounter issues with code snippets or setup, refer to the Troubleshooting Guide.

Specify your Cloud Storage input file, model, and output location.

To create a batch prediction job, send a POST request to the projects.locations.batchPredictionJobs.create method.

HTTP method and URL: 

POST https://LOCATION-aiplatform.googleapis.com/v1/projects/PROJECT_ID/locations/LOCATION/batchPredictionJobs

Request JSON body: 

{
  "displayName": "my-cloud-storage-batch-prediction-job",
  "model": "publishers/google/models/gemini-2.5-flash",
  "inputConfig": {
    "instancesFormat": "jsonl",
    "gcsSource": {
      "uris" : ["gs://bucketname/path/to/file.jsonl"]
    }
  },
  "outputConfig": {
    "predictionsFormat": "jsonl",
    "gcsDestination": {
      "outputUriPrefix": "gs://mybucket/path/to/output"
    }
  }
}

View cURL and PowerShell examples

Before using any of the request data, make the following replacements:

  • LOCATION: A region that supports Gemini models.
  • PROJECT_ID: Your project ID.
  • MODEL_PATH: The publisher model name (e.g., publishers/google/models/gemini-2.0-flash-001) or a tuned model endpoint.
  • INPUT_URI: The Cloud Storage URI of your input file (e.g., gs://bucketname/path/to/file.jsonl).
  • OUTPUT_URI: The Cloud Storage URI for the output directory (e.g., gs://mybucket/path/to/output).

cURL

Save the request body in a file named request.json and execute the following command: 

curl -X POST \
     -H "Authorization: Bearer $(gcloud auth print-access-token)" \
     -H "Content-Type: application/json; charset=utf-8" \
     -d @request.json \
     "https://LOCATION-aiplatform.googleapis.com/v1/projects/PROJECT_ID/locations/LOCATION/batchPredictionJobs"

PowerShell

Save the request body in a file named request.json and execute the following command: 

$cred = gcloud auth print-access-token
$headers = @{ "Authorization" = "Bearer $cred" }

Invoke-WebRequest `
    -Method POST `
    -Headers $headers `
    -ContentType: "application/json; charset=utf-8" `
    -InFile request.json `
    -Uri "https://LOCATION-aiplatform.googleapis.com/v1/projects/PROJECT_ID/locations/LOCATION/batchPredictionJobs" | Select-Object -Expand Content

from google import genai
from google.genai.types import CreateBatchJobConfig, JobState, HttpOptions

client = genai.Client(http_options=HttpOptions(api_version="v1"))

# See the documentation: https://googleapis.github.io/python-genai/genai.html#genai.batches.Batches.create
job = client.batches.create(
    # To use a tuned model, set the model param to your tuned model using the following format:
    # model="projects/{PROJECT_ID}/locations/{LOCATION}/models/{MODEL_ID}
    model="gemini-2.0-flash-001",
    # Source link: https://storage.cloud.google.com/cloud-samples-data/batch/prompt_for_batch_gemini_predict.jsonl
    src="gs://cloud-samples-data/batch/prompt_for_batch_gemini_predict.jsonl",
    config=CreateBatchJobConfig(dest=output_uri),
)
print(f"Job name: {job.name}")
print(f"Job state: {job.state}")
# Example response:
# Job name: projects/%PROJECT_ID%/locations/us-central1/batchPredictionJobs/9876453210000000000
# Job state: JOB_STATE_PENDING

# See the documentation: https://googleapis.github.io/python-genai/genai.html#genai.types.BatchJob
completed_states = {
    JobState.JOB_STATE_SUCCEEDED,
    JobState.JOB_STATE_FAILED,
    JobState.JOB_STATE_CANCELLED,
    JobState.JOB_STATE_PAUSED,
}

while job.state not in completed_states:
    time.sleep(30)
    job = client.batches.get(name=job.name)
    print(f"Job state: {job.state}")
# Example response:
# Job state: JOB_STATE_PENDING
# Job state: JOB_STATE_RUNNING
# ...
# Job state: JOB_STATE_SUCCEEDED

curl \
  -X GET \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \

Step 3: Retrieve and interpret the output¶

When the job completes, the output is stored in the Cloud Storage bucket or BigQuery table you specified. For successful rows, model responses are in the response column. For failed rows, error details are in the status column.

The output is a JSONL file where each line corresponds to a request from the input file.

Example output (JSONL)

Note: Each entry in the response file is a single line and not pretty-printed like the following example.

{
  "status": "",
  "processed_time": "2024-11-01T18:13:16.826+00:00",
  "request": {
    "contents": [
      {
        "parts": [
          {
            "fileData": null,
            "text": "What is the relation between the following video and image samples?"
          },
          {
            "fileData": {
              "fileUri": "gs://cloud-samples-data/generative-ai/video/animals.mp4",
              "mimeType": "video/mp4"
            },
            "text": null
          },
          {
            "fileData": {
              "fileUri": "gs://cloud-samples-data/generative-ai/image/cricket.jpeg",
              "mimeType": "image/jpeg"
            },
            "text": null
          }
        ],
        "role": "user"
      }
    ]
  },
  "response": {
    "candidates": [
      {
        "avgLogprobs": -0.5782725546095107,
        "content": {

The output is a new BigQuery table containing the original columns from your input table, plus two new columns: response and status.

Example output row structure:

  • request column: Contains the original JSON request. 
    {"content":[{...}]}
  • response column: Contains the JSON response from the model for successful predictions. 
    {
  "candidates": [
    {
      "content": {
        "role": "model",
        "parts": [
          {
            "text": "In a medium bowl, whisk together the flour, baking soda, baking powder."
          }
        ]
      },
      "finishReason": "STOP",
      "safetyRatings": [
        {
          "category": "HARM_CATEGORY_SEXUALLY_EXPLICIT",
          "probability": "NEGLIGIBLE",
          "probabilityScore": 0.14057204,
          "severity": "HARM_SEVERITY_NEGLIGIBLE",
          "severityScore": 0.14270912
        }
      ]
    }
  ],
  "usageMetadata": {
    "promptTokenCount": 8,
    "candidatesTokenCount": 396,
    "totalTokenCount": 404
  }
}
  • status column: Contains error details if the prediction for that row failed. This column is empty for successful rows.
