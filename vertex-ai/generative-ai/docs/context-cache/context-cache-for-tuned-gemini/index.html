Context Caching for Fine-tuned Gemini Models¶

You can use context caching for your fine-tuned Gemini models to improve performance and reduce costs for prompts that include large amounts of context. By caching frequently used context, you avoid re-sending large amounts of data with each request to your fine-tuned model.

While the management operations (Read, Update, Delete) for context caches are the same for both base and fine-tuned models, the creation and inference processes require specific adjustments. This guide details those differences.

This page shows you how to create and then use a context cache with a fine-tuned Gemini model.

The following diagram shows the workflow for using context caching with a fine-tuned Gemini model.

Key differences from base models¶

Using context caching with a fine-tuned model is similar to using it with a base model, but with two key differences: the model identifier used for cache creation and the endpoint used for sending inference requests.

Feature Base Model Fine-tuned Model
Model Identifier (for creation) projects/{...}/publishers/google/models/{MODEL} projects/{...}/locations/{LOCATION}/models/{MODEL}@{VERSION}
Request Endpoint (for usage) .../publishers/google/models/{MODEL}:generateContent .../endpoints/{ENDPOINT_ID}:generateContent

Before you begin¶

Prerequisites and Concepts

Concepts

Concepts

Context Caching: A feature that stores parts of a prompt context to reduce latency and cost on subsequent requests. Fine-tuning: The process of adapting a pre-trained model to a specific task by training it on a smaller, domain-specific dataset. Model Endpoint: A deployable and scalable entry point for a machine learning model that serves online predictions.

Supported models

Context caching is supported for models fine-tuned from the following base model:

  • gemini-1.0-pro-002

Prerequisites

You need a deployed fine-tuned Gemini model based on a supported base model. For details on how to fine-tune a Gemini model, see Fine-tune a Gemini model. To get the endpoint for your deployed tuned model, see Deploy a tuned model.

Make sure that you have the following information:

  • The ID and the version of the tuned Gemini model.
  • The endpoint resource name for the deployed fine-tuned model.
Step 1: Create a context cache for a fine-tuned model

The procedure for creating a context cache for a fine-tuned model largely follows the steps outlined in Create a context cache. The key difference is that instead of using a base model identifier, you must use your fine-tuned model identifier in the format projects/{PROJECT}/locations/{LOCATION}/models/{MODEL}@{VERSION}.

The following examples show how to create a context cache with a tuned Gemini model using the REST API.

Troubleshooting

If you encounter issues with code snippets or setup, refer to the Troubleshooting Guide.

You can use the Vertex AI API to send a POST request to create a context cache. The following example shows how to create a cache using a file stored in a Cloud Storage bucket.

Request

Before using any of the request data, make the following replacements:

  • PROJECT_ID: Your project ID.
  • LOCATION: The region to process the request. For a list of supported regions, see Available regions.
  • MODEL_ID: The fine-tuned Gemini model ID.
  • MODEL_VERSION: The fine-tuned Gemini model version.
  • CACHE_DISPLAY_NAME: A meaningful display name to help you identify the context cache.
  • MIME_TYPE: The MIME type of the content to cache.
  • CONTENT_TO_CACHE_URI: The Cloud Storage URI of the content to cache.

HTTP method and URL: 

POST https://LOCATION-aiplatform.googleapis.com/v1/projects/PROJECT_ID/locations/LOCATION/cachedContents

Request JSON body: 

{
  "model": "projects/PROJECT_ID/locations/LOCATION/models/MODEL_ID@MODEL_VERSION",
  "displayName": "CACHE_DISPLAY_NAME",
  "contents": [{
    "role": "user",
      "parts": [{
        "fileData": {
          "mimeType": "MIME_TYPE",
          "fileUri": "CONTENT_TO_CACHE_URI"
        }
      }]
  },
  {
    "role": "model",
      "parts": [{
        "text": "This is sample text to demonstrate explicit caching."
      }]
  }]
}

To send your request, choose one of the following options. The following commands assume that you have logged in to the gcloud CLI by running gcloud init or gcloud auth login.

Save the request body in a file named request.json, and execute the following command:

curl -X POST \
     -H "Authorization: Bearer $(gcloud auth print-access-token)" \
     -H "Content-Type: application/json; charset=utf-8" \
     -d @request.json \
     "https://LOCATION-aiplatform.googleapis.com/v1/projects/PROJECT_ID/locations/LOCATION/cachedContents"

Example curl command

LOCATION="us-central1"
MODEL_ID="model-id"
PROJECT_ID="test-project"
MODEL_VERSION=1
MIME_TYPE="video/mp4"
CACHED_CONTENT_URI="gs://path-to-bucket/video-file-name.mp4"

curl -X POST \
-H "Authorization: Bearer $(gcloud auth print-access-token)" \
-H "Content-Type: application/json" \
https://us-central1-aiplatform.googleapis.com/v1/projects/${PROJECT_ID}/locations/${LOCATION}/cachedContents -d \
'{
  "model":"projects/${PROJECT_ID}/locations/${LOCATION}/models/${MODEL_ID}@${MODEL_VERSION}",
  "contents": [
    {
      "role": "user",
      "parts": [
        {
          "fileData": {
            "mimeType": "${MIME_TYPE}",
            "fileUri": "${CACHED_CONTENT_URI}"
          }
        }
      ]
    }
  ]
}'

Save the request body in a file named request.json, and execute the following command:

$cred = gcloud auth print-access-token
$headers = @{ "Authorization" = "Bearer $cred" }

Invoke-WebRequest `
    -Method POST `
    -Headers $headers `
    -ContentType: "application/json; charset=utf-8" `
    -InFile request.json `
    -Uri "https://LOCATION-aiplatform.googleapis.com/v1/projects/PROJECT_ID/locations/LOCATION/cachedContents" | Select-Object -Expand Content

Response

You should receive a JSON response similar to the following:

{
  "name": "projects/PROJECT_NUMBER/locations/us-central1/cachedContents/CACHE_ID",
  "model": "projects/PROJECT_ID/locations/LOCATION/models/MODEL_ID@MODEL_VERSION",
  "createTime": "2024-06-04T01:11:50.808236Z",
  "updateTime": "2024-06-04T01:11:50.808236Z",
  "expireTime": "2024-06-04T02:11:50.794542Z"
}
Step 2: Use the context cache with a fine-tuned model

The procedure for using a context cache with a fine-tuned model largely follows the steps outlined in Use a context cache. The key difference is that instead of sending the request to a base model endpoint, you must send it to the endpoint of your deployed fine-tuned model in the format projects/{PROJECT}/locations/{LOCATION}/endpoints/{ENDPOINT_ID}.

When you use a context cache, you can't specify the following properties:

  • GenerativeModel.system_instructions
  • GenerativeModel.tool_config
  • GenerativeModel.tools

The following examples show how to use a context cache with a tuned Gemini model using the REST API.

Troubleshooting

If you encounter issues with code snippets or setup, refer to the Troubleshooting Guide.

You can use the Vertex AI API to send a POST request to your deployed model's endpoint to get a response.

Request

Before using any of the request data, make the following replacements:

  • PROJECT_ID: Your project ID.
  • LOCATION: The region where the request to create the context cache was processed.
  • ENDPOINT_ID: The endpoint where the fine-tuned model is deployed.
  • PROMPT_TEXT: The text prompt to submit to the model.
  • CACHE_ID: The ID of the context cache you created.

HTTP method and URL: 

POST https://LOCATION-aiplatform.googleapis.com/v1/projects/PROJECT_ID/locations/LOCATION/endpoints/ENDPOINT_ID:generateContent

Request JSON body: 

{
  "cachedContent": "projects/PROJECT_NUMBER/locations/LOCATION/cachedContents/CACHE_ID",
  "contents": [
      {"role":"user","parts":[{"text":"PROMPT_TEXT"}]}
  ],
  "generationConfig": {
      "maxOutputTokens": 8192,
      "temperature": 1,
      "topP": 0.95
