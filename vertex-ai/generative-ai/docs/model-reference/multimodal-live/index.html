Live API reference¶

Preview

This feature is subject to the "Pre-GA Offerings Terms" in the General Service Terms section of the Service Specific Terms. Pre-GA features are available "as is" and might have limited support. For more information, see the launch stage descriptions.

The Live API enables low-latency, bidirectional voice and video interactions with Gemini. Using the Live API, you can provide end users with the experience of natural, human-like voice conversations and the ability to interrupt the model's responses using voice commands. The Live API can process text, audio, and video input, and it can provide text and audio output.

To try a tutorial that lets you use your voice and camera to talk to Gemini through the Live API, see the websocket-demo-app tutorial.

For more information about the Live API, see Live API.

Capabilities¶

Live API includes the following key capabilities:

  • Multimodality: The model can see, hear, and speak.
  • Low-latency real-time interaction: The model can provide fast responses.
  • Session memory: The model retains memory of all interactions within a single session, recalling previously heard or seen information.
  • Support for function calling, code execution, and Search as a Tool: You can integrate the model with external services and data sources.

Supported models¶

  • Gemini 2.5 Flash with Live API native audio (Preview)
  • Gemini 2.0 Flash with Live API (Preview)
  • Gemini 2.5 Flash

Before you begin¶

Concepts
  • WebSocket: A communication protocol that provides full-duplex communication channels over a single, long-lived TCP connection, enabling real-time data exchange.
  • Stateful API: An API that remembers past interactions and context from the same session to inform current and future responses.
  • Session: A persistent connection between a client and the Gemini server over a WebSocket, during which conversational context is maintained.
  • Function Calling: A feature that allows the model to invoke external tools or APIs to retrieve real-time information or perform actions.
  • VAD (Voice Activity Detection): A technology used to detect the presence or absence of human speech in an audio stream, enabling features like automatic turn-taking.

Choose an integration path¶

The Live API is designed for server-to-server communication. For web and mobile app development, we recommend using the integration from our partners at Daily.

Integration Path Best for Key Characteristics
Server-to-Server (Direct API) Backend applications where you manage the infrastructure and authentication. Full control over the API connection, security, and data flow. Requires secure handling of authentication keys on your server.
Daily.co Partner Integration Web and mobile applications that require a streamlined, client-side solution. Provides SDKs and infrastructure to simplify connecting end-user clients to the Live API, handling complexities like audio/video streams and session management.

Integration guide¶

This section describes how to integrate with the Live API using a WebSocket connection.

    D -- Yes --> C;
    D -- No --> E[End Session];

Session lifecycle¶

A WebSocket connection establishes a session between your client and the Gemini server. A session is stateful, meaning the model retains the context of the conversation for its duration.

  1. Establish Connection: Your client initiates a WebSocket connection to the Live API endpoint.
  2. Configure Session: Immediately after connecting, you must send a configuration message (BidiGenerateContentSetup). This message defines the model, generation parameters, system instructions, and any tools for function calling. The server confirms the setup is complete with a BidiGenerateContentSetupComplete message.
  3. Exchange Messages: Once the session is configured, your client and the server can exchange messages to send content (text, audio, video) and receive responses.
  4. End Session: The session ends when the WebSocket connection is closed.

Sending and receiving messages¶

Messages are JSON-formatted objects exchanged over the WebSocket connection.

To send a message, your client must send a JSON object with exactly one of the following fields.

Message Description
BidiGenerateContentSetup Session configuration, which must be sent in the first message.
BidiGenerateContentClientContent Incremental content update for the current conversation turn.
BidiGenerateContentRealtimeInput Real-time audio or video input.
BidiGenerateContentToolResponse The result of a function call requested by the model.

To receive messages, listen for the WebSocket message event and parse the result. Server messages will have exactly one of the following fields.

Message Description
BidiGenerateContentSetupComplete Confirms that the session setup is complete.
BidiGenerateContentServerContent Content generated by the model in response to a client message.
BidiGenerateContentToolCall A request for the client to execute a function call.
BidiGenerateContentToolCallCancellation Sent when a function call is canceled due to user interruption.
UsageMetadata A report of the token usage for the session.
GoAway A signal that the connection will soon be terminated.
SessionResumptionUpdate A session checkpoint that can be used to resume a session.
BidiGenerateContentTranscription A transcription of the user's or model's speech.

Key features in-depth¶

Incremental content updates¶

Use incremental updates (BidiGenerateContentClientContent) to send text input, establish session context, or restore session history. For short contexts, you can send turn-by-turn interactions. For longer contexts, it is recommended to provide a single summary message to conserve the context window for subsequent interactions.

Note that BidiGenerateContentClientContent should not be used to provide a response to function calls issued by the model. Use BidiGenerateContentToolResponse for that purpose.

Function calling¶

All functions must be declared at the start of the session by sending tool definitions as part of the BidiGenerateContentSetup message. The model can generate multiple function calls from a single prompt, and the client should respond with BidiGenerateContentToolResponse. To learn more, see Introduction to function calling.

To see an example of function calling, run the "Intro to Function Calling with the Gemini API" Jupyter notebook.

Open in Colab Open in Colab Enterprise View on GitHub

System instructions¶

You can provide system instructions in the initial BidiGenerateContentSetup message to control the model's output and specify the tone and sentiment of audio responses. System instructions remain in effect for the entire session.

Interruptions¶

Users can interrupt the model's output at any time. When Voice Activity Detection (VAD) detects an interruption, the ongoing generation is canceled. The server sends a BidiGenerateContentServerContent message to report the interruption and a BidiGenerateContentToolCallCancellation message if any pending function calls were discarded.

Voices¶

Send a text-to-text request (Python)¶

This section shows an example of how to use the Live API for text-to-text generation using the Generative AI SDK for Python (Python 3.9+).

Troubleshooting

If you encounter issues with code snippets or setup, refer to the Troubleshooting Guide.

# Replace the `GOOGLE_CLOUD_PROJECT` and `GOOGLE_CLOUD_LOCATION` values
# with appropriate values for your project.

from google import genai
from google.genai.types import (
    Content,
    LiveConnectConfig,
    Modality,
    Part,
)

client = genai.Client(
    vertexai=True,
    project=GOOGLE_CLOUD_PROJECT,
    location=GOOGLE_CLOUD_LOCATION
)
MODEL_ID = "gemini-live-2.5-flash"

async with client.aio.live.connect(
    model=MODEL_ID,
    config=LiveConnectConfig(response_modalities=[Modality.TEXT]),
) as session:
    text_input = "Hello? Gemini, are you there?"
    print("> ", text_input, "\n")
    await session.send_client_content(
        turns=Content(role="user", parts=[Part(text=text_input)])
    )

    response = []

    async for message in session.receive():
        if message.text:
            response.append(message.text)

    print("".join(response))
# Example output:
# >  Hello? Gemini, are you there?
# Yes, I'm here. What would you like to talk about?

Limitations¶

View limitations

Consider the following limitations of the Live API when you plan your project.

Client authentication

The Live API only provides server-to-server authentication and is not recommended for direct client use. Client input should be routed through an intermediate application server for secure authentication.

Maximum session duration

The default maximum length of a conversation session is 10 minutes. For more information, see Session length.

Voice activity detection (VAD)

By default, the model automatically performs VAD on a continuous audio input stream. This can be configured or disabled in the setup message. If disabled, the client is responsible for sending ActivityStart and ActivityEnd messages.

Additional limitations

  • Manual endpointing is not supported.
  • Audio inputs and audio outputs negatively impact the model's ability to use function calling.
  • Token count is not supported.

Rate limits

The following rate limits apply:

  • 5,000 concurrent sessions per API key
  • 4M tokens per minute

API reference: Messages and events¶

This section provides detailed definitions for the messages and events used in the Live API.

Message: BidiGenerateContentClientContent

Incremental update of the current conversation delivered from the client. All the content here is unconditionally appended to the conversation history and used as part of the prompt to the model to generate content. A message here will interrupt any current model generation.

Fields Description
turns[] Content Optional. The content appended to the current conversation with the model. For single-turn queries, this is a single instance. For multi-turn queries, this is a repeated field that contains conversation history and latest request.
turn_complete bool Optional. If true, indicates that the server content generation should start with the currently accumulated prompt. Otherwise, the server will await additional messages before starting generation.
Message: BidiGenerateContentRealtimeInput

User input that is sent in real time. This is different from ClientContentUpdate because it can be sent continuously without interrupting model generation and is always assumed to be the user's input.

Fields Description
media_chunks[] Blob Optional. Inlined bytes data for media input.
activity_start ActivityStart Optional. Marks the start of user activity. This can only be sent if automatic (server-side) activity detection is disabled.
activity_end ActivityEnd Optional. Marks the end of user activity. This can only be sent if automatic (server-side) activity detection is disabled.
Type: ActivityEnd

Marks the end of user activity. This type has no fields.

Type: ActivityStart

Marks the start of user activity. Only one of the fields in this message must be set at a time. This type has no fields.

Message: BidiGenerateContentServerContent

Incremental server update generated by the model in response to client messages.

Fields Description
turn_complete bool Output only. If true, indicates that the model is done generating.
interrupted bool Output only. If true, indicates that a client message has interrupted current model generation.
generation_complete bool Output only. If true, indicates that the model is done generating.
grounding_metadata GroundingMetadata Output only. Metadata specifies sources used to ground generated content.
input_transcription Transcription Optional. Input transcription.
output_transcription Transcription Optional. Output transcription.
model_turn Content Output only. The content that the model has generated.
Type: Transcription

Audio transcription message.

Fields Description
text string Optional. Transcription text.
finished bool Optional. If true, indicates the end of the transcription.
Message: BidiGenerateContentSetup

Message to be sent in the first client message only. Contains configuration for the duration of the session.

Fields Description
model string Required. The fully qualified name of the publisher model.
generation_config GenerationConfig Optional. Generation config.
system_instruction Content Optional. The user-provided system instructions for the model.
tools[] Tool Optional. A list of Tools the model may use.
session_resumption SessionResumptionConfig Optional. Configures session resumption.
context_window_compression ContextWindowCompressionConfig Optional. Configures context window compression.
realtime_input_config RealtimeInputConfig Optional. Configures the handling of real-time input.
input_audio_transcription AudioTranscriptionConfig Optional. The transcription of the input audio.
output_audio_transcription AudioTranscriptionConfig Optional. The transcription of the output audio.
Type: AudioTranscriptionConfig

The audio transcription configuration. This type has no fields.

Message: BidiGenerateContentSetupComplete

Sent in response to a BidiGenerateContentSetup message from the client. This type has no fields.

Message: BidiGenerateContentToolCall

Request for the client to execute the function_calls and return the responses.

Fields Description
function_calls[] FunctionCall Output only. The function call to be executed.
Message: BidiGenerateContentToolCallCancellation

Notification that a previously issued ToolCallMessage should be canceled.

Fields Description
ids[] string Output only. The IDs of the tool calls to be canceled.
Message: BidiGenerateContentToolResponse

Client-generated response to a ToolCall received from the server.

Fields Description
function_responses[] FunctionResponse Optional. The response to the function calls.
Type: RealtimeInputConfig

Configures the real-time input behavior in BidiGenerateContent.

Fields Description
automatic_activity_detection AutomaticActivityDetection Optional. If not set, automatic activity detection is enabled by default.
activity_handling ActivityHandling Optional. Defines what effect activity has.
turn_coverage TurnCoverage Optional. Defines which input is included in the user's turn.
Enum: ActivityHandling

The different ways of handling user activity.

Enums Description
ACTIVITY_HANDLING_UNSPECIFIED Default behavior is START_OF_ACTIVITY_INTERRUPTS.
START_OF_ACTIVITY_INTERRUPTS Start of activity will interrupt the model's response (barge-in).
NO_INTERRUPTION The model's response will not be interrupted.
Type: AutomaticActivityDetection

Configures automatic detection of activity.

Fields Description
start_of_speech_sensitivity StartSensitivity Optional. Determines how likely speech is to be detected.
end_of_speech_sensitivity EndSensitivity Optional. Determines how likely detected speech is ended.
prefix_padding_ms int32 Optional. The required duration of detected speech before start-of-speech is committed.
silence_duration_ms int32 Optional. The required duration of detected silence before end-of-speech is committed.
disabled bool Optional. If disabled, the client must send activity signals.
Enum: EndSensitivity

End of speech sensitivity.

Enums Description
END_SENSITIVITY_UNSPECIFIED Default is END_SENSITIVITY_LOW.
END_SENSITIVITY_HIGH Automatic detection ends speech more often.
END_SENSITIVITY_LOW Automatic detection ends speech less often.
Enum: StartSensitivity

Start of speech sensitivity.

Enums Description
START_SENSITIVITY_UNSPECIFIED Default is START_SENSITIVITY_LOW.
START_SENSITIVITY_HIGH Automatic detection will detect the start of speech more often.
START_SENSITIVITY_LOW Automatic detection will detect the start of speech less often.
Enum: TurnCoverage

Options about which input is included in the user's turn.

Enums Description
TURN_COVERAGE_UNSPECIFIED Default behavior is TURN_INCLUDES_ALL_INPUT.
TURN_INCLUDES_ONLY_ACTIVITY The user's turn only includes activity since the last turn.
TURN_INCLUDES_ALL_INPUT The user's turn includes all real-time input since the last turn.
Type: UsageMetadata

Metadata on the usage of the cached content.

Fields Description
total_token_count int32 Total number of tokens that the cached content consumes.
text_count int32 Number of text characters.
image_count int32 Number of images.
video_duration_seconds int32 Duration of video in seconds.
audio_duration_seconds int32 Duration of audio in seconds.
Message: GoAway

Server will not be able to service the client soon.

Fields Description
time_left [Duration](https://protobuf.dev/reference/protobuf/google.protobuf/#duration) The remaining time before the connection will be terminated.
Message: SessionResumptionUpdate

Update of the session resumption state. Only sent if BidiGenerateContentSetup.session_resumption was set.

Fields Description
new_handle string New handle that represents state that can be resumed.
resumable bool True if the session can be resumed at this point.
last_consumed_client_message_index int64 Index of the last message sent by the client that is included in the state.
