    vLLM serving for text-only and multimodal language models on Cloud GPUs¶

    This tutorial walks you through deploying and serving Llama 3.1 (text-only) and Llama 3.2 (multimodal) models using vLLM in Vertex AI. It shows you how to efficiently handle model inference on GPUs and customize models for diverse applications.

    By the end of this guide, you will understand how to:

    • Download prebuilt Llama models from Hugging Face with a vLLM container.
    • Use vLLM to deploy these models on GPU instances within Vertex AI Model Garden.
    • Serve models efficiently to handle inference requests at scale.
    • Run inference on text-only requests and text-with-image requests.
    • Clean up your resources.
    • Debug common deployment issues.

    Get started in Model Garden¶

    The vLLM serving container is integrated into Model Garden, offering a playground, one-click deployment, and Colab Enterprise notebook examples. This tutorial focuses on deploying Llama models from a notebook.

    While Playground and one-click deployments are also available, this guide uses the Colab Enterprise notebook for detailed, step-by-step instructions.

    1. Navigate to the Llama 3.1 model card page and click Open notebook.
    2. Select the Vertex Serving notebook. The notebook opens in Colab Enterprise.
    3. Run through the notebook to deploy a model using vLLM and send prediction requests to the endpoint. This page provides additional context and explanation for the steps in the notebook.

    vLLM key features¶

    vLLM is a high-throughput and memory-efficient serving engine for Large Language Models (LLMs).

    Feature Description
    PagedAttention An optimized attention mechanism that efficiently manages memory during inference. It supports high-throughput text generation by dynamically allocating memory, enabling scalability for multiple concurrent requests.
    Continuous batching Consolidates multiple input requests into a single batch for parallel processing, maximizing GPU utilization and throughput.
    Token streaming Enables real-time, token-by-token output during text generation. Ideal for applications that require low latency, such as chatbots or interactive AI systems.
    Model compatibility Supports a wide range of pre-trained models from popular frameworks like Hugging Face Transformers, making it easy to integrate and experiment with different LLMs.
    Multi-GPU & multi-host Distributes the workload across multiple GPUs and machines, significantly increasing throughput and scalability.
    Efficient deployment Offers seamless integration with APIs, such as the OpenAI chat completions API, making deployment straightforward for production use cases.
    Seamless integration with Hugging Face models vLLM is compatible with the Hugging Face model format and supports loading from the Hub, simplifying the deployment of Llama models alongside others like Gemma, Phi, and Qwen.
    Community-driven open-source project vLLM is open-source and encourages community contributions, promoting continuous improvement in LLM serving efficiency.

    For a technical overview of the vLLM system, see the vLLM paper.

    Google Cloud customizations for vLLM¶

    The vLLM implementation in Vertex AI Model Garden is a customized version optimized for performance, reliability, and integration within Google Cloud.

    • Performance optimizations:

      • Parallel downloading from Cloud Storage: Significantly accelerates model loading by enabling parallel data retrieval from Cloud Storage.
      • Host memory prefix caching: Extends vLLM's GPU memory prefix caching to include host memory.
      • Speculative decoding: Includes pre-tuned configurations for high-performing model setups.

    • Feature enhancements:

      • Dynamic LoRA with enhanced caching: Extends dynamic LoRA capabilities with local disk caching, robust error handling, and support for loading LoRA weights directly from Cloud Storage.
      • Llama 3.1/3.2 function calling parsing: Implements specialized, robust parsing for Llama 3.1/3.2 function calling.

    • Vertex AI ecosystem integration:

      • Vertex AI prediction format support: Ensures seamless compatibility with Vertex AI prediction input and output formats.
      • Vertex AI environment variable awareness: Leverages Vertex AI environment variables (AIP_*) for streamlined configuration and resource management.
      • Enhanced error handling: Implements comprehensive error handling, I/O validation, and server termination mechanisms to ensure stability.
      • Nginx server integration: Integrates an Nginx server to facilitate the deployment of multiple replicas, enhancing scalability and high availability.

    Additional benefits of vLLM¶

    • Benchmark performance: vLLM offers competitive throughput and latency compared to other serving systems like Hugging Face Text Generation Inference and NVIDIA's FasterTransformer.
    • Ease of use: The library provides a straightforward API for deploying Llama 3.1 and 3.2 models with minimal setup.
    • Advanced features: vLLM supports streaming outputs and efficiently handles variable-length prompts, enhancing interactivity in applications.

    3. Define the deployment function

    This function uploads the model to Vertex AI, configures deployment settings, and deploys it to an endpoint using a prebuilt vLLM Docker image.

    def deploy_model_vllm(
    model_name: str,
    model_id: str,
    service_account: str,
    base_model_id: str = None,
    machine_type: str = "g2-standard-8",
    accelerator_type: str = "NVIDIA_L4",
    accelerator_count: int = 1,
    gpu_memory_utilization: float = 0.9,
    max_model_len: int = 4096,
    dtype: str = "auto",
    enable_trust_remote_code: bool = False,
    enforce_eager: bool = False,
    enable_lora: bool = False,
    max_loras: int = 1,
    max_cpu_loras: int = 8,
    use_dedicated_endpoint: bool = False,
    max_num_seqs: int = 256,
) -> Tuple[aiplatform.Model, aiplatform.Endpoint]:
    """Deploys trained models with vLLM into Vertex AI."""
    endpoint = aiplatform.Endpoint.create(
        display_name=f"{model_name}-endpoint",
        dedicated_endpoint_enabled=use_dedicated_endpoint,
    )

    if "8b" in base_model_name.lower():
        accelerator_type = "NVIDIA_L4"
        machine_type = "g2-standard-12"
        accelerator_count = 1
    elif "70b" in base_model_name.lower():
        accelerator_type = "NVIDIA_L4"
        machine_type = "g2-standard-96"
        accelerator_count = 8
    elif "405b" in base_model_name.lower():
        accelerator_type = "NVIDIA_H100_80GB"
        machine_type = "a3-highgpu-8g"
        accelerator_count = 8
    else:
        raise ValueError(f"Recommended GPU setting not found for: {accelerator_type} and {base_model_name}.")

    common_util.check_quota(
        project_id=PROJECT_ID,
        region=REGION,
        accelerator_type=accelerator_type,
        accelerator_count=accelerator_count,
        is_for_training=False,
    )

    vllm_args = [
        "python", "-m", "vllm.entrypoints.api_server", 
        "--host=0.0.0.0", 
        "--port=8080",
        f"--model={model_id}", 
        f"--tensor-parallel-size={accelerator_count}",
        "--swap-space=16",
        f"--gpu-memory-utilization={gpu_memory_utilization}",
        f"--max-model-len={max_model_len}", f"--dtype={dtype}",
        f"--max-loras={max_loras}", f"--max-cpu-loras={max_cpu_loras}",
        f"--max-num-seqs={max_num_seqs}", "--disable-log-stats"
    ]

    if enable_trust_remote_code:
        vllm_args.append("--trust-remote-code")
    if enforce_eager:
        vllm_args.append("--enforce-eager")
    if enable_lora:
        vllm_args.append("--enable-lora")
    if model_type:
        vllm_args.append(f"--model-type={model_type}")

    env_vars = {
        "MODEL_ID": model_id,
        "DEPLOY_SOURCE": "notebook",
        "HF_TOKEN": HF_TOKEN
    }

    model = aiplatform.Model.upload(
        display_name=model_name,
        serving_container_image_uri=VLLM_DOCKER_URI,
        serving_container_args=vllm_args,
        serving_container_ports=[8080],
        serving_container_predict_route="/generate",
        serving_container_health_route="/ping",
        serving_container_environment_variables=env_vars,
        serving_container_shared_memory_size_mb=(16 * 1024),
        serving_container_deployment_timeout=7200,
    )
    print(f"Deploying {model_name} on {machine_type} with {accelerator_count} {accelerator_type} GPU(s).")

    model.deploy(
        endpoint=endpoint,
        machine_type=machine_type,
        accelerator_type=accelerator_type,
        accelerator_count=accelerator_count,
        deploy_request_timeout=1800,
        service_account=service_account,
    )
    print("endpoint_name:", endpoint.name)

    return model, endpoint

    3. Define the deployment function

    This function handles the deployment of the Llama 3.2 model on Vertex AI, configuring the environment, memory utilization, and vLLM settings.

    def deploy_model_vllm(
    model_name: str,
    model_id: str,
    service_account: str,
    base_model_id: str = None,
    machine_type: str = "g2-standard-8",
    accelerator_type: str = "NVIDIA_L4",
    accelerator_count: int = 1,
    gpu_memory_utilization: float = 0.9,
    max_model_len: int = 4096,
    dtype: str = "auto",
    enable_trust_remote_code: bool = False,
    enforce_eager: bool = False,
    enable_lora: bool = False,
    max_loras: int = 1,
    max_cpu_loras: int = 8,
    use_dedicated_endpoint: bool = False,
    max_num_seqs: int = 12,
    model_type: str = None,
) -> Tuple[aiplatform.Model, aiplatform.Endpoint]:
    """Deploys trained models with vLLM into Vertex AI."""
    endpoint = aiplatform.Endpoint.create(
        display_name=f"{model_name}-endpoint",
        dedicated_endpoint_enabled=use_dedicated_endpoint,
    )

    if not base_model_id:
        base_model_id = model_id

    vllm_args = [
        "python",
        "-m",
        "vllm.entrypoints.api_server",
        "--host=0.0.0.0",
        "--port=8080",
        f"--model={model_id}",
        f"--tensor-parallel-size={accelerator_count}",
        "--swap-space=16",
        f"--gpu-memory-utilization={gpu_memory_utilization}",
        f"--max-model-len={max_model_len}",
        f"--dtype={dtype}",
        f"--max-loras={max_loras}",
        f"--max-cpu-loras={max_cpu_loras}",
        f"--max-num-seqs={max_num_seqs}",
        "--disable-log-stats",
    ]

    if enable_trust_remote_code:
        vllm_args.append("--trust-remote-code")
    if enforce_eager:
        vllm_args.append("--enforce-eager")
    if enable_lora:
        vllm_args.append("--enable-lora")
    if model_type:
        vllm_args.append(f"--model-type={model_type}")

    env_vars = {
        "MODEL_ID": base_model_id,
        "DEPLOY_SOURCE": "notebook",
    }

    # HF_TOKEN is not a compulsory field and may not be defined.
    try:
        if HF_TOKEN:
            env_vars["HF_TOKEN"] = HF_TOKEN
    except NameError:
        pass

    model = aiplatform.Model.upload(
        display_name=model_name,
        serving_container_image_uri=VLLM_DOCKER_URI,
        serving_container_args=vllm_args,
        serving_container_ports=[8080],
        serving_container_predict_route="/generate",
        serving_container_health_route="/ping",
        serving_container_environment_variables=env_vars,
        serving_container_shared_memory_size_mb=(16 * 1024),
        serving_container_deployment_timeout=7200,
    )
    print(f"Deploying {model_name} on {machine_type} with {accelerator_count} {accelerator_type} GPU(s).")

    model.deploy(
        endpoint=endpoint,
        machine_type=machine_type,
        accelerator_type=accelerator_type,
        accelerator_count=accelerator_count,
        deploy_request_timeout=1800,
        service_account=service_account,
    )
    print("endpoint_name:", endpoint.name)

    return model, endpoint

    Debugging common issues¶

    This section provides guidance on resolving common issues encountered during vLLM model deployment and inference.

    How to check logs for errors

    To identify the root cause of a deployment failure, check the logs in the Google Cloud console.

    1. Go to the Vertex AI Endpoints page.
    2. Click the name of your endpoint.
    3. On the endpoint details page, find your model deployment. A failed deployment will have an error status.
    4. Click View logs to open Cloud Logging, which will be filtered to show logs for your deployment.
    5. Analyze the logs for error messages related to resource constraints (like CUDA OOM), authentication, or configuration.

    Issue 1: CUDA Out of Memory (OOM) during deployment

    Problem: A torch.OutOfMemoryError: CUDA out of memory error occurs when the model's memory requirements exceed the available GPU memory. This often happens with multimodal models if max_num_seqs is set too high.

    Explanation: The max_num_seqs parameter defines the maximum number of concurrent requests the model can handle. Multimodal models consume significantly more memory per sequence than text-only models because they must process image data. For example, a max_num_seqs value of 256 might work for an 8B text model on an L4 GPU but will cause an OOM error for an 11B vision model on the same hardware.

    Solution: Reduce the max_num_seqs value. For the Llama-3.2-11B-Vision-Instruct model on an NVIDIA A100 GPU, a value of 12 is a reasonable starting point. You can also resolve this by using a machine type with more or larger GPUs.

    Issue 2: Hugging Face token needed

    Problem: The deployment fails with an error message like Cannot access gated repository.

    Explanation: This error occurs because Llama models are gated, and your deployment is missing a valid Hugging Face token or the token does not have the correct permissions.

    Solution: 1. Ensure you have requested and been granted access to the model on Hugging Face. 2. Generate a new Read access token from your Hugging Face account settings. 3. Provide this token in the HF_TOKEN environment variable when deploying your model.

    Issue 3: Chat template needed

    Problem: The deployment fails with a ValueError indicating that a chat template is missing.

    Explanation: Recent versions of the transformers library require an explicit chat template if the tokenizer does not define one.

    Solution: Provide a chat template during deployment using the --chat-template argument in the vllm_args. You can find sample templates in the vLLM examples repository.

    Issue 4: Model max sequence length too large

    Problem: The deployment fails with a ValueError stating The model's max seq len (4096) is larger than the maximum number of tokens that can be stored in KV cache (2256).

    Explanation: The combination of model size and other parameters (gpu_memory_utilization, max_num_seqs) does not leave enough GPU memory to allocate the Key-Value (KV) cache for the specified max_model_len.

    Solution: * Option 1 (Recommended): Decrease the max_model_len to a value smaller than the available KV cache size indicated in the error message (e.g., 2048). * Option 2: Increase the available GPU memory by using a machine type with more or larger GPUs. If using multiple GPUs, ensure tensor-parallel-size is set correctly. * Option 3: Slightly increase gpu_memory_utilization (e.g., to 0.95), but this may risk OOM errors during inference.
