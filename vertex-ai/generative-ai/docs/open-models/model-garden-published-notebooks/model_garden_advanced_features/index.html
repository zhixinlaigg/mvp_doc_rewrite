    Vertex AI Model Garden - Advanced Features¶

    Run in Colab Enterprise View on GitHub

    Overview¶

    Model optimization is a crucial step for balancing cost-effectiveness with performance metrics like throughput and latency. Because user traffic patterns and requirements vary, a one-size-fits-all approach is often insufficient. For example, chat applications prioritize low latency for an interactive experience, while recommendation systems may need to maximize throughput.

    This notebook provides a suite of advanced optimization techniques to help you customize and optimize AI model performance for your unique use cases and workloads. You will learn how to implement the following features using Meta-Llama models as examples, though you can apply these techniques to other supported models in Vertex AI Model Garden:

    • Prefix Caching: Reduces latency for requests with common prompt prefixes.
    • Speculative Decoding: Accelerates token generation to improve throughput.

    Costs¶

    This tutorial uses billable components of Google Cloud:

    • Vertex AI
    • Cloud Storage

    Learn about Vertex AI pricing and Cloud Storage pricing, and use the Pricing Calculator to generate a cost estimate based on your projected usage.

    Before you begin¶

    Concepts
    • Prefix Caching: An optimization technique that reuses the computations for common prompt prefixes to reduce the Time-To-First-Token (TTFT).
    • Speculative Decoding: An algorithm that uses a smaller, faster "drafter" model to generate multiple token candidates in parallel, which are then verified by the larger target model to accelerate output generation.
    • vLLM: An open-source library designed for fast and efficient LLM inference and serving.
    • Hex-LLM: A high-efficiency LLM serving solution developed by Google Cloud, built with XLA for optimized performance on TPUs.
    • Time-To-First-Token (TTFT): The time elapsed from when a prompt is sent to an LLM until the first token of the response is received.
    Prerequisites

    Request for quota

    You may require the following quotas to try the examples in this notebook:

    • Custom model serving TPU v5e cores per region
    • Custom model serving Nvidia A100 80GB GPUs per region

    By default, the quota for TPU deployment (Custom model serving TPU v5e cores per region) is 4, which is sufficient for serving the Llama 3.1 8B model. The Llama 3.1 70B model requires 16 TPU v5e cores. TPU quota is only available in us-west1. You can request a higher TPU quota by following the instructions at "Request a higher quota".

    The quota for A100_80GB deployment (Custom model serving Nvidia A100 80GB GPUs per region) is 0 by default. You need to request at least 4 for the 70B model and 1 for the 8B model by following the instructions at "Request a higher quota".

    Implement Prefix Caching¶

    Prefix caching reduces Time-to-First-Token (TTFT) for prompts that share identical content at the beginning, such as system instructions, few-shot examples, or multi-turn conversation history. Instead of re-computing these common prefixes, the serving solution retains a cache of the processed input token computations. This can significantly reduce latency, especially for long prompts. For instance, benchmarks show TTFT reductions of over 90%.

    You can implement prefix caching using either Hex-LLM on TPUs or vLLM on GPUs. Use the table below to decide which serving solution best fits your needs.

    Feature Hex-LLM vLLM
    Primary Accelerator TPU GPU
    Key Advantage Optimized for high-efficiency serving on TPUs. Broad model support and flexible caching options (GPU and Host Memory).
    Supported Models Llama 3.1 (8B, 70B), Llama 3 (8B), Gemma (2B, 7B), and more. Most text-only, decoder-only LLMs, including Llama, Gemma, and Mistral families.
    Best For Users who want to leverage TPUs for cost-effective, high-performance serving. Users who need broad model compatibility and advanced caching strategies on GPUs.

    Hex-LLM is a High-Efficiency Large Language Model (LLM) TPU serving solution built with XLA, developed by Google Cloud. It is optimized for performance on TPUs.

def deploy_model_hexllm(
    model_name: str,
    model_id: str,
    service_account: str,
    base_model_id: str = None,
    data_parallel_size: int = 1,
    tensor_parallel_size: int = 1,
    machine_type: str = "ct5lp-hightpu-1t",
    tpu_topology: str = "1x1",
    disagg_topology: str = None,
    hbm_utilization_factor: float = 0.6,
    max_running_seqs: int = 256,
    max_model_len: int = 4096,
    enable_prefix_cache_hbm: bool = False,
    endpoint_id: str = "",
    min_replica_count: int = 1,
    max_replica_count: int = 1,
    use_dedicated_endpoint: bool = False,
) -> Tuple[aiplatform.Model, aiplatform.Endpoint]:
    """Deploys models with Hex-LLM on TPU in Vertex AI."""
    if endpoint_id:
        aip_endpoint_name = (
            f"projects/{PROJECT_ID}/locations/{REGION}/endpoints/{endpoint_id}"
        )
        endpoint = aiplatform.Endpoint(aip_endpoint_name)
    else:
        endpoint = aiplatform.Endpoint.create(
            display_name=f"{model_name}-endpoint",
            location=TPU_DEPLOYMENT_REGION,
            dedicated_endpoint_enabled=use_dedicated_endpoint,
        )

    if not base_model_id:
        base_model_id = model_id

    if not tensor_parallel_size:
        tensor_parallel_size = int(machine_type[-2])

    num_hosts = int(tpu_topology.split("x")[0])

    # Learn more about the supported arguments and environment variables at https://cloud.google.com/vertex-ai/generative-ai/docs/open-models/use-hex-llm#config-server.
    hexllm_args = [
        "--host=0.0.0.0",
        "--port=7080",

    The Vertex AI prebuilt vLLM container supports two types of prefix caching: in GPU memory and in VM host memory.

    Caching Method Description Pros Cons
    GPU Memory Caching Caches prefix KV states directly in the GPU's high-bandwidth memory (HBM). Fastest access: Provides the lowest latency on a cache hit. Limited capacity: The cache size is constrained by available GPU memory.
    VM Host Memory Caching Uses the VM's main RAM as a larger, second-tier cache. Large capacity: Can store significantly more cached prefixes than GPU memory. Slower access: Incurrs overhead from transferring data from host RAM to GPU memory.

    When host memory caching is enabled, it works alongside GPU caching. Processed requests are written to both caches, with the host memory write happening asynchronously to minimize performance impact. This tiered approach provides a 20-75% TTFT improvement for requests that miss the GPU cache but hit the host cache.

    Best practices¶

    To maximize the benefits of prefix caching, follow these best practices:

    • Structure Prompts Effectively: Place static content (like system instructions or context documents) at the beginning of your prompts and dynamic content (like user questions) at the end.
    • Warm Up the Cache: Before running batch queries, send a few requests with the common prefixes to populate the cache.
    • Monitor Performance: Track metrics like cache hit rates, latency, and the percentage of tokens cached to optimize your prompts and caching strategy.

    Implement Speculative Decoding¶

    Speculative decoding accelerates model inference by using a smaller, faster "drafter" model to propose multiple future tokens in parallel. The larger, more powerful target model then verifies these proposed tokens in a single forward pass. If the drafted tokens are correct, several tokens are generated concurrently, significantly reducing the Time-per-Output-Token (TPOT) without compromising response quality.

    The Vertex AI prebuilt vLLM container supports two speculative decoding methods. Use the table below to choose the appropriate method for your use case.

    Method Description Pros Cons
    Draft Model Uses a smaller, faster LLM to generate draft tokens. High quality/accuracy: Offers significant speedups when the drafter model aligns well with the target model. Requires training or finding a suitable drafter model; consumes additional HBM for the drafter model's weights.
    N-gram Uses n-gram matching from the prompt to propose draft tokens. No extra model needed: Simple to implement and works well for tasks with high overlap between prompt and response (e.g., code editing, RAG). Less effective for creative or open-ended generation tasks where the output is not directly grounded in the prompt.

    While speculative decoding improves TPOT, note that it can slightly increase TTFT due to the initial prefill required for the drafter.

def poll_operation(op_name: str) -> bool:
    creds, _ = google.auth.default()
    auth_req = google.auth.transport.requests.Request()
    creds.refresh(auth_req)
    headers = {
        "Authorization": f"Bearer {creds.token}",
    }
    get_resp = requests.get(
        f"https://{REGION}-aiplatform.googleapis.com/v1beta1/{op_name}",
        headers=headers,
    )
    opjs = get_resp.json()
    if "error" in opjs:
        raise ValueError(f"Operation failed: {opjs['error']}")
    return opjs.get("done", False)


def poll_and_wait(op_name: str, total_wait: int, interval: int = 60):
    waited = 0
    while not poll_operation(op_name):
        if waited > total_wait:
            raise TimeoutError("Operation timed out")
        print(
            f"\rStill waiting for operation... Waited time in second: {waited:<6}",
            end="",
            flush=True,
        )
        waited += interval
        time.sleep(interval)

        "--port=8080",

        f"--max-model-len={max_model_len}",
        f"--dtype={dtype}",
        f"--max-num-seqs={max_num_seqs}",
        "--disable-log-stats",
    ]

    if enable_trust_remote_code:
        vllm_args.append("--trust-remote-code")

    if enforce_eager:
        vllm_args.append("--enforce-eager")

    if enable_chunked_prefill:
        vllm_args.append("--enable-chunked-prefill")

    if model_type:
        vllm_args.append(f"--model-type={model_type}")

    env_vars = {
        "MODEL_ID": base_model_id,
        "DEPLOY_SOURCE": "notebook",
    }

    # HF_TOKEN is not a compulsory field and may not be defined.
    try:
        if HF_TOKEN:
            env_vars["HF_TOKEN"] = HF_TOKEN
    except NameError:
        pass

    draft_model = None
    draft_resource_name = draft_model_id
    if speculation_method == "draft_model":
        print("Uploading draft model...")
        drafter_vllm_args = [
            "python",
            "-m",
            "vllm.entrypoints.api_server",
            "--host=0.0.0.0",
            "--port=8080",
            f"--model={draft_model_id}",

            serving_container_image_uri=VLLM_DOCKER_URI,
            serving_container_args=drafter_vllm_args,

            serving_container_predict_route="/generate",
            serving_container_health_route="/ping",
            serving_container_shared_memory_size_mb=(16 * 1024),
            serving_container_deployment_timeout=7200,
        )
        draft_resource_name = draft_model.resource_name

    print("Uploading target model...")
    model = aiplatform.Model.upload(
        display_name=model_name,
        serving_container_image_uri=VLLM_DOCKER_URI,

        serving_container_health_route="/ping",
        serving_container_environment_variables=env_vars,
        serving_container_shared_memory_size_mb=(16 * 1024),
        serving_container_deployment_timeout=7200,
    )

    print(
        f"Deploying {model_name} on {machine_type} with"
        f" {accelerator_count} {accelerator_type} GPU(s)."
    )

    creds, _ = google.auth.default()
    auth_req = google.auth.transport.requests.Request()
    creds.refresh(auth_req)

    headers = {
        "Content-Type": "application/json",
        "Authorization": f"Bearer {creds.token}",
    }

        "deployedModel": {
            "model": model.resource_name,
            "displayName": model_name,
            "dedicatedResources": {
                "machineSpec": {
                    "machineType": machine_type,
                    "acceleratorType": accelerator_type,
                    "acceleratorCount": accelerator_count,
                },
                "minReplicaCount": 1,
                "maxReplicaCount": 1,
            },
            "serviceAccount": service_account,
            "systemLabels": {
                "NOTEBOOK_NAME": "model_garden_advanced_features",
            },
        },
    }
    if enable_speculative_decoding:
        if speculation_method == "ngram":
            data["deployedModel"]["speculativeDecodingSpec"] = {
                "speculativeTokenCount": speculative_token_count,
                "ngramSpeculation": {"ngramSize": ngram_size},
            }
        elif speculation_method == "draft_model":
            data["deployedModel"]["speculativeDecodingSpec"] = {
                "speculativeTokenCount": speculative_token_count,
                "draftModelSpeculation": {
                    "draftModel": draft_resource_name,
                },
            }
        else:
            raise ValueError(f"Unsupported speculation method: {speculation_method}.")
    response = requests.post(url, headers=headers, json=data)
    print(f"Deploy Model response: {response.json()}")
    if response.status_code != 200 or "name" not in response.json():
        raise ValueError(f"Failed to deploy model: {response.text}")
    poll_and_wait(response.json()["name"], 3600)
    return model, draft_model, endpoint
