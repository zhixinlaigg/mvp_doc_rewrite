Run AutoSxS pipeline to perform pairwise model-based evaluation¶

Note: For the most updated pairwise model-based evaluation features, see Define your metrics.

This page introduces how to perform pairwise model-based evaluation using AutoSxS, a tool that runs through the evaluation pipeline service. It explains how to use AutoSxS through the Vertex AI API, the Vertex AI SDK for Python, or the Google Cloud console.

What is AutoSxS?¶

Automatic side-by-side (AutoSxS) is a pairwise model-based evaluation tool that uses an autorater to compare the performance of two generative AI models. You can use AutoSxS to evaluate models in the Vertex AI Model Registry or models with pre-generated predictions. This allows AutoSxS to support Vertex AI foundation models, tuned models, and third-party language models.

The autorater is a powerful language model that acts as a human rater, judging the quality of model responses based on a given prompt and a set of evaluation criteria. It determines which model provides a better response and outputs preferences, explanations, and confidence scores.

At a high level, AutoSxS compares the predictions of Model A and Model B using the autorater.

Before you begin¶

Concepts
  • Pairwise model-based evaluation: A method of comparing two models by having a human or an AI-based "autorater" choose the better of two responses to the same prompt.
  • AutoSxS: An automatic, on-demand implementation of pairwise model-based evaluation that uses an AI-based autorater.
  • Autorater: A language model that judges the quality of model responses based on predefined criteria for a specific task.
  • Evaluation dataset: A set of prompts and optional context that are used to test the models. It can be a BigQuery table or a JSON Lines file in Cloud Storage.
  • Prompt parameters: Templated inputs that allow you to flexibly define how data from your evaluation dataset is used to prompt the models and the autorater.

How AutoSxS works¶

Supported models¶

AutoSxS supports the evaluation of any model when you provide pre-generated predictions. It also supports automatically generating responses for any text model in the Vertex AI Model Registry that supports batch prediction.

If your text model is not in the Model Registry, you can provide pre-generated predictions stored as a JSONL file in Cloud Storage or in a BigQuery table. For pricing information on response generation, see Text generation pricing.

Supported tasks and criteria¶

AutoSxS supports evaluating models for summarization and question-answering tasks. The evaluation criteria are predefined for each task to make the evaluation more objective and improve response quality.

Summarization

The summarization task has a 4,096 input token limit.

Criteria Description
Follows instructions To what extent does the model's response demonstrate an understanding of the instruction from the prompt?
Grounded Does the response include only information from the inference context and inference instruction?
Comprehensive To what extent does the model capture key details in the summarization?
Brief Is the summarization verbose? Does it include flowery language? Is it overly terse?

Question Answering

The question_answering task has a 4,096 input token limit.

Criteria Description
Fully answers the question The answer responds to the question completely.
Grounded Does the response include only information from the instruction context and inference instruction?
Relevance Does the content of the answer relate to the question?
Comprehensive To what extent does the model capture key details in the question?

Evaluation dataset and predictions¶

This section details the data you should provide in your AutoSxS evaluation dataset and best practices for dataset construction.

Dataset format¶

AutoSxS accepts a single evaluation dataset with a flexible schema. The dataset can be a BigQuery table or stored as JSON Lines in Cloud Storage. Each row represents a single example, and the columns can be one of the following:

  • ID columns: Used to identify each unique example.
  • Data columns: Used to fill out prompt templates.
  • Pre-generated predictions: Responses generated by a model for a given prompt. Using pre-generated predictions saves time and resources.
  • Ground-truth human preferences: Used to benchmark AutoSxS against your ground-truth data.

Here is an example evaluation dataset where context and question are data columns, and model_b_response contains pre-generated predictions for one of the models.

context question model_b_response
Some might think that steel is the hardest material or titanium, but diamond is actually the hardest material. What is the hardest material? Diamond is the hardest material. It is harder than steel or titanium.

Prompt parameters¶

Many language models take multiple prompt parameters as input. For example, chat-bison takes messages, examples, and context, while text-bison takes a single prompt parameter. AutoSxS provides flexibility to specify these parameters using templates.

You can map a dataset column directly to a prompt parameter:

{'some_parameter': {'column': 'my_column'}}

Alternatively, you can define a template that uses columns from your dataset as variables:

{'some_parameter': {'template': 'Summarize the following: {{ my_column }}.'}}

You can also use the protected default_instruction keyword, which is replaced with the default instruction for the given task:

model_prompt_parameters = {
        'prompt': {'template': '{{ default_instruction }}: <function define_env.<locals>.context at 0x1024d4a60>'},
}

Gemini

For Gemini models, the prompt parameter keys are contents (required) and system_instruction (optional), aligning with the Gemini request body schema.

model_a_prompt_parameters={
    'contents': {
        'column': 'context'
    },
    'system_instruction': {'template': '{{ default_instruction }}'},
},

text-bison

For text-bison, the input parameter is prompt and the output is content.

model_a_prompt_parameters={
    'prompt': {
        'template': {
            'Answer the following question from the point of view of a college professor: <function define_env.<locals>.context at 0x1024d4a60>\n{{ question }}'
        },
    },
},
response_column_a='content',  # Column in Model A response.
response_column_b='model_b_response',  # Column in eval dataset.

Autorater parameters¶

The autorater also requires prompt parameters to perform its evaluation.

Autorater prompt parameter Configurable by user? Description
Autorater instruction No A calibrated instruction describing the criteria the autorater should use to judge the responses.
Inference instruction Yes A description of the task each candidate model should perform.
Inference context Yes Additional context for the task being performed.
Responses No (configured via pre-generated responses) A pair of responses to evaluate, one from each candidate model.

Here is a sample configuration for the autorater's prompt parameters:

autorater_prompt_parameters={
    'inference_instruction': {
        'template': 'Answer the following question from the point of view of a college professor: {{ question }}.'
    },
    'inference_context': {
        'column': 'context'
    }
}

Best practices¶

  • Provide examples that represent the types of inputs your models will process in production.
  • Your dataset must include at least one example. We recommend around 100 examples for high-quality aggregate metrics. Quality improvements tend to diminish after 400 examples.
  • For guidance on writing effective prompts, see Design text prompts.
  • If you use pre-generated predictions, include them in a column of your evaluation dataset. This is useful for comparing models not in the Vertex AI Model Registry and for reusing responses.

Evaluation scenarios¶

AutoSxS can be configured for different evaluation scenarios depending on whether you are using models from the Vertex AI Model Registry or providing pre-generated predictions.

Scenario Model A Source Model B Source Use Case
Compare two models Vertex AI Model Registry Vertex AI Model Registry Evaluate a tuned model against a reference model, with AutoSxS generating responses for both.
Compare a model to predictions Vertex AI Model Registry Pre-generated predictions Evaluate a model in the registry against an external model or a previous version by providing its responses in the dataset.
Compare two sets of predictions Pre-generated predictions Pre-generated predictions Evaluate two external models or benchmark the autorater against human preferences by providing all responses.

This scenario evaluates a tuned model against a reference model, both from the Vertex AI Model Registry.

# Evaluation dataset schema:
#   my_question: str
#   my_context: str
parameters = {
    'evaluation_dataset': DATASET,
    'id_columns': ['my_context'],
    'task': 'question_answering',
    'autorater_prompt_parameters': {
      'inference_instruction': {'column': 'my_question'},
      'inference_context': {'column': 'my_context'},
  },
    'model_a': 'publishers/google/models/text-bison@002',
    'model_a_prompt_parameters': {'prompt': {'template': '{{ my_question }}\nCONTEXT: {{ my_context }}'}},
  'response_column_a': 'content',
    'model_b': 'projects/abc/locations/abc/models/tuned_bison',
    'model_b_prompt_parameters': {'prompt': {'template': '{{ my_context }}\n{{ my_question }}'}},
  'response_column_b': 'content',
}

This scenario evaluates a model from the registry against a set of pre-generated predictions.

# Evaluation dataset schema:
#   my_question: str
#   my_context: str
#   response_b: str

parameters = {
    'evaluation_dataset': DATASET,
    'id_columns': ['my_context'],
    'task': 'question_answering',
    'autorater_prompt_parameters': {
        'inference_instruction': {'column': 'my_question'},
        'inference_context': {'column': 'my_context'},
    },
    'model_a': 'publishers/google/models/text-bison@002',
    'model_a_prompt_parameters': {'prompt': {'template': '{{ my_question }}\nCONTEXT: {{ my_context }}'}},
    'response_column_a': 'content',
    'response_column_b': 'response_b',
}

This scenario evaluates two sets of pre-generated predictions. It is useful for comparing external models or for benchmarking AutoSxS against human-preference data by providing human judgments in the human_preference_column.

# Evaluation dataset schema:
#  my_question: str
#  my_context: str
#   response_a: str
#   response_b: str
#   actual: str
parameters = {
    'evaluation_dataset': DATASET,
    'id_columns': ['my_context'],
    'task': 'question_answering',
    'autorater_prompt_parameters': {
      'inference_instruction': {'column': 'my_question'},
      'inference_context': {'column': 'my_context'},
  },
  'response_column_a': 'response_a',
  'response_column_b': 'response_b',
  'human_preference_column': 'actual',
}

Run an evaluation job¶

This section walks you through the process of running an AutoSxS evaluation job. You can use the REST API, the Vertex AI SDK for Python, or the Google Cloud console.

The following diagram shows the workflow for running a pairwise model-based evaluation job with AutoSxS.

flowchart TD
    A[Step 1: Prepare Evaluation Dataset] --> B[Step 2: Configure and Run Job]
    B --> C[Step 3: View Evaluation Results]

    click A "#prepare-your-evaluation-dataset"
    click B "#configure-and-run-the-job"
    click C "#view-evaluation-results"
Run an evaluation job

Step 1: Prepare your evaluation dataset

First, create your evaluation dataset as a JSONL file in Cloud Storage or as a BigQuery table. The dataset should contain prompts and any additional data required for your evaluation scenario. For more details, see Evaluation dataset and predictions.

Here is an example of a JSONL dataset for a question-answering task, which includes pre-generated predictions for Model B.

{
  "id": 1,
  "question": "What is the hardest material?",
  "context": "Some might think that steel is the hardest material, or even titanium. However, diamond is actually the hardest material.",
  "model_b_response": "Diamond is the hardest material. It is harder than steel or titanium."
}
{
  "id": 2,
  "question": "What is the highest mountain in the world?",
  "context": "K2 and Everest are the two tallest mountains, with K2 being just over 28k feet and Everest being 29k feet tall.",
  "model_b_response": "Mount Everest is the tallest mountain, with a height of 29k feet."
}
{
  "id": 3,
  "question": "Who directed The Godfather?",
  "context": "Mario Puzo and Francis Ford Coppola co-wrote the screenplay for The Godfather, and the latter directed it as well.",
  "model_b_response": "Francis Ford Coppola directed The Godfather."
}

Step 2: Configure and run the job

Next, configure and submit the AutoSxS pipeline job. Use the following syntax to specify the path to your model:

  • Publisher model: publishers/PUBLISHER/models/MODEL (e.g., publishers/google/models/text-bison)
  • Tuned model: projects/PROJECT_NUMBER/locations/LOCATION/models/MODEL@VERSION (e.g., projects/123456789012/locations/us-central1/models/1234567890123456789)

Troubleshooting

If you encounter issues with code snippets or setup, refer to the Troubleshooting Guide.

To create a model evaluation job, send a POST request using the pipelineJobs.create method.

Before using the request data, make the following replacements:

  • PIPELINEJOB_DISPLAYNAME: A display name for the pipelineJob.
  • PROJECT_ID: Your Google Cloud project ID.
  • LOCATION: The region to run the pipeline components (e.g., us-central1).
  • OUTPUT_DIR: The Cloud Storage URI to store evaluation output (e.g., my-bucket/output).
  • EVALUATION_DATASET: The BigQuery table or Cloud Storage path(s) to your JSONL dataset.
  • TASK: The evaluation task (summarization or question_answering).
  • ID_COLUMNS: A list of columns that uniquely identify each example.
  • AUTORATER_PROMPT_PARAMETERS: The prompt parameters for the autorater.
  • RESPONSE_COLUMN_A: The column containing Model A's predictions.
  • RESPONSE_COLUMN_B: The column containing Model B's predictions.
  • MODEL_A (Optional): The resource name of Model A if responses are not pre-generated.
  • MODEL_B (Optional): The resource name of Model B if responses are not pre-generated.
  • MODEL_A_PROMPT_PARAMETERS (Optional): The prompt parameters for Model A.
  • MODEL_B_PROMPT_PARAMETERS (Optional): The prompt parameters for Model B.
  • JUDGMENTS_FORMAT (Optional): The format for judgments (jsonl, json, or bigquery).
  • BIGQUERY_DESTINATION_PREFIX (Optional): The BigQuery table for judgments if format is bigquery.

  1. Start the evaluation flow.

    You can start from either Model Garden or the Model Registry.

    • To evaluate a Google foundation model:

      1. Go to the Vertex AI Model Garden and select a model that supports pairwise evaluation, such as text-bison. Go to Model Garden
      2. Click Evaluate.
      3. Select a model version and click Select.
      4. If prompted, save a copy of the model to the Vertex AI Model Registry.
      5. On the Create Evaluation page, for Evaluate Method, select Evaluate this model against another model.
      6. Click Continue.

    • To evaluate an existing model in the Model Registry:

      1. Go to the Vertex AI Model Registry page. Go to Vertex AI Model Registry
      2. Click the name of a model that supports pairwise evaluation.
      3. In the Evaluate tab, click SxS.
      4. Click Create SxS Evaluation.

  2. Configure the evaluation.

    Follow the steps in the evaluation creation wizard:

    1. Evaluation dataset: Select an evaluation objective, a model to compare against, your evaluation dataset, and the ID columns.
    2. Model settings: Specify whether to use pre-generated responses from your dataset or have Vertex AI generate them using batch prediction. Configure the response columns and any necessary prompt parameters.
    3. Autorater settings: Enter your autorater prompt parameters and specify an output location for the evaluation results.

  3. Start the evaluation.

    Click Start Evaluation to run the job.

Judgments

Judgments are example-level metrics that help you understand model performance on individual prompts. They can be written to Cloud Storage (JSONL) or a BigQuery table and include inference prompts, model responses, autorater decisions, explanations, and confidence scores.

Column Description
id columns Columns that distinguish unique evaluation examples.
inference_instruction Instruction used to generate model responses.
inference_context Context used to generate model responses.
response_a Model A's response.
response_b Model B's response.
choice The model with the better response (Model A, Model B, or Error).
confidence A score from 0 to 1 indicating the autorater's confidence in its choice.
explanation The autorater's reason for its choice.

Aggregate metrics

AutoSxS calculates win-rate metrics from the judgments table.

Metric Description
AutoRater model A win rate Percentage of times the autorater chose Model A's response as better.
AutoRater model B win rate Percentage of times the autorater chose Model B's response as better.

Human-preference alignment metrics

If you provide human-preference data, AutoSxS also calculates alignment metrics to benchmark the autorater against human judgments. These include metrics like accuracy, precision, recall, F1-score, and Cohen's Kappa.
