Use Visual Question Answering (VQA) to get image information¶

Caution: Starting on June 24, 2025, Imagen versions 1 and 2 are deprecated. Imagen models imagegeneration@002, imagegeneration@005, and imagegeneration@006 will be removed on September 24, 2025 . For more information about migrating to Imagen 3, see Migrate to Imagen 3.

Visual Question Answering (VQA) lets you provide an image to a model and ask a question about its contents. In response, you receive one or more natural language answers.

VQA model options¶

Vertex AI offers multiple models for performing VQA tasks. This page describes how to use the imagetext model (part of Imagen). The Gemini API can also perform VQA tasks, particularly for multimodal inputs.

The following table provides a high-level comparison to help you choose the best model for your use case.

Feature Gemini API Imagen (imagetext model)
Input Multiple images, video, and text A single image
Task Type Multimodal reasoning and conversation Short-form Q&A and captioning
Best for Complex questions requiring context from multiple sources. Straightforward questions about a single image's contents.

Note: The Gemini API can answer questions based on multiple image inputs, while Imagen can process one image in each input. For more information, see the Gemini API documentation.

Before you begin

Concepts
  • Visual Question Answering (VQA): A task where a model answers natural language questions about an image.
  • imagetext model: A foundational model in Vertex AI for understanding images, capable of tasks like VQA and image captioning.
  • Token: The basic unit of text (e.g., a word or subword) that a language model processes.
  • Base64 encoding: A method to convert binary data like an image into a text string for use in text-based formats like JSON.

Before sending a request, complete the following setup:

  • Set up your Google Cloud project and authentication.
  • Enable the Vertex AI API.
  • Identify your PROJECT_ID and LOCATION. For a list of available regions, see Generative AI on Vertex AI locations.
  • To authenticate to Vertex AI, set up Application Default Credentials. For more information, see Set up authentication for a local development environment.

Prepare your image and prompt

To make a VQA request, you need the following:

  • An image: The image must be specified as a base64-encoded byte string. The size limit is 10 MB.
  • A prompt: The question you want to ask about your image. For example:
    • What color is this shoe?
    • What type of sleeves are on the shirt?
  • Response count (optional): The number of answers you want to generate. Accepted integer values are 1-3.

Send a VQA request

Use the following samples to ask a question and get an answer about an image.

Troubleshooting

If you encounter issues with code snippets or setup, refer to the Troubleshooting Guide.

For more information about imagetext model requests, see the imagetext model API reference.

Before using any of the request data, make the following replacements:

  • PROJECT_ID: Your Google Cloud project ID.
  • LOCATION: Your project's region (e.g., us-central1).
  • VQA_PROMPT: The question you want to ask about your image.
  • B64_IMAGE: The base64-encoded byte string of your image.
  • RESPONSE_COUNT: The number of answers to generate (1-3).

HTTP method and URL:

POST https://LOCATION-aiplatform.googleapis.com/v1/projects/PROJECT_ID/locations/LOCATION/publishers/google/models/imagetext:predict

Request JSON body:

{
  "instances": [
    {
      "prompt": "VQA_PROMPT",
      "image": {
          "bytesBase64Encoded": "B64_IMAGE"
      }
    }
  ],
  "parameters": {
    "sampleCount": RESPONSE_COUNT
  }
}

To send your request, choose one of these options:

curl

Note: The following command assumes that you have logged in to the gcloud CLI with your user account by running gcloud init or gcloud auth login, or by using Cloud Shell, which automatically logs you into the gcloud CLI. You can check the currently active account by running gcloud auth list.

Save the request body in a file named request.json, and execute the following command:

curl -X POST \
     -H "Authorization: Bearer $(gcloud auth print-access-token)" \
     -H "Content-Type: application/json; charset=utf-8" \
     -d @request.json \
     "https://LOCATION-aiplatform.googleapis.com/v1/projects/PROJECT_ID/locations/LOCATION/publishers/google/models/imagetext:predict"

PowerShell

Note: The following command assumes that you have logged in to the gcloud CLI with your user account by running gcloud init or gcloud auth login. You can check the currently active account by running gcloud auth list.

Save the request body in a file named request.json, and execute the following command:

$cred = gcloud auth print-access-token
$headers = @{ "Authorization" = "Bearer $cred" }

Invoke-WebRequest `
    -Method POST `
    -Headers $headers `
    -ContentType: "application/json; charset=utf-8" `
    -InFile request.json `
    -Uri "https://LOCATION-aiplatform.googleapis.com/v1/projects/PROJECT_ID/locations/LOCATION/publishers/google/models/imagetext:predict" | Select-Object -Expand Content

Before trying this sample, follow the Python setup instructions in the Vertex AI quickstart using client libraries. For more information, see the Vertex AI Python API reference documentation.

In this sample, you use the load_from_file method to load a local image and the ask_question method to get answers.

import vertexai
from vertexai.preview.vision_models import Image, ImageTextModel

# TODO(developer): Update and un-comment below lines
# PROJECT_ID = "your-project-id"
# input_file = "input-image.png"

vertexai.init(project=PROJECT_ID, location="us-central1")

model = ImageTextModel.from_pretrained("imagetext@001")
source_img = Image.load_from_file(location=input_file)

answers = model.ask_question(
    image=source_img,
    question=question,
    # Optional parameters
    number_of_results=1,
)

print(answers)
# Example response:
# ['tabby']

Before trying this sample, follow the Node.js setup instructions in the Vertex AI quickstart using client libraries. For more information, see the Vertex AI Node.js API reference documentation.

In this sample, you call the predict method on a PredictionServiceClient to get answers for the provided question.

/**
 * TODO(developer): Update these variables before running the sample.
 */
const projectId = process.env.CAIP_PROJECT_ID;
const location = 'us-central1';
const inputFile = 'resources/cat.png';
// The question about the contents of the image.
const prompt = 'What breed of cat is this a picture of?';

const aiplatform = require('@google-cloud/aiplatform');

// Imports the Google Cloud Prediction Service Client library
const {PredictionServiceClient} = aiplatform.v1;

// Import the helper module for converting arbitrary protobuf.Value objects
const {helpers} = aiplatform;

// Specifies the location of the api endpoint
const clientOptions = {
  apiEndpoint: `${location}-aiplatform.googleapis.com`,
};

// Instantiates a client
const predictionServiceClient = new PredictionServiceClient(clientOptions);

async function getShortFormImageResponses() {
  const fs = require('fs');
  // Configure the parent resource
  const endpoint = `projects/${projectId}/locations/${location}/publishers/google/models/imagetext@001`;

  const imageFile = fs.readFileSync(inputFile);
  // Convert the image data to a Buffer and base64 encode it.
  const encodedImage = Buffer.from(imageFile).toString('base64');

  const instance = {
    prompt: prompt,
    image: {
      bytesBase64Encoded: encodedImage,
    },
  };
  const instanceValue = helpers.toValue(instance);
  const instances = [instanceValue];

  const parameter = {
    // Optional parameters
    sampleCount: 2,
  };
  const parameters = helpers.toValue(parameter);

  const request = {
    endpoint,
    instances,
    parameters,
  };

  // Predict request
  const [response] = await predictionServiceClient.predict(request);
  const predictions = response.predictions;
  if (predictions.length === 0) {
    console.log(
      'No responses were generated. Check the request parameters and image.'
    );
  } else {
    predictions.forEach(prediction => {
      console.log(prediction.stringValue);
    });
  }
}
await getShortFormImageResponses();

Interpret the VQA response

The following sample response is for a request with "sampleCount": 2 and "prompt": "What is this?". The response returns two prediction string answers.

{
  "predictions": [
    "cappuccino",
    "coffee"
  ]
}

VQA parameters¶

When you request VQA responses, you can set several parameters to control the output.

  • Number of results: Use this parameter to limit the number of answers returned for each request. For more information, see the imagetext (VQA) model API reference.
  • Seed number: A number you can add to a request to make the generated responses deterministic. Adding a seed number helps ensure that you get the same predictions each time, though the answers are not necessarily returned in the same order. For more information, see the imagetext (VQA) model API reference.

Maximum number of tokens returned in response (short-form) 64 tokens
Maximum number of tokens accepted in request (VQA short-form only) 80 tokens

The following service latency estimates apply when you use this model. These values are illustrative and not a promise of service:

Latency Value
API requests (short-form) 1.5 seconds

Locations¶

A location is a region you can specify in a request to control where data is stored at rest. For a list of available regions, see Generative AI on Vertex AI locations.

Responsible AI safety filtering¶

The VQA feature model doesn't support user-configurable safety filters. However, the overall Imagen safety filtering occurs on the following data:

  • User input
  • Model output

As a result, your output may differ from the sample output if Imagen applies these safety filters. Consider the following examples.

Filtered input

If the input is filtered, the response is similar to the following:

{
  "error": {
    "code": 400,
    "message": "Media reasoning failed with the following error: The response is blocked, as it may violate our policies. If you believe this is an error, please send feedback to your account team. Error Code: 63429089, 72817394",
    "status": "INVALID_ARGUMENT",
    "details": [
      {
        "@type": "type.googleapis.com/google.rpc.DebugInfo",
        "detail": "[ORIGINAL ERROR] generic::invalid_argument: Media reasoning failed with the following error: The response is blocked, as it may violate our policies. If you believe this is an error, please send feedback to your account team. Error Code: 63429089, 72817394 [google.rpc.error_details_ext] { message: \"Media reasoning failed with the following error: The response is blocked, as it may violate our policies. If you believe this is an error, please send feedback to your account team. Error Code: 63429089, 72817394\" }"
      }
    ]
  }
}

Filtered output

If the number of responses returned is less than the sample count you specify, the missing responses were filtered by Responsible AI. For example, the following is a response to a request with "sampleCount": 2, but one of the responses is filtered out:

{
  "predictions": [
    "cappuccino"
  ]
}

If all the output is filtered, the response is an empty object similar to the following:

{}
