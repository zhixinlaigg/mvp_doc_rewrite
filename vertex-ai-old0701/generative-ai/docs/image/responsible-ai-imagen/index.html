    Responsible AI and usage guidelines for Imagen¶

    Imagen on Vertex AI brings Google's state-of-the-art generative AI capabilities to application developers. As an early-stage technology, Imagen on Vertex AI's evolving capabilities and uses create potential for misapplication, misuse, and unintended or unforeseen consequences. For example, Imagen on Vertex AI could generate output that you don't expect, such as images that are offensive, insensitive, or contextually incorrect.

    Given these risks and complexities, Imagen on Vertex AI is designed with Google's AI Principles in mind. However, it is important for developers to understand and test their models to deploy them safely and responsibly. To aid developers, Imagen on Vertex AI has built-in safety filters to help customers block potentially harmful outputs within their use case. See the Safety filters and attributes section for more.

    When Imagen on Vertex AI is integrated into a customer's unique use case and context, additional responsible AI considerations and model limitations may need to be considered. We encourage customers to use fairness, interpretability, privacy, and security recommended practices.

    Before you begin¶

    Concepts
    • Responsible AI (RAI): A framework for developing, assessing, and deploying AI systems in a safe, ethical, and responsible manner.
    • Safety Filters: Automated mechanisms designed to detect and block potentially harmful content in both input prompts and generated outputs.
    • Safety Attributes: A set of categories (e.g., "Violence", "Sexual") used to score content for potential harm, which can be returned in the API response for user review.
    • Acceptable Use Policy (AUP): A set of rules that define prohibited uses of a service to prevent abuse and ensure legal and ethical compliance.

    Imagen usage guidelines¶

    Read the following general product attributes and legal considerations before you use Imagen on Vertex AI.

    • Image and text filters and outputs: Images (generated or uploaded) through Imagen on Vertex AI are assessed against safety filters. Imagen aims to filter out content that violates our acceptable use policy (AUP) or additional Generative AI product restrictions. Our generative imagery models are intended to generate original content and not replicate existing content. We've designed our systems to limit the chances of this occurring, and we will continue to improve how these systems function. Like all cloud service providers, Google maintains an Acceptable Use Policy that prohibits customers from using our services in ways that infringe third-party IP rights.
    • Configurable safety filter thresholds: Google blocks model responses that exceed the designated confidence scores for certain safety attributes. To request the ability to modify a safety threshold, contact your Google Cloud account team.
    • Text addition supported on certain model versions: Imagen does not support adding text to images (uploaded or generated) using a text prompt when using the imagegeneration@004 or lower model versions.
    • Report suspected abuse: You can report suspected abuse of Imagen on Vertex AI or any generated output that contains inappropriate material or inaccurate information using the Report suspected abuse on Google Cloud form.
    • Trusted Tester Program opt-out: If you previously opted in to permit Google to use your data to improve pre-GA AI/ML services as part of the Trusted Tester Program terms, you can opt out using the Trusted Tester Program - Opt Out Request form.

    Safety filters and attributes¶

    Text prompts provided as inputs and images (generated or uploaded) through Imagen on Vertex AI are assessed against a list of safety filters. These filters include harmful categories like violence, sexual, derogatory, and toxic. They aim to block content that violates our Generative AI Prohibited Use Policy or our AI Principles.

    If the model responds with an error like "The prompt couldn't be submitted" or if fewer images are returned than requested, it indicates that the input or generated output triggered a safety filter.

    It's important to understand the distinction between safety filters and safety attributes: * Safety filters are the internal mechanisms Google uses to block harmful content. You can adjust their sensitivity but cannot see the exact scores that trigger them. * Safety attributes are the safety scores returned to you when you set includeSafetyAttributes to true. These scores are for your information and do not represent all the filters Google applies. For example, we return a score for the "Health" category but do not filter content based on it.

    You can choose how aggressively to filter sensitive content by adjusting the safetySetting parameter.

    Configure safety filters¶

    You can use several parameters to control safety filtering in the image generation models. Some parameters affect the content produced, while others affect how filtering is reported to you.

    The following table describes the optional parameters that affect content filtering. For more technical information, see the image generation model API reference.

    Parameter Description
    safetySetting Sets how aggressively to filter for potentially sensitive output content.
    includeRaiReason Provides a reason code or message when generated images are filtered.
    personGeneration Allows you more control over the generation of people, faces, and children.
    disablePersonFace Deprecated. A choice to allow person and face generation or not. Use personGeneration instead.
    includeSafetyAttributes Returns detailed safety attribute scores for the input prompt, input image (for editing), and all generated images that are not filtered.

    Troubleshooting

    If you encounter issues with code snippets or setup, refer to the Troubleshooting Guide.

    Limitations¶

    The following limitations apply to different Imagen capabilities.

    Image generation and editing¶

    • Bias amplification: Imagen can generate high-quality images, but the content relies on its training data, which can unintentionally include biases that may perpetuate stereotypes or discriminate against certain groups. Careful monitoring and evaluation are necessary to ensure outputs align with your use case.
    • Transparency and disclosure: It can be difficult for users to differentiate between AI-generated and non-AI-generated imagery. When using AI-generated images, clearly disclose that they were created by an AI system to ensure transparency. We apply metadata labeling to AI-generated images to help combat misinformation.
    • Insufficient context: Imagen may lack the contextual understanding required to generate images appropriate for all situations. Check that your generated images align with your chosen context, purpose, and intended audience.
    • Misrepresentation and authenticity: Editing images, especially of people, can result in misrepresentation or manipulation, potentially leading to deceptive content. It is important to use editing features responsibly, without compromising the authenticity of the images. We apply metadata labeling to AI-edited images to help combat misinformation.

    Visual captioning¶

    • Accuracy and context sensitivity: Visual captioning may struggle with complex or ambiguous images. The generated descriptions may not always capture the complete context or nuance.
    • Ambiguity and subjective interpretations: Images can be open to multiple interpretations. The generated captions may not always align with human understanding or cultural backgrounds.
    • Accessibility considerations: While automated captions can support accessibility, they may not fully replace human-generated alt-text tailored to specific accessibility needs.

    Visual Question Answering (VQA)¶

    • Overconfidence and uncertainty: VQA models may provide answers with unwarranted confidence, even when the correct answer is ambiguous. It is essential to communicate the model's uncertainty rather than conveying a false sense of certainty.

    Recommended practices¶

    To use this technology safely and responsibly, it is important to consider risks specific to your use case in addition to the built-in technical safeguards. The following workflow outlines our recommended practices.

    flowchart TD
    A[Assess security risks] --> B[Mitigate safety risks]
    B --> C[Perform safety testing]
    C --> D[Solicit user feedback and monitor]

click A "#assess-security-risks"
click B "#mitigate-safety-risks"
click C "#perform-safety-testing"
click D "#solicit-user-feedback-and-monitor"
    Recommended Practices

    1. Assess your application's security risks. Consider how your application could be misused by bad actors. Generative AI introduces new risks, such as generating harmful content, misleading information, or infringing on intellectual property.

    2. Consider adjustments to mitigate safety risks. In addition to Imagen's built-in safety filters, consider implementing other mitigations. This could include adding user input restrictions, filtering generated output on the client side, or requiring human review for sensitive workflows.

    3. Perform safety testing appropriate to your use case. Test your application to ensure the safety controls are working as expected. Use techniques like red-teaming to probe for vulnerabilities and test the system's response to adversarial inputs.

    4. Solicit user feedback and monitor content. Provide a mechanism for your users to report inappropriate content. Continuously monitor application outputs and user feedback to identify and address any emerging safety issues or model limitations.

    Give feedback on Imagen on Vertex AI¶

    If you receive an output or response that is inaccurate or that you feel is unsafe, you can let us know by submitting feedback. Your feedback can help improve Imagen on Vertex AI and broader Google efforts in AI.

    Because feedback may be human readable, don't submit data that contains personal, confidential, or sensitive information.
