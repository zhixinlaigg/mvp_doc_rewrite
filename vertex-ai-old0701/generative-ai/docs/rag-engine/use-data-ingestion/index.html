    Use data ingestion with Vertex AI RAG Engine¶

    This page explains how to perform data ingestion into Vertex AI RAG Engine from a supported data source. You can import data from sources like Cloud Storage, Google Drive, Slack, Jira, or SharePoint using the ImportRagFiles API.

    Note: Vertex AI RAG Engine supports VPC-SC security controls and CMEK. Data residency and AXT security controls are not supported.

    Compare data sources¶

    Before you begin, determine the most suitable data source for your needs. The following table provides a comparison of the supported data sources.

    Data Source Description & Use Case Key Requirements
    Local File Upload A synchronous, single-file upload for files up to 25 MB. Ideal for quick tests or ingesting individual documents. File size limit of 25 MB.
    Cloud Storage Asynchronously import one or more files from a Cloud Storage bucket. Best for batch processing large collections of documents already in Google Cloud. IAM permissions for the service account to read from the bucket.
    Google Drive Asynchronously import files from a Google Drive folder. Useful for ingesting documents managed and stored in Google Workspace. Share the Google Drive folder with the service account and grant Viewer permissions.
    Slack Import conversation histories from Slack channels using a data connector. Ideal for building a knowledge base from team communications. Slack app with correct permissions and an API token stored in Secret Manager.
    Jira Import issues and project data from Jira using a data connector. Useful for querying information about projects, tasks, and tickets. Jira API token and user email. Data is fetched using project names or JQL queries.
    SharePoint Import files from a SharePoint site. Best for ingesting documents from a Microsoft 365 environment. Azure app registration with appropriate API permissions and credentials.

    For more information on file size limits and supported document types, see Supported document types.

    Before you begin¶

    Before you begin

    Create a RAG corpus

    All data must be imported into a RAG corpus. A corpus is a collection of RagFiles that your application can query. To create one, follow the instructions at Create a RAG corpus.

    Concepts
    • RAG Corpus: A collection of documents or files that are indexed and optimized for retrieval-augmented generation searches.
    • API Token: A unique string of characters used to authenticate your identity and grant access to an API (e.g., from Slack or Jira).
    • Secret Manager: A secure Google Cloud service for storing and managing sensitive data like API keys, passwords, and certificates.
    • JQL (Jira Query Language): A powerful, text-based search language used in Jira to find issues based on specific criteria.
    • Service Account: A special type of Google account used by an application or a virtual machine (VM) instance, not a person.

    Set up permissions

    To import data, you must grant the correct permissions to the Vertex AI RAG Engine service account.

    • For Google Drive:

      1. Go to the IAM page of your Google Cloud project.
      2. Select Include Google-provided role grant.
      3. Search for the Vertex AI RAG Data Service Agent service account and copy the email address.
      4. In Google Drive, click Share on the folder or file you want to import.
      5. Paste the service account email and grant it Viewer permission.

    • For Slack, Jira, or SharePoint:

      1. Obtain the necessary API token or client secret from the source service.
      2. Store the token or secret in Google Cloud Secret Manager.
      3. Grant the Secret Manager Secret Accessor (roles/secretmanager.secretAccessor) role to your project's Vertex AI RAG Data Service Agent service account to allow it to access the secret.

    Import data from a supported source¶

    Choose one of the following sources to import your data.

    Troubleshooting

    If you encounter issues with code snippets or setup, refer to the Troubleshooting Guide.

    You can import files from either Cloud Storage or Google Drive. The system automatically checks the file's path, filename, and content hash to prevent re-indexing unchanged files. If a file with the same name and path is updated, it will be re-indexed.

    To import your files, use the code samples in the Import RagFiles API reference. Ensure you have completed the permission setup described in the Before you begin section.

    To import files from Slack, follow these steps:

    Step 1: Set up a Slack app
    1. Go to the Slack API page and create a new app.
    2. From the app's dashboard, navigate to Features > OAuth & Permissions.
    3. In the Scopes section, add the following Bot Token Scopes:
      • channels:history
      • groups:history
      • im:history
      • mpim:history
    4. Navigate to Settings > Install App and click Install to Workspace to install the app.
    5. After installation, copy the Bot User OAuth Token. This is your API token.
    Step 2: Store the API token and grant access
    1. Add your API token to Secret Manager.
    2. Grant the Secret Manager Secret Accessor role to your project's Vertex AI RAG Data Service Agent service account. See Set up permissions for details.
    Step 3: Import the data

    Use the following code samples to import messages from your Slack channels. You will need your Slack channel ID, which can be found in the channel's URL or details pane.

    View curl example 
    API_KEY_SECRET_VERSION=SLACK_API_KEY_SECRET_VERSION
CHANNEL_ID=SLACK_CHANNEL_ID
PROJECT_ID=us-central1

curl -X POST \
-H "Authorization: Bearer $(gcloud auth print-access-token)" \
-H "Content-Type: application/json" \
https://${ ENDPOINT }/v1beta1/projects/${ PROJECT_ID }/locations/${ PROJECT_ID }/ragCorpora/${ RAG_CORPUS_ID }/ragFiles:import \
-d '{
  "import_rag_files_config": {
    "slack_source": {
      "channels": [
        {
          "apiKeyConfig": {
            "apiKeySecretVersion": "'"${ API_KEY_SECRET_VERSION }"'"
          },
          "channels": [
            {
              "channel_id": "'"${ CHANNEL_ID }"'"
            }
          ]
        }
      ]
    }
  }
}'
    View Python example

    You can specify a time range by setting START_TIME and END_TIME.

    # Slack example
start_time = protobuf.timestamp_pb2.Timestamp()
start_time.GetCurrentTime()
end_time = protobuf.timestamp_pb2.Timestamp()
end_time.GetCurrentTime()
source = rag.SlackChannelsSource(
    channels = [
        SlackChannel("CHANNEL1", "api_key1"),
        SlackChannel("CHANNEL2", "api_key2", START_TIME, END_TIME)
    ],
)

response = rag.import_files(
    corpus_name="projects/my-project/locations/us-central1/ragCorpora/my-corpus-1",
    source=source,
    chunk_size=512,
    chunk_overlap=100,
)

    To import data from Jira, follow these steps:

    Step 1: Create a Jira API token
    1. Sign in to your Atlassian account.
    2. Navigate to Security > API tokens and click Create API token.
    3. Give the token a label and copy the generated token value.
    Step 2: Store the API token and grant access
    1. Add your API token to Secret Manager.
    2. Grant the Secret Manager Secret Accessor role to your project's Vertex AI RAG Data Service Agent service account. See Set up permissions for details.
    Step 3: Import the data

    Use the following code samples to import data. You must provide your Atlassian email, your Jira server URI (e.g., your-org.atlassian.net), and either project names or custom JQL queries. For more on JQL, see Use advanced search with Jira Query Language (JQL).

    View curl example 
    EMAIL=JIRA_EMAIL
API_KEY_SECRET_VERSION=JIRA_API_KEY_SECRET_VERSION
SERVER_URI=JIRA_SERVER_URI
CUSTOM_QUERY=JIRA_CUSTOM_QUERY
PROJECT_ID=JIRA_PROJECT
REGION= "us-central1"

curl -X POST \
-H "Authorization: Bearer $(gcloud auth print-access-token)" \
-H "Content-Type: application/json" \
https://${ ENDPOINT }/v1beta1/projects/${ PROJECT_ID }/locations/REGION>/ragCorpora/${ RAG_CORPUS_ID }/ragFiles:import \
-d '{
  "import_rag_files_config": {
    "jiraSource": {
      "jiraQueries": [{
        "projects": ["'"${ PROJECT_ID }"'"],
        "customQueries": ["'"${ CUSTOM_QUERY }"'"],
        "email": "'"${ EMAIL }"'",
        "serverUri": "'"${ SERVER_URI }"'",
        "apiKeyConfig": {
          "apiKeySecretVersion": "'"${ API_KEY_SECRET_VERSION }"'"
        }
      }]
    }
  }
}'
    View Python example 
    # Jira Example
jira_query = rag.JiraQuery(
    email="xxx@yyy.com",
    jira_projects=["project1", "project2"],
    custom_queries=["query1", "query2"],
    api_key="api_key",
    server_uri="server.atlassian.net"
)
source = rag.JiraSource(
    queries=[jira_query],
)

response = rag.import_files(
    corpus_name="projects/my-project/locations/REGION/ragCorpora/my-corpus-1",
    source=source,
    chunk_size=512,
    chunk_overlap=100,
)

    To import files from your SharePoint site, follow these steps:

    Step 1: Set up an Azure app
    1. In the Azure portal, go to App Registrations and create a new registration.
      • Provide a name for the application.
      • Choose the option, Accounts in this organizational directory only.
      • Leave the redirect URIs empty.
    2. From the app's Overview page, copy the Application (client) ID and the Directory (tenant) ID.
    3. Under Manage > API permissions, add the following permissions:
      • SharePoint: Sites.Read.All
      • Microsoft Graph: Files.Read.All and Sites.Read.All (instead of Browser SiteLists.Read.All)
      • Click Grant admin consent for your directory to apply the changes.
    4. Under Manage > Certificates & secrets, create a new client secret and copy its Value.
    Step 2: Store the client secret and grant access
    1. Add the client secret's value to Secret Manager.
    2. Grant the Secret Manager Secret Accessor role to your project's Vertex AI RAG Data Service Agent service account. See Set up permissions for details.
    Step 3: Import the data

    Use the following code samples to import files. You must specify your SharePoint site name (e.g., your-org.sharepoint.com) and a drive name or ID. You can optionally specify a folder path or ID to limit the import scope.

    View curl example

  "import_rag_files_config": {
    "sharePointSources": {
      "sharePointSource": [{
        "clientId": "'"${ CLIENT_ID }"'",

    Understand import results¶

    Data deduplication¶

    RAG Engine avoids re-processing unchanged files. If you import the same file multiple times without any modifications to its content or the chunking configuration, the file is skipped. The response.skipped_rag_files_count in the API response indicates how many files were skipped for this reason.

    A file is skipped if all of the following conditions are met:

    • The file has been imported previously.
    • The file content has not changed.
    • The chunking configuration for the file has not changed.

    Import failures and logging¶

    To understand the outcome of an import job, you can inspect the API response or configure a data sink to log detailed results.

    • Response Metadata: The response.metadata object in the SDK response contains high-level information about the import job, including request and response times.

    • Import Result Sink: For detailed, file-level logging, you can specify an import_result_sink in your import request. This is an optional parameter that designates a destination for logging the status of each imported file. This makes it easier to identify which files failed to import and why.

      The sink can be a Cloud Storage path or a BigQuery table: * Cloud Storage: Provide a path like gs://my-bucket/my/object.ndjson. The object must not exist before the import. After the job completes, this object will contain one JSON object per line, detailing the status of each file. * BigQuery: Provide a table reference like bq://my-project.my-dataset.my-table. If the table does not exist, it will be created. If it exists, its schema will be verified.
