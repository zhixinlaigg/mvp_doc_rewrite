Grounding with Elasticsearch¶

This page explains how to use your Elasticsearch instance to ground large language model (LLM) responses on your private data.

Grounding enhances LLM responses by providing factual context from specified data sources. By grounding with Elasticsearch, you can leverage your existing Elasticsearch indexes to improve the quality and reliability of Gemini's output. This helps reduce hallucinations and ensures responses are relevant to your data.

This capability allows you to build powerful Retrieval-Augmented Generation (RAG) applications, such as:

  • Generative search summaries
  • Question-and-answer chatbots using enterprise data
  • Agents grounded in your proprietary data

You can ground a model on up to 10 data sources at once. For comprehensive results, you can combine grounding with Elasticsearch with Grounding with Google Search to connect the model to public information from the internet.

Before you begin¶

Concepts
  • Grounding: The process of connecting a large language model (LLM) to external data sources to provide factual, up-to-date context for its responses.
  • RAG (Retrieval-Augmented Generation): An AI framework that retrieves facts from an external knowledge base to ground LLMs before they generate a response.
  • Elasticsearch Index: A collection of related documents in Elasticsearch that are stored and indexed together for fast searching.
  • Search Template: A predefined search request in Elasticsearch that can be executed with different parameters, simplifying complex queries.
  • kNN (k-Nearest Neighbors) Search: A method for finding the 'k' most similar items in a dataset to a query, commonly used for semantic search with vector embeddings.
Prerequisites

Before you can ground LLM responses with Elasticsearch, complete the following:

  1. Enable the Vertex AI API: Ensure the Vertex AI API is enabled for your Google Cloud project.
  2. Install the gcloud CLI: Install and initialize the Google Cloud command-line tool.
  3. Set up Elasticsearch: You need an existing Elasticsearch cluster and index. Gather the following information:
    • Endpoint: The URL of your Elasticsearch cluster.
    • Index Name: The name of the index you want to search (e.g., my-data-index).
    • API Key: An API key that grants access to your Elasticsearch cluster. The key must have the prefix ApiKey.
  4. Create an Elasticsearch search template: Create a search template that returns result data for grounding. For more information, see the next section.

Set up a search template in Elasticsearch¶

Set up a search template

Best practices

For the best grounding responses, follow these principles when creating a search template:

  • Include only relevant data: Avoid including data that is not useful for answering prompts, such as image URLs (unless the prompt asks for them) or embedding vectors.
  • Return enough results: Grounding removes Elasticsearch results with low relevance to your prompt. Configure your template to return a higher number of results to ensure all relevant context is captured.
  • Structure results effectively: You can return data in a single field or spread it across multiple fields.

Sample template

While you can use your own search templates, we recommend the generic kNN search template for Elasticsearch grounding. This template performs a semantic search using k-Nearest Neighbors.

For additional examples, see the Elasticsearch Labs GitHub repository.

The following command creates a generic kNN search template in Elasticsearch.

PUT _scripts/google-template-knn-multioutput
{
  "script": {
    "lang": "mustache",
    "source": {
      "_source": {
        "excludes": [ "title_embedding", "description_embedding", "images"]
      },
        "size": "num_hits",
          "knn" : [
          {
            "field": "description_embedding",
            "k": 5,
            "num_candidates": 10,
            "query_vector_builder": {
              "text_embedding": {
                "model_id": "googlevertexai_embeddings_004",
                "model_text": "query"
              }
            },
            "boost": 0.4
          },
          {
            "field": "title_embedding",
            "k": 5,
            "num_candidates": 10,
            "query_vector_builder": {
              "text_embedding": {
                "model_id": "googlevertexai_embeddings_004",
                "model_text": "query"
            }
          },
          "boost": 0.6
          }
          ]
    }
  }
}

To ground a model with Elasticsearch in the Google Cloud console, follow these steps:

  1. Go to the Vertex AI Studio Create prompt page.

    Go to Create prompt

  2. In the Settings panel, click the Grounding: Your data toggle to enable it.

  3. In the Customize Grounding pane, select Elasticsearch.
  4. Enter your Elasticsearch endpoint.
  5. Enter your Elasticsearch API Key.
  6. Enter your Elasticsearch index.
  7. Enter your Elasticsearch search template.
  8. Adjust the Number of hits slider to set the number of results to retrieve.
  9. Click Save.
  10. Enter your prompt in the prompt input field.
  11. Click Submit to generate the grounded response.

This section shows how to use the Vertex AI API to ground a model with your Elasticsearch data source.

Prepare a grounded generation request

To send a text prompt and ground it with Elasticsearch, send a POST request to the Vertex AI API. In the request body, replace the following placeholders:

  • QUERY: The text prompt to ground.
  • ELASTIC_SEARCH_ENDPOINT: The absolute endpoint path for the Elasticsearch resource.
  • ELASTIC_SEARCH_API_KEY: The API key for the Elasticsearch data endpoint.
  • INDEX_NAME: The name of the Elasticsearch index to use for grounding.
  • SEARCH_TEMPLATE_NAME: The Elasticsearch search template to use for grounding.
  • NUM_HITS: The number of results to return from the Elasticsearch data source.

Request JSON body:

{
  "contents": [
    {
      "role": "user",
      "parts": [
        {
          "text": "QUERY"
        }
      ]
    }
  ],
  "tools": [{
    "retrieval": {
      "externalApi": {
        "api_spec": "ELASTIC_SEARCH",
        "endpoint": "ELASTIC_SEARCH_ENDPOINT",
        "apiAuth": {
          "apiKeyConfig": {
            "apiKeyString": "ApiKey ELASTIC_SEARCH_API_KEY"
          }
        },
        "elasticSearchParams": {
          "index": "INDEX_NAME",
          "searchTemplate": "SEARCH_TEMPLATE_NAME",
          "numHits": "NUM_HITS",
        }
      }
    }
  }]
}

For more information on other API fields, such as system instructions and multi-turn chats, see the Generative AI beginner's guide.

Send the API request

Save the request body in a file named request.json. Then, execute the following curl command. Replace the following placeholders:

  • LOCATION: The region to process the request. For available locations, see Generative AI on Vertex AI locations.
  • PROJECT_ID: Your Google Cloud project ID. For more information, see Creating and managing projects.
  • MODEL_ID: The ID of the multimodal model you are using.
curl -X POST \
    -H "Authorization: Bearer $(gcloud auth print-access-token)" \
    -H "Content-Type: application/json; charset=utf-8" \
    -d @request.json \
"https://LOCATION-aiplatform.googleapis.com/v1beta1/projects/PROJECT_ID/locations/LOCATION/publishers/google/models/MODEL_ID:generateContent"

Understand your response¶

Understand your response

When a model response is successfully grounded to your Elasticsearch data, the response includes grounding metadata with citations and source content. If the source data has low relevance or is incomplete, metadata might not be provided, and the response will not be grounded.

You should receive a JSON response similar to the following:

{
  "candidates": [
    {
      "content": {
        "role": "model",
        "parts": [
          {
            "text": "Based on the information ..."
          }
        ]
      },
      "finishReason": "STOP",
      "safetyRatings": [ "..." ],
      "groundingMetadata": {
        "groundingChunks": [
          {
            "retrievedContext": {
              "text": "ipsum lorem ..."
            }
          },
          {...},
          {...},
        ],
        "groundingSupports": [
          {
            "segment": {
              "startIndex": 25,
              "endIndex": 147,
              "text": "ipsum lorem ..."
            },
            "groundingChunkIndices": [1,2],
            "confidenceScores": [0.6626542, 0.82018316],
          },
        ],
      },
    }
  ],
}

The following is a breakdown of the output data:

  • role: Indicates the sender of the response. For a grounded answer, the role is always model.
  • text: The grounded answer generated by the LLM.
  • groundingMetadata: Information about the grounding source, which contains the following:
    • groundingChunks: A list of results from your Elasticsearch index that support the answer.
    • groundingSupports: Information about a specific claim within the answer that can be used to show citations.
      • segment: The part of the model's answer that is substantiated by a grounding chunk.
      • groundingChunkIndices: The index of the groundingChunks that corresponds to this claim.
      • confidenceScores: A number from 0 to 1 that indicates how grounded the claim is in the provided set of grounding chunks. This field is not available for Gemini 2.5 Pro, Gemini 2.5 Flash, and later models.
